# 图标设计与检查

选用、补齐或检查图标，以及 Init 登记项目图标规则时加载。先按 [视觉资产选择](visual-assets.md) 查适用项目/团队资产；普通复用不要求重建图标系统。Init 以已有图标和实现为依据，Design 沿用已确认交互与项目风格。

## 方法依据与适用范围

- 扩展图标家族或检查造型时，按 [来源约定](sources.md) 读取 [Lucide 设计语言](https://lucide.dev/contribute/icons/design-principles) 和相关 [设计规格](https://lucide.dev/contribute/icons/specification)。参考视觉重量、光学居中、细节密度、共享几何与实际尺寸检查方法；Lucide 的画布、笔画、圆角数值仅适用于该体系，不成为本插件的统一默认值。
- 对含义存在疑问或准备省略标签时，查阅 [NN/g 图标可用性研究](https://www.nngroup.com/articles/how-to-test-digital-icons/)：分别考察图形能否被认出，以及用户能否在界面中理解其作用。Agent 的判断不等于用户测试。
- 项目规则与来源图标家族优先；本页为任务适配，出处和许可边界见 [来源声明](../third-party/visual-assets/NOTICE.md)。按当前问题读取，复用任务内已读内容，不引入图标库或外部 Skill 的安装依赖。

## 先确定含义，再选形状

1. 明确图标在当前页面表达的是动作、对象还是状态，以及用户需要做出的判断。先核对产品语义，再搜索名称、近义词并查看实际图形。
2. 复用项目已确认的视觉隐喻。一个图形能被认出，并不证明用户知道点击后的结果；例如电源形状不能单独解释某操作会待机、退出还是断开连接。
3. 含义有歧义、操作后果重要或目标用户不熟悉时保留短标签；图标不能取代输入标签、必要后果说明或错误恢复。可访问名称与必要的可见标签分别考虑，触屏关键含义不依赖 hover。
4. 状态变化沿用项目的形状、标记与颜色规则；不只换颜色表达状态，也不因换了状态就换成另一个图标家族。

## 复用与必要补齐

优先使用适用的真实 Library 实例。没有合适资源时，选择能匹配项目风格与许可要求的成熟矢量家族；只取当前所需图标，不混用不同家族凑齐同一组操作。已有库不适用的具体原因留在任务中。

确有缺口时，在授权范围内按选定家族制作 SVG 或 Figma 原生矢量：

- 从实际同组图标提取画布、有效绘制区、笔画/填充、端点、圆角、细节密度与主题用法。颜色使用项目认可的语义规则，不重新选产品色板。
- 复用已有基本形和修饰符的比例与位置；减少影响小尺寸识别的细节。授权与许可允许修改时才改源形状，修改现有主组件另遵循来源管理范围。
- 并排比较视觉重量与居中效果，必要时做光学调整。尺寸相同不保证看起来同样大；像素对齐不能破坏辨识度或曲线。
- 用当前工具支持的矢量导入或原生绘制能力交付，回读实际路径、描边/填充、尺寸与可用的变量绑定。将图片放进 SVG 容器不等于可编辑矢量；UI 图标默认不走位图生成。

无法完成所需矢量时说明缺口，继续已具备资产的部分；不要把栅格占位图称为完成的图标系统。无需为了一个缺口重新设计整套库。

## 在实际界面验收

| 检查 | 观察方式 |
| --- | --- |
| 含义 | 放回具体任务，检查形状与动作/状态含义；有歧义时用短标签或针对该点访谈。实际用户理解测试单独报告 |
| 同组一致性 | 与相邻图标并排看笔画、圆角、密度、视觉重量和修饰符，不只检查外框数值 |
| 真实尺寸与状态 | 在目标显示尺寸和适用主题下检查清晰度、裁切、对比与必要状态；图形尺寸和操作热区分别按项目平台依据检查 |
| Figma 交付 | 实例/矢量类型真实、状态与变量绑定符合项目规则；视觉替换后复核受影响操作区域和原型连接 |
| 来源 | 按 [资源说明蓝图](../assets/resource-card.txt) 记录实际来源、家族、适用规则与必要署名/许可；新增认可规则进入本次知识增量 |

检查截图与原生资产后修正具体问题。结构校验不能证明图标好认，用户选中样式也不等于目标用户的理解已经验证。
