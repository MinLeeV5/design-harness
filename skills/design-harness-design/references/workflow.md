# Design：先确认交互，再细化视觉

默认顺序：整体需求确认 → 流程骨架确认 → 主流程可点击低保真原型确认 → 分支逐条确认 → 统一视觉细化 → 最终确认与知识回写。已有同范围的明确确认直接承接；纯文案、配色等不改变操作的小改动只做相关阶段，说明简化依据。工具能力不足不等于任务适合省略原型。

## 1. 从入口按需读取

按 [上下文契约](context-loading.md) 读取入口，再选择相关模块、资源与必要依赖。向用户简述采用的依据和关键缺口，不倾倒整份知识库。

需要核对实现时，用入口仓库链接与已有上下文定位相关代码；调查细节留在任务中，设计文档使用产品语言。区分当前实现、已确认待实现和候选设计。项目规则不能回答的新问题留给访谈。

涉及视觉资产时按 [Library 与视觉资产](visual-assets.md) 读取项目来源索引，复核相关库是否可访问、是否适用。此时只查本次所需范围，不为低保真原型搜遍所有素材或提前生成完整插画。

## 2. 逐题访谈，确认整体需求

按 [访谈机制](interview.md) 一次解决一个高影响问题。成熟需求继承已有决策；模糊目标可用流程图、线框或临时草图帮助讨论。

目标、范围、约束与成功标准清楚后，汇总整体理解，并明确本次 Page、阶段、原型覆盖范围与已委托事项，请用户确认。分支的交互细节可留到后续阶段；会改变主路径的权限、前置条件或退出后果要先识别。用户未回复不是确认。

默认沿一套推荐主方案推进。尚未确定的关键交互可提出局部备选，比较相同任务下的收益、代价和适用条件，选定后并回主方案。不要默认扩成 2–3 套完整流程，也不要用换色或圆角冒充交互差异。用户明确要求多套完整方案时按其范围执行。

## 3. 在需求 Page 梳理流程骨架

整体需求确认后创建独立需求 Page，或继续本需求已授权的 Page。按 [需求 Page 蓝图](../assets/requirement-page.txt) 和 [工作模板](work-templates.md) 从流程图开始，沿用项目文档配置。

用少量节点与箭头表示入口、参与端、核心操作、系统反馈和完成结果。标出分支入口、返回/退出及影响结构的约束；分支先标关系，详细画面后续展开。主流程是用户完成目标的端到端路径，必要返回与退出不能以“之后再做异常”为由省略。

围绕流程中的关键取舍逐题访谈。流程骨架确认后进入原型；如果整体需求确认时已审阅并批准同一骨架，直接继续。

## 4. 先完成主流程可点击低保真原型

按 [原型制作与走查](prototyping.md) 建立必要画面、操作区域、反馈与真实跳转，提供可打开的原型入口。低保真聚焦层级和交互，已有项目组件可以直接复用，无需重绘成黑白线框。

先做最小可走通路径，再围绕具体步骤边体验、边访谈、边修正。一轮只讨论一个影响交互的问题；需要比较时只做对应片段的备选。必要的连接/步骤图先用可编辑示意图，精细插画与视觉修饰后置。

按 [阶段检查](evaluation.md) 核对入口至完成、返回与关键反馈，实际在预览中走查。展示完成内容与验证限制，请用户确认主流程交互后再展开分支；写入已获授权，不意味着交互已获确认。

## 5. 逐条补充分支与异常恢复

根据骨架，按依赖和对用户任务的影响选择下一条分支。每条只展开从分叉点到重新汇入主流程或结束的必要画面、条件与反馈，复用已确认部分。

为当前分支补可点击连接并走查，围绕关键选择访谈，确认后再进入下一条。用户可明确委托常规细节或批准一组已展示分支，避免机械重复审批。确实无适用分支时说明依据。

新分支如果改变主流程前提，解释冲突并回到受影响决策，修正相关原型后再继续。未展开分支、暂缓项与待核实能力要明确，不能用只走通正常路径表示全部交互完成。

## 6. 交互确认后统一细化视觉

主流程与本次范围内分支确认后，基于同一交互结构应用项目字体、色彩、组件、图标与插画；保留原型连接及确认依据。按 [视觉资产](visual-assets.md) 先复用适用 Library，必要缺口再按类型补齐，新增候选暂留需求 Page。

需要图标时按 [图标方法](iconography.md) 处理语义、家族与矢量补齐；需要示意图或情境插画时按 [插画方法](illustration.md) 明确表达目的、制作代表样图并迭代。各自完成实际尺寸与版面检查，再扩展本次所需系列；不为每个需求加载全部指导或建立新图形体系。

产品画面与评审说明都采用图形配必要短文。流程用图、状态用画面、差异用局部对照，保留操作标签、后果、关键规则和真实定位；按 [工作模板](work-templates.md) 检查可读性。图形不能引入产品不支持的关系或能力。

按问题选择 [Impeccable](impeccable.md) 或 [UI/UX Pro Max](ui-ux-pro-max.md) 最新指导，再按 [检查标准](evaluation.md) 检查节点、绑定、目标尺寸截图和受影响原型路径。能在授权范围修正的问题直接修正。视觉调整改变交互时，重新确认受影响部分。

提供主方案与原型链接、已确认取舍、实际检查结果及剩余限制，请用户确认最终设计。没有关键分歧时不制造多套方案供选择。

## 7. 确认增量，回写 Harness

按 [知识更新](knowledge-update.md) 展示变更前后、来源、影响与实现状态。用户确认增量后更新真实资产、资源说明、模块和需求索引；既有同范围授权直接沿用。

需求 Page 保留流程、原型、设计与决策出处。Harness 只沉淀获准的规则、可复用资产及索引；新增 Library 来源或插画风格也须属于已批准增量。完成时报告最终设计、实际回写与待实现事项。
