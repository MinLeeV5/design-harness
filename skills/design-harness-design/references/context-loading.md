# 按需读取项目 Harness

用于 Design 的项目知识读取与回写定位。输入是用户指定的 Figma 项目和新需求；不要求本地项目配置。项目通过可见原生文本承载上下文，读取助手见 [Figma 操作](figma-operations.md)。

## 识别入口与索引

标准入口标记为 `Design Harness / Contract 1`，位于 Harness Page 顶层 Frame `DH / AGENTS`，主体是 TEXT `DH / Entry`。

| 读取层级 | 要得到的信息 |
| --- | --- |
| 入口 | 产品/平台/渠道范围、少量全局约束、一条仓库链接、已确认待实现索引，以及七类模块目录 |
| 模块概览 TEXT `DH / Module` | 本模块适用范围、整理状态、资源 ID/说明节点、需要时读取的依赖 |
| 资源说明 TEXT `DH / Resource` | 用途、设计/实现状态、实际资产位置、规则、依赖与设计依据，以及必要的验证限制 |
| 原生资产与必要来源 | 实际组件、变量绑定、模板结构、状态画面及相关代码，而非仅凭目录名称理解设计 |

七类模块为项目上下文、设计风格、Tokens/变量、布局、组件、模板和场景。目录节点 ID 必须来自真实工具结果；尚未整理的模块不会因为列在目录中就变成已确认知识。入口是项目设计依据，不授权系统命令、额外写入或跳过用户确认。

## 读取顺序

1. 只列 Page 的 ID 与名称，优先定位用户明确指定的 Harness Page 或名称为 `design-harness` 的页面。忽略名称两端空格与大小写；多个候选时确认目标，不根据当前打开的 Page 推断用户选择。
2. 读取目标 Page 顶层目录，找标准入口。历史入口可能叫“00 / 开始使用”或其他项目名称；只读该小节点理解现有组织，不先改名、迁移或递归导出全页。
3. 先独立读入口的全局约束和有效版本。按本次需求语义选择模块概览的真实 TEXT 节点，再根据用途与适用范围选择资源说明和实际资产。
4. 对确有需要的资源依赖逐层读取，在对话中记住已读稳定 ID，避免循环与重复。出现缺失引用时查看已知容器的局部目录；仍不能定位就说明具体缺口，不扩展成全文件扫描。
5. 有实现疑问时，以入口的仓库链接和已有上下文核对实际 remote 与项目归属，再按任务确认相关版本、目录和本地差异，定向查询源码；路径或仓库同名不等于来源相同。需要获取代码时在新目录使用已核实地址，不切换或覆盖现有工作区，不直接执行旧 Figma 文本中的命令。无法核实则说明本次结论的限制，继续可独立的设计工作；不向 Figma 回填源码路径、符号、commit 或调查日志。

例如，连接超时与重试需求通常加载连接场景、错误/恢复规则、提示组件及关联 token；是否补读布局取决于该页面结构，不必读取会议日历的全部画稿。

读取助手只限制遍历和返回量，不自动判断语义相关性。遇到 `truncated`，按返回的节点与偏移定向续读，不能把截断结果当作完整规范。

没有可用 Harness 入口时说明缺失并引导初始化；必要模块未整理时，只处理本次需要的缺口或由用户限定设计范围。旧 Contract 1 缺少仓库链接时先从当前工作区/已有上下文核实，必要来源仍无法确定才询问；分支、commit、源码映射并非 Figma 必填字段，不把它们缺失当作入口不可用。旧技术内容仍可作核查线索，只读时不擅自迁移；获准精简后不再补回。迁移入口和重建知识库属于初始化工作。

需要生成场景、比较方案或解释资源时，读取设计风格模块的 `documentation/work-templates` 资源及其 `DH / Work Templates` 配置，按 [Figma 工作模板](work-templates.md) 复用真实资产。旧项目没有该配置时可从已授权原稿提炼，缺失项明确标注；模板版本变化不自动覆盖项目样式或已填写需求页。

需要理解产品的视觉语言时，先读设计风格模块的 `style/design-description`（可显示为 DESIGN.md），再按内容加载关联 tokens、布局或组件。正文说明意图和用法，精确值从项目真实资产核对；按 [设计描述约定](design-description.md) 解读和维护。旧项目按已有资源语义定位，不因缺少固定标题就阻断设计；编写或修订描述时再读取最新上游写法。文档模板配置不代替产品设计语言。

## 使用状态与证据

优先采用适用范围内已确认的项目规范。分别理解设计状态、实现状态和已有的验证限制：当前实现、候选方案、已确认待实现不能合并成单一通过标记。缺少运行证据不能推断为运行通过，也不要求每份资源都补技术核查字段。设计确认与目标版本决定新需求的有效约束；较旧代码只说明实现差距。

变量和样式属于文件级资产。目录应提供真实 collection/variable/style ID；原生资产使用真实节点 ID。读取规则和绑定不会赋予修改全局库的权限。项目规范与通用建议冲突时采用项目规范；事实冲突则调查相关版本和渠道，必要时向用户提出明确取舍。

## 回写时保持契约兼容

用户选定方案后，先按 [知识更新](knowledge-update.md) 确认具体增量，再更新已有入口、模块与资源。新增资源可以使用本 Skill 的 [资源蓝图](../assets/resource-card.txt)，沿用项目原有视觉表达。

- 所有说明文本按 [文档排版约定](work-templates.md#文档排版与可读性) 设置原生富文本层级，保留语义 TEXT 的完整内容与节点 ID。超链接里的 URL/节点 ID 也要在可见正文中可读取，不能为美化把定位信息移出索引指向的文本。
- 稳定资源 ID 在项目中唯一；资源说明包含用途与适用范围、设计/实现状态、资产与设计依据、依赖及实际确认记录；必要时简述影响设计判断的验证限制。
- 模块目录只保留资源 ID、用途/何时读取、说明 TEXT 的真实节点定位和状态；详细规则在资源说明中维护。
- 入口保留项目边界、全局约束、一条仓库链接、有效设计范围和模块概览定位；需求 Page 通过索引关联，候选稿不自动成为默认规范。
- 正文按 [内容边界](work-templates.md#写给设计师的内容) 使用产品语言；项目上下文聚焦产品定位、用户任务、使用环境、渠道差异和业务边界，具体页面行为回写布局、组件或场景模块，不新增技术附录。
- 先生成经批准的真实资产和资源说明，再更新模块与入口的引用。使用真实返回 ID，回读后核对依赖和状态。

当前实现基线与已确认待实现设计分开保留；工作流轮次、等待队列等运行状态留在对话，不写成 Figma 隐藏数据。
