# Design 方案与回写检查

在方案生成、修正与知识回写时检查真实产物，无需独立 review 阶段或机器门禁 JSON。

## 每个候选方案生成与修正时

| 检查 | 具体方法 |
| --- | --- |
| 目标与验收 | 按已确认主任务走一遍，核对核心操作与成功标准；不只看单屏美观 |
| 可比较性 | 相同场景与内容深度，差异落在已约定比较轴，说明收益与代价 |
| 项目一致性 | 实际 token/字体/组件/布局/术语绑定与使用，检查适用渠道与设计版本 |
| 必要状态 | 针对任务检查空/加载/失败/离线/权限/长内容等确实相关状态及恢复；不得承诺不存在的能力 |
| 信息与操作 | 主次动作、反馈、导航/返回、文案与后果清晰；检查错误预防与恢复 |
| 平台与可访问性 | 用项目采用的现行平台依据核对尺寸、对比、非颜色表达、输入方式、焦点/读屏设计意图；没有依据不编造阈值 |
| 视觉与结构 | 回读节点类型/尺寸/绑定；在目标尺寸截图检查对齐、密度、溢出与素材；需要原型时检查连接与流向 |

具体问题按“节点/场景 → 用户会遇到的困难 → 依据 → 修正”说明。影响主要任务、违反已确认约束或掩盖实现状态的问题必须修正或明确与用户讨论；局部优化不应无限延长交付。

## 回写后

核对实际写入与批准增量一致；来源方案和新资产互相可定位；模块/入口目录与资源一致；已确认待实现没有覆盖当前实现基线；已取代条目指向有效版本。验证实际组件实例/变量绑定，不只检查索引文字。

## 如何表达结论

用具体“已核验、已发现问题、未核验/不适用及原因”，不输出综合审美分、置信度或准备百分比。Figma 可证明的属性与运行环境才能证明的行为分别报告；未执行运行测试不能说键盘、读屏、性能或真实状态切换已验证。

源数据只静态读过就按静态依据表达。截图看起来相同不代表组件实例、变量绑定或交互已正确；反之，结构检查通过也不替代渲染检查。
