# 可点击低保真原型

在流程骨架已确认、开始主流程或当前分支时读取。使用 [原型蓝图](../assets/interaction-prototype.txt) 组织实际产物，阶段推进按 [工作流](workflow.md)，访谈按 [逐题机制](interview.md)。

## 覆盖范围与保真度

- 主流程先覆盖从真实入口到任务完成的必要画面、操作、关键反馈及返回/退出。分支先在骨架标出，主流程确认后逐条展开；依赖未决业务事实的路径明确标注。
- 低保真保持真实信息层级、内容和操作尺寸，以判断交互为准。可复用项目组件、变量和现有画面，不必人为去色或重画；不提前精修阴影、装饰和情境插画。
- 需要图才能判断操作时先做可编辑示意图。占位图要说明用途，不能让占位符承载关键操作含义。
- 默认一个主方案。局部备选复用相同前提与内容，比较完后把选定方式并回；不用多套完整原型增加评审负担。

## 建立真实交互

1. 按 [工具流程](figma-operations.md) 核对文件、Page 和原型能力；发现当前连接器支持的原型写入、读取及预览方式。需要 API 细节时查 [Figma Reaction](https://developers.figma.com/docs/plugins/api/Reaction/) 与当前工具文档，不把某连接器扩展当通用 API。
2. 在本需求授权区域建立必要的原生 Frame/Instance。先确定画面与状态的对应关系，再设置实际操作区域的触发条件、目标画面、返回/关闭和必要组件状态切换。新增分支复用主流程已有目标。
3. 使用当前支持的专用原型操作或 Plugin API 写入 reactions 等真实连接，设置有效的流程起点；只修改本次范围，保留已有无关反应与起点。不能把可见箭头、节点名称或文本链接当作原型跳转。
4. 设备连接、网络结果、权限变化等外部事件若无法真实触发，用明确标注的演示控制或状态入口模拟。把模拟控件与产品 UI 分开，不虚构已实现的自动行为。
5. 回读本次触发条件、目标 ID、起点及状态连接，排除不存在的目标、跨错 Page、被覆盖的点击区域和意外死路。复制画面或视觉调整后复核引用。
6. 提供由真实文件与节点定位得到的原型入口。用当前可用的预览/浏览器/桌面能力从起点实际点击；只具备编辑 API 或截图能力时明确“连接已配置，点击待验证”，交给用户体验，不能宣称已走通。

不预设每个连接器都支持原型。如果专用工具缺失但执行工具支持原生 API，使用执行工具。仍无法构建可点击原型时，继续完成流程与静态讨论稿，说明缺口，请用户选择补足能力或明确调整本次交付；不能悄悄把静态连线稿当成交互阶段完成。保留已有授权，不为换工具重复请求相同写入许可。

## 按路径走查与确认

主流程检查入口 → 必要操作 → 反馈 → 完成，再检查返回/退出是否符合已确认规则。当前分支检查触发点 → 分支操作/反馈 → 回主流程或结束；局部修改后复核受影响的往返路径。通过画面状态或短说明表达等待与限制，不用复杂动画掩盖未确定行为。

向用户展示当前可体验入口、覆盖范围和一个关键取舍，按回答修正。主流程确认后再开始分支；分支确认后再进入下一条或视觉细化。不要要求用户批准尚未做出的画面，也不重复询问已明确委托的常规细节。

分别表达证据：

| 证据 | 能说明什么 |
| --- | --- |
| 原型连接回读 | 触发、目标、起点已配置，引用可解析 |
| 预览实际点击或用户体验反馈 | 对应路径在 Figma 原型中的表现；说明由谁体验、覆盖哪条路径 |
| 产品运行检查 | 实际设备、后端、焦点/读屏等行为；不能由模拟原型推断 |

用户可以在已知验证限制下确认设计方向；未执行的检查仍保留待验证状态。视觉细化后再走查受影响连接；新事实改变交互时只重开对应决定。
