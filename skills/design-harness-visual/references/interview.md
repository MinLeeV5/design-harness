# 视觉目标与方案对比访谈

访谈贯穿 [视觉工作流](workflow.md)，每次只问一个问题，并给出推荐和具体理由。先承接上游交互与项目视觉规范；可从现有资产查询的事实自行核实，业务需求不重新访谈。

## 出方案前

先确认本次最希望改善的视觉结果，以及项目规范内允许探索的范围。例如“优先让设备状态一眼可辨，还是突出当前主要操作”，给出结合任务情境的推荐。沿答案明确比较依据与代表画面范围，不要求用户重新填写完整需求问卷；已有明确目标用简短汇总确认，小修改同样参与。

目标与边界明确后，确认第一套候选的一个代表页计划再生成；本次探索的 2–3 套范围不等于一次批量放行。不同方向围绕同一目标和内容展开；用户没有指定审美词或参考图不代表无法探索，也不将 Agent 的风格偏好写成用户决定。

## 围绕画面比较

每次候选页生成后展示实际画面与表达目标；候选未齐备时附下一候选页的具体计划，按 [逐项门禁](handoff.md#交互与视觉的逐项门禁) 合并询问是否认可当前表达并按计划继续，然后停下等待。候选已齐备时转入比较提问，不为下一项计划新增候选。修改意见只用于当前项；候选制作验收与继续探索许可不写成最终选定。

候选达到共同代表范围后再统一比较，说明每套的差异、收益与代价，给出推荐及理由。然后只问当前最影响选择的一项取舍；结合画面定位讨论信息层级、分组或图形表达，不一次要求回答全部偏好。

明确记录用户选择的主方向及可融合的局部内容。回答含糊时只澄清影响整合的部分，不自行把“都不错”解读为选定或自由混合。所有方案均不合适时，定位不满足目标的原因，再修订代表画面；不能跳过选择直接铺开全部页面。

## 收敛与恢复

将用户选择落实为一致的整合代表稿，逐页获准生成、展示和确认；共同代表范围确认后再放行后续页面。未混合时沿用用户已明确选定并确认采用的同一版本。完整展开仍按单页或单页的一种状态逐项验收与放行，不重新访谈已选风格。候选制作验收、主方向选择、整合稿确认和下一项生成授权分别记录。

每个实际决定写入本阶段 [交接记录](handoff.md)，以 [视觉蓝图](../assets/visual-delivery.txt) 保存当前项、真实方案链接、选择理由、融合内容、验收与下一项放行；不复制整段对话。同一需求跨任务或中断恢复时从已有决定继续，待确认仍等待，不因压缩重新头脑风暴或扩大生成范围。

发现问题涉及操作语义、状态、导航或恢复方式时，说明位置、影响及建议，由用户决定是否返回交互阶段。视觉访谈不能替代上游交互决定。
