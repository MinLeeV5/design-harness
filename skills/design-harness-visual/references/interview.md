# 视觉共创：目标、画面反馈与方案取舍

访谈贯穿目标确认、每个候选页、统一比较、整合及逐项展开。承接上游交互和项目视觉规范，事实先查，业务需求不重访。可以连续多轮讨论，每轮只问一个影响本项的问题，给推荐与具体理由，并等待回答。

## 围绕当前目标或画面的讨论循环

1. **回述理解**：说明本次视觉要改善的用户感受或信息判断，以及继承的约束。已有稿时展示实际画面，指出具体位置、表达意图及与目标的关系，不只报告下一候选或下一页计划。
2. **定位未决取舍**：检查层级、密度、分组、色彩语义或图形表达是否有值得共同决定的问题。未知偏好或不满意先探查原因，不把“更高级”直接翻译成 Agent 偏爱的装饰。
3. **逐题讨论**：围绕一项取舍说明可行表达的收益、代价与推荐依据，再问一个问题。意图尚不清楚时开放提问并给出初步判断；有实际画面时用位置与效果辅助选择，不一次要求回答所有审美偏好。
4. **承接与修订**：说明用户反馈将保留或改变本项的什么表达，在当前授权内修订。回答只描述感受但不足以形成取舍时继续讨论原因；不直接写成认可或继续许可。还有影响本项的未决问题则下一轮再问。
5. **展示与收束**：展示修订后的实际稿及变化理由；有新取舍继续讨论，足以判断当前稿后再验收并提出一个具体下一项计划。用户已明确确认同一版本及下一项范围时承接，不重复审批。

每个检查点都核对是否有新的视觉取舍。已选方向和适用规则充分时，说明沿用依据并直接进入本项制作或验收，不重启风格访谈、不为每页凑问题。单题可以讨论多轮；设计取舍尚未解决时先等待该回答，不同时要求验收与继续。

## 出方案前

围绕本次最希望改善的视觉结果、判断成功的依据和可探索范围共创。例如状态辨识与主要操作的突出程度，推荐须结合任务情境。沿回答明确共同评价维度与代表范围，用户尚无审美词或参考图也可以继续探索。已有明确目标精简回述并沿用其确认，不要求完整问卷；小修改同样参与方案比较。

目标与边界明确后提出第一套候选的一个代表页计划，获准后生成。本次探索共 2–3 套，候选保持共同内容、状态、尺寸和既定交互；总范围不等于一次批量放行。

## 每个候选与统一比较

每次候选页生成后先展示实际画面，说明表达怎样服务目标，围绕本页未决判断或用户反馈执行讨论循环。候选未齐备时，解决影响当前表达或下一候选的取舍后，再附下一候选页的具体计划，按 [逐项门禁](handoff.md#交互与视觉的逐项门禁) 验收与放行。修改意见只用于当前项；候选制作验收不等于最终选定。

候选达到共同代表范围后统一比较，说明差异、收益、代价与推荐，再一次讨论一个最影响选择的取舍。局部反馈可以影响后续探索假设；影响共同评价依据时与用户确认该变化，不悄悄改变内容或比较条件。未生成方案只能说明探索假设，不能声称已展示效果。

明确记录用户选择的主方向、理由及可融合的局部内容。“都不错”时澄清影响选择的部分；所有方案均不满意时先理解未达目标的原因，再按授权修订代表画面。不自行选定、自由混合或直接铺开全部页面。

## 整合、展开与恢复

主方向选择后仍围绕整合画面检查融合是否一致、是否兑现选择理由；有新问题继续本项讨论。整合代表稿逐页获准、生成、展示和确认，共同代表范围确认后再逐项展开。未融合且用户已明确选定并确认采用同一代表版本时直接沿用。

完整展开承接已选方向，每页或单页一种状态检查目标在此处的表达及是否暴露新问题。新取舍只讨论本项受影响部分，不重访全套风格；无新取舍简述沿用依据。候选制作验收、主方向选择、整合稿确认和下一项授权分别记录，讨论偏好不替代具体稿件验收与放行。

按 [交接约定](handoff.md) 与 [视觉蓝图](../assets/visual-delivery.txt) 保存关键问题、真实结论与理由、表达变化、方案链接和未决项，不复制访谈全文。恢复时继续未完讨论或门禁，承接有效确认，不重新头脑风暴或扩大范围。

发现取舍涉及操作语义、状态、导航或恢复方式，说明位置、影响和建议，由用户决定是否返回交互；视觉共创不能替代上游交互决定。
