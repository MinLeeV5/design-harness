# 视觉工作流

1. 读取[设计组织模式](../../../shared/references/design-organization.md)、当前需求、已确认行为、交接和必要项目事实；持续模式维护主稿或明确打开的独立例外，不自动拆分、合并或改变默认。正式 PRD 按[来源与承接](../../../shared/references/product-source.md)核对。
2. 按[视觉设计方法](../../../shared/references/visual-method.md)建立实际基线、细化并比较；已有决定直接承接，方向明确直接完成。用户明确要求多方案时，按共同方法先讨论目标、差异与任务范围，确认后按所选数量生成真实结果；支持跨方案融合、版本细化与再探索，保存和选择与最终接受写回分开。
3. 按[资源协议](../../../shared/references/protocol.md)维护 Spec、React/CSS 与参数，按[资产方法](../../../shared/references/assets.md)处理实际所需图形。本阶段获准的公共增量按[共同维护与交接](../../../shared/references/handoff.md)完成并验证影响。
4. 在[预览](../../../shared/references/preview-export.md)中检查实际画面、状态与操作。内部视觉身份只承接其[执行范围](../../../shared/references/agent.md)，不继承外部阶段的公共基础、项目组织或交付操作权限。
5. 按[评价](evaluation.md)报告对照、实际操作、未核实项和选择结果；按[共同维护与交接](../../../shared/references/handoff.md)收尾。请求导出时一并验证离线 HTML，完成视觉评审后停止。

改变已确认行为时只重新对齐受影响部分。公共方法独立于执行入口，不扩大当前授权；小修改不强制固定数量候选。
