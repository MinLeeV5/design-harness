# 视觉工作流

1. 读当前需求、已确认行为、项目共享基础和事实基线，按[交付保真](../../../shared/references/fidelity.md)区分当前产品沿用区域与本次新增设计；核对实际源环境、版本、上下文和视口，不能只查看设计产物自身。
2. 明确改动直接完成；方向有分歧时才生成有意义的局部或代表候选，数量由问题决定。相同内容、状态与尺寸下比较，保留选择理由；候选不自动成为已确认基线。
3. 复用项目共享基础中的真实 Token、组件、字体、图标与资产。保留产品壳层、分组分割和控件层级，页面组合写入完整 Spec，布局与交互细节写项目 React 组件；保持属性与 Catalog 约束一致，不预铺通用调参控件。图形按[资产方法](../../../shared/references/assets.md)处理。
4. 使用[Agent](../../../shared/references/preview-export.md)直接提出视觉要求或先点选元素，再比较生成预览、调节本次适用控件并接受；页面组合修改 Spec，组件内部变化修改 React。先补结构、组件和行为缺失，再收敛几何、字形、表面与像素细节。获准的公共基础增量按[共同维护与交接](../../../shared/references/handoff.md)在当前任务中完成，并验证受影响需求。
5. 按相同实际尺寸和可比状态逐区对照基线与交付，检查壳层、菜单／浮层、固定与滚动区域、长文本、焦点、错误及恢复。真实视口改变布局，缩略显示不代替响应式验证。
6. 展示对照画面、交互结果与未核实项，落实反馈并维护保真记录。完整 UI 的完成结论须覆盖声明范围，未核实区域不能写为与生产一致。按[共同维护与交接](../../../shared/references/handoff.md)完成检查和交接，记录最终选择、融合范围与实际验收；请求导出时一并生成、验证离线 HTML，完成视觉评审后停止。

改变业务行为时只重新对齐受影响部分。小修改不强制探索固定套数。公共基础更新、交接和按需导出均在本阶段内处理，不依赖另一个 Skill。
