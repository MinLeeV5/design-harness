# 视觉设计：访谈、探索、收敛与展开

按 [交接约定](handoff.md) 核对确认范围、产物版本、真实节点和当前授权。输入可以是交互阶段交付，也可以是用户指定且已确认行为的现有界面；纯视觉小改动不强制重走交互阶段。缺少会影响视觉判断的交互决定时，只指出缺口，由用户选择补充依据或返回交互。

## 1. 恢复进度并访谈视觉目标

每项新的视觉需求默认经过“目标访谈 → 2–3 套代表方案 → 对比访谈 → 选主方向并按需融合 → 整合稿确认 → 完整展开”，小修改也执行。在新任务承接或中断后恢复同一项需求时，按交接记录继续当前步骤，承接已有选择与确认，不重新启动已完成的探索。

按 [上下文读取](context-loading.md) 加载相关设计风格、token、组件和布局。按 [逐题访谈](interview.md) 确认本次视觉目标、比较依据及可探索范围；事实先查，每题给出推荐与理由。已有目标可以精简呈现供本次确认，不因任务小或项目风格成熟就跳过方案比较。

原交互产物作为确认基线保留。在同一需求 Page 的视觉区域制作副本或使用用户已指定的视觉编辑区域，记录来源→视觉节点的对应关系；不覆盖上游交接记录。复制原型必须重新核对内部目标和起点，不能保留指向旧稿的意外连接。

## 2. 制作 2–3 套代表方案

先按 [Library 与视觉资产](visual-assets.md) 查项目认可来源和本次相关的可访问团队库，复用适用实例、变量与样式；访问受限如实记录。选定图形类型后只读图标或插画对应方法，不加载全部第三方规范。

在已确认目标下探索不同的视觉表达，每轮至少两套，有第三种值得比较的方向时给三套。大需求选能体现差异的关键页面，小修改呈现受影响区域；使用相同内容、状态、尺寸和交互约束制作实际代表画面，不能用参考图或文字方向代替。未选定方向前不为每套方案铺完全部页面。

差异应服务本次目标，例如信息层级、内容分组或图形表达，并说明各自收益与代价；配色调整也要解释语义或可读性的影响。方案遵守项目规范与既定交互，不为凑数量更换品牌或引入新操作。若约束没有留下两种可行表达，指出具体限制，由用户决定可开放的视觉维度。

用 [视觉蓝图](../assets/visual-delivery.txt) 与 [方案比较模板](work-templates.md#选用与组合) 呈现真实画面、共同评价维度、差异和推荐理由。必要图形先复用；仅在比较确实依赖新图形时制作代表样图，选定方向后再扩展系列。

## 3. 对比访谈与整合确认

围绕代表画面按 [访谈机制](interview.md) 一次解决一个取舍，给出推荐及原因。用户选一个主方向，可明确吸收其他方案的局部优点；记录采用什么、来自哪套方案及选择理由。尚未选定或所有方案都不满意时，回到影响判断的目标或表达问题，修订代表方案再比较。

按选择生成一份整合后的代表稿，检查层级、图形、排版与资产的一致性，展示实际变化并请用户确认该版本。即使没有混合，也明确主方案及其代表版本；同一画面版本已经明确获准时承接该确认。零散偏好或选择主方向不代表尚未展示的整合效果已获准。**整合代表稿确认后才完整展开。**

在目标确认、方案选择和整合确认后更新本阶段可见交接记录，保留真实方案链接、选择理由、融合范围与未决事项。候选和已选产物分别标明，恢复时继续当前步骤。

## 4. 完整展开并检查

以确认的代表稿扩展本次其余画面与状态。以画面、图示和少量文案降低理解负担，保留必要标签、后果与恢复提示；图标语义要清楚，功能关系用可编辑图形，情境插画检查实际导入、裁切与渲染。沿用已选方向处理制作细节，不把每个实例当作新的探索任务。

按 [视觉检查](evaluation.md) 看目标尺寸截图、文字与图形理解、状态表达、实例/变量绑定。回读受影响操作的触发条件、目标与流程起点；实际预览能力可用时点击相关路径，缺少时记录待验证。仅修复副本映射等与已确认行为一致的制作错误。

发现导航、状态、操作语义、信息可见时机或恢复路径需要改变，按 [阶段边界](handoff.md#阶段边界) 提出问题和建议；由用户决定是否返回交互。受影响画面保留待定，不用“视觉优化”替代上游决定。可以继续其他独立画面。

## 5. 交付并停止

展示完整视觉稿与实际变化，承接或取得该具体版本的设计确认；代表稿获准不等于尚未展示的全部页面获准。按 [视觉蓝图](../assets/visual-delivery.txt) 更新交接，包含当前步骤、上游版本、方案与选择、融合范围、确认稿链接、资产来源/限制、候选知识增量及待验证项。

新风格仍属于本需求，尚未成为 Harness 默认规范。有关设计语言的候选增量按需用 [描述方法](design-description.md) 形成；没有新增可复用规则就如实说明。

建议用户需要沉淀时在新任务调用 `$design-harness-writeback` 并提供交接链接；**本阶段到此停止**。用户对视觉稿的确认不自动批准候选知识增量或全局资产变更。
