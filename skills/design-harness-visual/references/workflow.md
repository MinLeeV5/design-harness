# 视觉工作流

1. 读当前需求、已确认行为、固定基础与真实预览，承接视觉目标、品牌及布局约束。
2. 明确改动直接完成；方向有分歧时才生成有意义的局部或代表候选，数量由问题决定。相同内容、状态与尺寸下比较，保留选择理由。
3. 复用固定基础中的 Token、组件与资产。布局与候选差异直接写 React；稳定调参目标登记 CSS 变量。图形按[资产方法](assets.md)处理。
4. 使用[Live](preview-export.md)点选、比较、即时调参并保存；结构变化修改 React。需求内基础可按授权调整，公共基础单独批准。
5. 检查桌面与必要窄屏、长文本、焦点、错误及交互连续性。真实视口改变布局，缩略显示不代替响应式验证。
6. 展示实际画面与边界，落实反馈。记录最终选择、融合范围与实际验收；完成后停止。

改变业务行为时只重新对齐受影响部分。小修改不强制探索固定套数。
