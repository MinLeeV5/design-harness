# 恢复与交接

恢复时依次读取 project.json、需求 manifest.json、requirement.md、interactions/*.md、handoff.md；随后按当前候选读取完整 Spec、参数、Catalog／Registry、专属组件和项目唯一公共基础。工具从完整插件启动，项目不承载工作台源码或绝对安装路径。

handoff.md 至少记录当前范围、事实基线、已确认决定、当前候选及选择理由、实际变化、检查结果、未决项和下一步。沿用区域与本次新增分开，保留基线版本、环境、上下文和实际视口。

分别报告视觉保真、实际交互、行为真实性与工程检查，区分源代码、设计模拟、源 Mock、真实服务和现网。完整 UI 需核对适用壳层、租户切换、菜单、分割线、固定／滚动区域等；细则见[交付保真](fidelity.md)。未取得证据不登记通过。

工具导出不表示用户确认。验收状态记录在需求 handoff.md；候选不自动晋升为公共基础，只有批准增量可回写。公共更新需保持向下兼容并检查已有需求；需要新 HTML 时用当前插件从 requirements 重新导出并验证。未保存实例属性和编辑冲突由 Agent 明确处理，不自动用外部文件覆盖用户草稿。

本轮只支持当前统一协议；旧 studio 试跑不作多版本引擎兼容。requirements 是唯一需求维护来源，历史用 Git 记录；不保留 releases、源码副本或 runtime。检查截图和模型输出临时清理，不保留 evidence 目录。
