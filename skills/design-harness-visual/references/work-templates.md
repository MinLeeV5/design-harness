# Figma 工作模板

写入 Figma 文档前只读“写给设计师的内容”和“文档排版与可读性”；需要模板时读“选用与组合”，只有构建、登记或迁移模板时再读后续对应部分。通用结构来自随 Skill 携带的 [模板蓝图](../assets/figma-work-templates.json)；项目内容继续使用入口、模块、资源或需求 Page 的对应蓝图。

## 三层职责

| 层次 | 内容与位置 |
| --- | --- |
| 通用工作结构 | 插件维护场景流程、方案对比、规范资源三类蓝图及槽位语义；不在每个项目复制一套访谈、审批、交付流程 |
| 原生 Figma 模板 | 项目有可访问且兼容的工作模板时优先复用；否则在已授权区域按蓝图构建可编辑 Frame、Component 和 Instance |
| 项目文档配置 | Harness 的设计风格模块记录文档字体、配色、标题习惯、参与端名称、画面比例和实际模板引用；产品 UI 规范独立维护 |

蓝图是可移植的构建依据，不是已经安装的 Figma 组件库。仅有 JSON、索引、截图或空画面槽位时，不得宣称原生模板或功能设计已完成。分发包不绑定某个项目 fileKey、nodeId、字体或业务名称。

## 写给设计师的内容

- 正文解释产品行为、设计规则、适用范围和状态。把实现术语转为用户能观察到的操作、反馈或限制，不用类名、方法名解释交互。
- 代码信息限定为 Harness 入口的一条仓库链接。源码路径、分支、commit、命令和核查日志不进入正文，也不搬到 Figma 技术附录或隐藏数据；Agent 在任务中按需查询。
- 项目上下文只保留产品定位、用户任务、使用环境、渠道差异和业务边界。具体页面行为归入布局、组件或场景模块，概览用链接关联。
- 保留设计资产所需的 token 名称、精确值、Figma 节点/变量/样式 ID 和原稿/需求链接。设计状态与实现状态分别表达；仅在影响设计判断时写简短验证限制，如“断线后的恢复待实机验证”，不逐条附检查日志。

## 文档排版与可读性

Figma 文档以设计师阅读为先，同时保持 Agent 可读取。借用 Markdown 的信息层级，将语义转换为原生富文本和 Auto Layout；不能把 `.txt`/Markdown 全文以同字号平铺，也不能把 `#`、`**` 或管道分隔符当作排版效果。

### 图形与必要短文

产品界面和评审说明都优先降低理解成本：任务步骤用流程图，状态用对应画面，交互分歧用局部对照，连接/位置关系用可编辑示意图，资产规则用代表实例。文字补充图中难以准确表达的条件、后果和恢复方式；图标有歧义时配短标签，不能靠删字或加入装饰插画制造“简洁”。图形来源与制作由当前阶段工作流决定；文档排版不扩大设计范围。

需求 Page 以流程和原型画面为主体，旁注就近、简短且可读，详细规则链接到有界可读的对应资源。流程图的标签使用原生可见文本，箭头表达方向和分叉；截图引用说明其参考性质。图形、截图和可见连线不能代替真实原型连接。

精简重复说明，保留必要标签、关键规则、状态、仓库链接及真实定位；不把这些内容转成位图、隐藏副本或难以读取的小字。目标是准确理解，不设置一刀切的字数或图文比例。

| 内容语义 | Figma 表达 |
| --- | --- |
| 文档标题与版本 | 一个明确主标题，Contract/模板版本作为次要眉题；不让版本标签抢过项目/需求名 |
| 章节与小节 | 用字号、字重和段前间距表达层级；同级一致，标题靠近所属正文 |
| 正文与字段 | 按主题分短段；字段名适度加粗，值保持正文样式，不把整段都加粗或只靠空行分级 |
| 列表与步骤 | 原生列表或可读的项目符号/编号与悬挂缩进；并列项逐条呈现，步骤保留顺序 |
| 目录与比较 | 简短索引用分组列表；需要横向比较时用带表头、对齐列和自适应行高的原生行列结构，不粘贴 ASCII/管道表格 |
| 设计 token 与资源标识 | 按需使用可用的等宽字体，精确名称与值完整可读取；不因此增设源码或命令区域 |
| 链接与来源 | 有意义的标签和可点击链接；读取所需的完整 URL 或真实节点 ID 同时保留在可见文字里，不能只存于超链接属性 |
| 状态与提醒 | 用明确文字和克制的强调区分已确认/待实现/未核实；不能仅靠颜色，也不把每段都装进强调卡片 |

优先沿用已确认的项目文档规范。缺少对应配置时，以蓝图的文档默认值起步：标题 32、章节 24、小节 20、正文 18、辅助说明 14、标识 16；正文行高 150%、段间距 12、单列正文宽约 720，外层内边距 24、章节间距 48。它们是可调整的文档起点，不是产品 token 或统一验收阈值；以实际字体、语言、内容长度和截图调整。标识字体从实际可用字体中选取，不强制某个字体包；蓝图保留 `code` 配置键以兼容已有配置，仅用于必要的设计标识。

正文定宽并随内容增高，外层用 Auto Layout 管理间距；长文按主题拆节，超长资源按既有目录分成可独立读取的小资源。长链接允许视觉自动换行，保留完整地址；不要用缩小整页字体来塞满画板。整体视图能辨认标题与分组，正文可读倍率下能顺畅阅读和定位来源。

### 保持 Contract 1 可读取

`DH / Entry`、`DH / Module`、`DH / Resource`、`DH / Work Templates`、`DH / Handoff` 保留原生可见 TEXT 和原有节点 ID；在同一 TEXT 内按文本范围设置标题、字重、段落和链接样式，即可得到文档层级。必要的容器、背景与资产画面置于外层/旁边。

每个语义 TEXT 保留当前约定的完整设计内容，文字顺序与视觉阅读顺序一致；旧版的源码定位字段不属于必填内容。入口的一条仓库链接与模块目录不能只移到旁边的卡片；模块/资源的详细规则通过原有索引拆分，不另存一份隐藏的机器正文。若排版需要多节点表格而当前索引只指向一个 TEXT，先采用该 TEXT 内的分组列表，不能以美化为由让现有读取链丢失设计内容。普通需求说明可拆分为原生段落和表格，索引须定位到能有界完整读取的说明容器。

写入后既回读正文与真实定位，也查看整体和正文局部截图；覆盖标题层级、行距/留白、列表或表格对齐、长链接、中文与混合字体、截断/遮挡。工具不支持富文本或无法截图时，报告具体未完成项；文字写入成功不等于可读性已验证。

## 选用与组合

| 稳定模板 ID | 适用 | 结构与可变项 |
| --- | --- | --- |
| `work/scenario-flow` | 流程草图、当前页/状态及串联走查 | 流程图 → 获准的步骤画面 → 操作/反馈 → 汇入或结束；逐项补入原型入口、连接和确认范围，未生成与待补连接如实标注 |
| `work/proposal-comparison` | 交互局部备选或视觉代表方案 | 共同目标与约束 → 实际片段/代表画面 → 收益、代价与推荐 → 用户选择；按需呈现融合范围、整合代表稿及确认 |
| `work/resource-spec` | 解释规则、组件、模式与来源 | 标题/稳定 ID → 实际资产或使用实例 → 使用条件、属性/状态、依赖、设计依据与确认；区分设计/实现状态，需要时简述验证限制 |

三类模板可按需使用 `discussion` 与 `feedbackImpact` 槽位，用短文说明关键问题、真实取舍与理由、提案或画面怎样因反馈改变；无新问题时省略或简述沿用依据。未决内容保留待讨论状态，链接本阶段交接，不填访谈全文。回写只沿用已确认结论，不借模板重开设计访谈。

只在当前阶段所属区域组合：交互的流程与关键草图先确认，主流程逐页制作，串联确认后再补分支/状态；关键分歧才做局部备选。视觉在目标访谈后计划 2–3 套候选，但一次只制作某候选的一个代表页，齐备后再比较；整合和完整展开同样逐页、逐状态确认。小修改也适用，完整多套方案仅在明确要求时制作。逐项放行见 [交接约定](handoff.md#交互与视觉的逐项门禁)。

蓝图描述最终组织方式，不授权一次填满；只创建本轮获准内容，尚未生成的页面、状态或候选以短清单登记，不预建空白画板。Harness 用资源模板解释规则、Library 来源和代表资产，Init/回写沿用各自确认单位。

七类知识中的「模板库」仍用于**产品页面结构与交互模式**。文档工作模板登记在设计风格模块的 `documentation/work-templates` 资源下，不当成新的产品模式，也不新增第八类知识。

## 从原稿提炼项目配置

先观察已有场景栏、标题、参与端标签、连接线、注释和状态表达，再拟定配置与来源。重复稳定用法可以复用；单个局部值仅作为候选。已有明确批准的配置直接沿用。

- 字体取实际可用的项目说明字体；记录标题/正文/标识的角色、层级、行距、正文宽度，以及替代字体及其范围。画面副本保留产品字体。
- 配色按文档用途区分场景强调、参与端标签、交互注释、正文与状态。项目缺少对应规则时才采用蓝图中的文档默认值，并标明这是模板默认值。
- 单端与多端使用同一结构；参与端名称来自真实责任划分，不预设设备类型或固定两端。
- 场景步骤数量和分支按任务决定。比较流程时同一列表示同一步骤；没有画面的单元格明确说明等待、无操作或不适用，不能用不存在的产品界面填充。
- 画面槽位采用来源的宽高比；用于排版的缩略宽度与产品设计尺寸分开记录。保留未缩放设计稿的链接，不把缩略槽位当作研发尺寸依据。
- 文档样式使用独立命名空间，例如 `DH Docs / …`。默认可采用节点局部样式；只有已获准建立文件级样式或变量时才新增对应资产。

配置写在可见原生 TEXT `DH / Work Templates`，由设计风格模块的资源说明链接。内容包括使用的模板 ID/版本、字体与配色来源、文档排版覆盖项、布局选项、真实模板/组件节点或库引用、适用范围与确认记录。入口先于设计风格模块建立时，把文档样式建议并入首个模块提案，随后在设计风格模块登记；不为排版新增一次审批。仅有项目差异时只记录差异，无需把通用蓝图全文复制进 Figma。

## 原生构建与复用

按 [Figma 工具流程](figma-operations.md) 先核对目标与局部空间。使用 use_figma 创建组件时，加载其要求的组件库 Skill；不把 Console 与 use_figma 的扩展 API 混用。

1. 根据实际节点验证已有模板类型、属性、可编辑性和引用，匹配稳定模板 ID 与语义。名称相同不等于兼容。已有库可实例化时复用；只有 Frame 时按其可复制结构使用。
2. 标题标签、参与端标签、说明卡等重复单元可建为 Component，使用文本属性和必要变体；已有组件优先使用实例。每个组件留在命名容器中，返回实际 ID。
3. 外层模板使用可复制编辑的 Auto Layout Frame，便于增删步骤、参与端和方案。无需为步骤数量制造组件变体组合。流程分支可另行展开，保持语义和阅读顺序明确。
4. 按连接器单次操作限制分批构建。先建立当次需要的单元与结构，再填入已确认内容，返回每批创建/修改的真实 ID；失败后回读并只补缺项。
5. 资产说明绑定实际组件/模板、来源及模板版本。模板中的空槽必须标记用途；正式场景和方案中以真实画面、说明或明确的待验证项替换。
6. 在同一授权区域用本次任务内容检查复用；截图核对长说明、不同画面比例，以及任务确实需要的增删步骤/参与端。临时检查副本在核验后清理，已交付内容保留。

蓝图不执行工具调用，也不推导用户确认、业务状态或文件级资产权限。Figma 模板建成并回读、截图核验后，才能记录为原生资产已完成；真实产品行为仍按静态/运行验证分别说明。

## 旧工作区迁移

旧项目可能有「工作流程模板」和「原稿风格模板」两个分区。先分清通用流程、项目表达、产品模式和已经填入的需求/决策。

- 通用流程由插件维护，入口只引用当前四个阶段入口；不持续保留一份内容易漂移的流程副本。
- 可复用的项目文档组件/Frame 与风格依据归入 `documentation/work-templates`。同文件移动优先保留节点 ID；旧空模板不是已完成产品资产。
- 产品页面模式继续进入模板库；实际需求和选择记录保留其来源，不能当成空模板清理。
- 将具体移动、替换、删除和引用修复列入模块提案。已有明确批准同一范围时直接执行；先回读目标资产与修复入口、文本链接、原型跳转等已发现引用，再清理获准移除的旧容器。

后续更新按模板 ID、版本和项目覆盖配置比较差异，只升级获准范围，不整批重建已经填入内容的需求页。
