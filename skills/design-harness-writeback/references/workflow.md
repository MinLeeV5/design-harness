# 交付与回写工作流

1. 核对需求、实际确认、事实基线与源文件。按[交付保真](fidelity.md)确认交付类型、区域和状态，区分需求交付和公共基础更新；只要求导出时不额外晋升知识。
2. 运行协议、构建和类型检查；分别核对视觉对照、真实交互路径及行为真实性的证据。遗漏的壳层、组件或状态须修复或经用户确认缩小交付范围，不能用模拟成功、检查数量或“设计参考”替代完整 UI 保真。
3. 按[导出协议](preview-export.md)通过插件从当前需求与公共基础导出一个 HTML，浏览器直接下载或 CLI 指定资源目录外文件。实际验证离线交互与资源，项目不保存 releases、源码副本或清单；导出不自动记录为验收，后续修正重新导出。
4. 有明确批准的公共增量时更新 foundation 的规则、组件、资源与版本，记录边界、理由和来源；不把页面特例或未选候选自动提升为规范。
5. 公共基础仅保留一处；更新需检查向下兼容和已有需求，再次导出采用当前需求与基础。历史用 Git 记录。
6. 维护[交接](handoff.md)，分别报告交付保真、工程检查、真实服务验证范围、批准增量与未核实项后停止。

外部发布、Git 推送或在线分享仍需明确授权；默认只做本地导出。
