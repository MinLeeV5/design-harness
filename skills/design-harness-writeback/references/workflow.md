# 知识回写：只沉淀已确认增量

按 [交接约定](handoff.md) 读取用户指定设计的确认范围、产物版本、来源和候选增量，再按 [上下文读取](context-loading.md) 找到受影响资源。输入可以来自视觉或交互阶段，也可以是用户指定的已确认设计；没有视觉变化不要求空跑视觉阶段。

1. **核对来源。** 回读真实交付物，确认候选增量对应的是已确认版本。发现设计冲突、未决定的规则或缺失来源时给出具体问题与建议，由用户决定返回相应阶段；不在回写过程中设计解决方案。
2. **展示具体增量。** 按 [知识更新](knowledge-update.md) 给出前后变化、用途、范围、节点/文件级资产、依赖和状态。没有可复用变化就只提出需求索引或无回写结论，不制造规范。
3. **承接或取得批准。** 已明确批准的同一增量与范围直接执行。设计确认与回写批准分开判断，只询问尚未批准的实际变更；暂缓项留在需求 Page 的交接记录。
4. **更新并核验。** 仅写批准项，先真实资产与资源说明，后模块和入口索引。按 [回写检查](evaluation.md) 回读关系、状态与渲染；失败先查实际结果，只补未完成项。
5. **交付并停止。** 在本阶段记录实际更新链接、设计/实现状态、批准依据和剩余事项。报告完成、暂缓与待验证，不启动后续 Init 或实现工作。

保留当前实现与已确认待实现设计的区别；源码静态核查或原型体验不能证明产品已实现。不修改来源设计、团队源库或其他未批准范围，不自动跨项目传播规则。
