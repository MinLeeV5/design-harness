# 交付与回写工作流

1. 核对需求、实际确认与源文件。区分需求交付和公共基础更新；只要求导出时不额外晋升知识。
2. 运行协议、构建和类型检查，核对必要浏览器证据。未验证项如实说明，不把模拟运行当作真实产品验收。
3. 按[导出协议](preview-export.md)创建独立版本，拒绝覆盖；核验 HTML、源码、资源与字节清单。导出不自动记录为验收。
4. 有明确批准的公共增量时更新 foundation 的规则、组件、资源与版本，记录边界、理由和来源；不把页面特例自动提升为规范。
5. 公共更新不改既有需求与交付。显式升级通过新需求 ID 创建新基础快照，重新评审。
6. 维护[交接](handoff.md)，报告交付、批准增量与验证结果后停止。

外部发布、Git 推送或在线分享仍需明确授权；默认只做本地导出。
