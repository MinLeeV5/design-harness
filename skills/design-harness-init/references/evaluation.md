# Init 产出检查

在当前模块写入和补齐后检查真实资产与证据，无需独立 review 阶段或机器门禁 JSON。

## 每模块写入后

| 检查 | 看什么证据 | 不满足时 |
| --- | --- | --- |
| 内容与确认范围一致 | 模块提案、真实用户确认、实际节点及文件级变更 | 修复范围内偏差；新取舍回到该模块 |
| 现状有依据 | 在任务中核实相关原稿/代码与平台、渠道、版本；Figma 用产品行为与状态表达结论 | 缺证据明确未核实，技术核查细节不写入设计正文 |
| 仓库入口准确且简洁 | 入口仅一条经 remote 核实的完整仓库链接；无凭据、本机路径或主机别名 | 无法核实则标为待补；不扩展成源码定位表或技术附录 |
| 内容归属与读者匹配 | 项目上下文限于产品、任务、环境、渠道和业务边界；具体行为在布局、组件或场景，无路径/符号/commit/命令日志 | 按授权范围归位，用产品语言改写并修复索引 |
| 可渐进读取 | 入口→概览 TEXT→资源→资产真实 ID，适用时机与依赖 | 修索引，定向复读；不整页重扫 |
| 库确实可复用 | 变量 ID/别名/绑定；ComponentSet/Component/Instance 类型、属性、变体；模板结构 | 补真实资产，参考 Frame 不能冒充组件 |
| Library 来源适用且可定位 | 已启用/可访问范围、项目认可记录、真实库与代表资产定位、图标/插画/色彩复用规则 | 按 [视觉资产约定](visual-assets.md) 定向复核；检索受限标未核实，不能判为不存在 |
| 场景与状态真实完整 | 已批准范围的进入条件、分支、反馈、恢复；模板与场景映射 | 补相应状态/说明，不强制无关场景 |
| 图形表达降低理解成本 | 示意关系有事实依据，图标风格与主题一致，必要标签和后果可读，矢量/位图类型与来源准确 | 修正语义歧义、装饰干扰或错误类型声明 |
| 图形规则与代表资产一致 | 涉及时按 [图标](iconography.md) 或 [插画](illustration.md) 检查既有家族/系列、标签、实际尺寸与适用场景 | 只记录已核实的项目做法；不把社区示例参数或新生成样图当作存量规范 |
| 呈现可用 | 截图、目标尺寸、字体、排版、标签、内容无截断/重叠 | 修复后复核受影响处 |
| 增量不破坏既有事实 | 原页保护、当前实现与已确认待实现分开、依赖仍有效 | 恢复正确状态与引用，说明未完成部分 |

## 文档可读性检查

对本次写入的入口、模块/资源说明、模板配置和索引按 [文档排版约定](work-templates.md#文档排版与可读性) 检查：整体截图可辨标题与分区；正文局部截图可读、行长适当、段落/列表/表格对齐，长链接不裁切或被迫缩小。回读语义 TEXT，核对入口仓库链接、设计规则、状态和真实 Figma 定位；不要求补回旧源码字段。没有截图时明确未完成可读性核验，不能仅凭字符完整宣称排版通过。

## 工作模板检查

按 [工作模板约定](work-templates.md) 核对模板 ID/版本、项目文档配置、真实 Frame/Component/Instance、必要属性和引用。检查正文自适应、参与端与步骤对齐、源画面比例、长说明及本次所需的增删结构；实际内容中的空槽或候选状态不得伪装为已完成设计。迁移旧分区后核对入口、资源说明和已发现的原型链接，保留原有来源及确认记录。

设计风格模块另按 [设计描述约定](design-description.md) 核对适用章节是否解释视觉意图、用途与边界，并指向真实 token/布局/组件；不能只交形容词或数值清单。正文与精确值冲突、推测动机写成已确认、待实现覆盖现状等问题需修正。

## 如何表达结论

用具体“已核验、已发现问题、未核验/不适用及原因”，不输出综合审美分、置信度或准备百分比。Figma 可证明的属性与运行环境才能证明的行为分别报告；未执行运行测试不能说键盘、读屏、性能或真实状态切换已验证。

源数据只静态读过就按静态依据表达。截图看起来相同不代表组件实例、变量绑定或交互已正确；反之，结构检查通过也不替代渲染检查。
