# 初始化工作流

1. **确定依据与范围。** 读用户目标与项目约定，区分已有产品首次建立设计工作区与尚无界面的新项目。已有产品按[交付保真](../../../shared/references/fidelity.md)提取指定版本的规范、实现和可用运行界面；新项目承接已确认的用户、平台、设计意图与约束，缺失的关键决定再共创。读取 project.json 的设计组织模式；未确认时按[组织模式](../../../shared/references/design-organization.md)给出推荐、依据和代价，取得用户实际确认或明确委托后决定，并约定持续模式的主稿。复用已有范围、模式与授权，不为形式增加访谈。只读业务代码，不将业务运行模块作为设计工作区依赖。

2. **先建立覆盖清单。** 盘点范围内的产品壳层、共享布局、公共组件、组合模式和资产；工作区建立后将清单记入 foundation/design.md，维护来源、实现与预览位置、已提取／待补／已确认排除，沿用、变更和新增分别标明。未指定模块时先盘点公共层，再界定本轮实现范围，不自行缩成一个示例控件。内部文件可按公共组件职责归并，业务流程保留边界；有来源索引不等于已有实现。新项目清单记录约定要建立的基础，不虚构既有规范。

3. **建立运行与布局基线。** 已有产品在现有授权内尝试项目提供的开发或 Mock 运行方式，记录实际环境与限制。提取前追踪全局样式、单位转换、根字号、字体与行高、父级布局及滚动职责；取得代表页面在指定内容、状态、实际视口与缩放条件下的截图及计算样式，作为后续实例的对照依据，不只抄局部 CSS 数字。新项目按约定目标明确容器、布局与状态，标明设计草稿身份。无法取得运行基线时记录已尝试方式、原因及待核实项，继续可完成的源码提取。

4. **校准后扩展基础。** 按[模板职责](../../../shared/references/workspace.md)创建独立目录，用 CLI 的 --mode 及适用的 --primary 保存已确认模式；已有工作区使用 organization 承接配置，不重跑 init 覆盖。理由和确认来源记入 foundation/design.md。在唯一 foundation 中维护设计描述、Token、React 组件及 Catalog／Registry，工作台保持在插件。先建立代表布局的基础验证实例，与来源在可比条件下核对行高、条目及分组间距、标题、内边距、分割线和固定区域；新项目按设计目标核对，修正差异后再扩展其他模式。组件与页面模式按实际职责提取，保留适用的壳层、变体、菜单与浮层；模板按本项目实际模式和范围沉淀，不套用固定类别或数量。新增模式单独说明，模板默认值保持草稿。图片按[资产方法](../../../shared/references/assets.md)处理。

5. **补齐基础验证预览。** 承接代表实例，用现有 requirements 协议承载明确标为“基础验证”的预览，通过 new <预览ID> --preview 标明用途，完整 Spec 复用公共组件和页面结构，不另存一套模板 UI 树。预览不是产品主稿，不借预览用途拆分业务需求，也不为尚未启动的实际设计自动创建主稿。纳入本轮实现的公共组件与布局模式应有可定位的实例；在实际容器内核对外观、键盘、适用状态及真实触发路径，记录结果到预览 handoff.md。通用示例需替换或补齐本项目实例，预置状态不代替操作验证。源码提取、源应用 Mock、设计模拟与真实服务分别说明。

6. **评价后交付。** 按[本阶段验证](evaluation.md)核对覆盖清单、实际预览及检查结果，维护基础版本、可复用边界、确认状态与待补项。公共更新保持向下兼容并验证受影响需求，包括基础预览。交付实现位置、预览入口和验证边界后停止；未覆盖约定范围或未完成对应基线核对时，只交付阶段性结果，明确剩余项，不以 draft 标记或工程检查通过代替完成条件。用户尚未验收与初始化实现未完成分别记录。

基础验证预览属于 Init，不自动开展新的业务需求或进入交互、视觉阶段。项目知识不得写入插件分发资源。
