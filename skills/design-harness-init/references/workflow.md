# 初始化工作流

1. 读用户目标与项目约定，按[交付保真](fidelity.md)确定交付范围及事实基线，盘点规范、实际运行界面、上层壳层、组件、资源和当前行为。只读业务代码，不建立运行依赖。
2. 承接已有基础；缺失时按最有价值的模块共创意图、范围和复用边界，不为形式增加访谈。沿用、变更、新增与排除区域分别记录，保留来源版本、环境和未核实差异。
3. 按[模板职责](workspace.md)建立独立目录，在 foundation 中记录事实、设计描述、Token、React 组件及 Catalog／Registry，工作台保持在插件。默认值标为草稿，来源与未来设计分开。
4. 抽取当前任务所需的真实组件和布局职责；代表实例包含适用的壳层、控件变体、菜单与浮层，核对实际画面、键盘和状态，不只提取颜色或静态外观。图片按[资产方法](assets.md)处理。
5. 维护唯一公共基础的版本、适用边界、确认状态与说明；公共更新会影响既有需求，应保持向下兼容并验证受影响需求。交付基础位置、检查与待补项后停止。

仅初始化不自动生成需求。通用示例明确示例身份；项目知识不得写入插件分发资源。
