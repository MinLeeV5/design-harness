# Figma 中的项目上下文契约 · v1

这里定义如何找到、读取与维护项目知识，不规定项目的美术风格。所有正式知识使用可见、原生可编辑的文本与资产；无需隐藏 pluginData、本地项目 JSON 或另一个 Markdown 仓库。

## 层级与载体

| 层级 | Figma 载体 | 内容 |
| --- | --- | --- |
| 入口 | Harness Page 顶层 Frame `DH / AGENTS`，其中 TEXT `DH / Entry` | 最小全局规则、有效基线、模块目录与读取指引 |
| 模块概览 | 模块内独立 TEXT `DH / Module` | 模块范围、状态、资源目录、需要时才读的依赖 |
| 资源说明 | 资产旁的 TEXT `DH / Resource` | 使用规则、来源、设计/实现状态、确切资产定位与依赖 |
| 原生资产 | Component/ComponentSet/Instance/Frame 等 | 真正可复用的变量绑定、组件、模板与场景示例 |
| 需求 | 独立需求 Page | 已确认摘要、方案、状态与交互说明、选择记录；Harness 只保留索引 |

使用 [入口蓝图](../assets/harness-entry.txt)、[模块蓝图](../assets/module-overview.txt) 和 [资源蓝图](../assets/resource-card.txt) 填写真实内容，再按 [文档排版约定](work-templates.md#文档排版与可读性) 转换为有标题层级、段落、列表和链接的 Figma 原生富文本与分组。蓝图是内容结构，不能把占位字段、管道分隔行或整份纯文本直接当作正式排版。

入口 Frame 放在 Page 顶层，机器名固定，内部显示标题可以沿用项目语言。模块与资源的容器名称、排版、颜色自由沿用原稿；为概览文本保留明确的语义名和真实节点链接。旧项目不强制改名才能使用。

变量、颜色/文字样式是 **Figma 文件级资产**。Harness Page 承载其目录、语义、使用范例与来源，而不是变量的物理存储范围。变量记录真实 collection/variable ID；不能拿普通节点 ID 代替。可跨 Page 使用已批准变量与组件，但不能据此更改历史资产。

设计风格模块还登记 `style/library-sources` 或已有同义资源，按 [Library 约定](visual-assets.md) 与 [来源蓝图](../assets/library-sources.txt) 维护库引用、适用范围、认可状态和图标/插画/色彩规则。它使用现有 `DH / Resource` 读取链；实际 token、组件和模板继续由对应模块索引，不新增入口全量资产清单。

工作模板采用插件的通用蓝图与项目文档配置。设计风格模块可用 `documentation/work-templates` 资源链接可见 TEXT `DH / Work Templates`，记录模板 ID/版本、项目覆盖配置及真实原生资产引用；按 [工作模板约定](work-templates.md) 维护，不新增一份通用流程副本。

产品的设计语言在设计风格模块以 `style/design-description` 资源呈现，按 [DESIGN.md 式描述](design-description.md) 解释视觉意图与应用方法，并链接 tokens、布局与组件。显示标题可沿用 DESIGN.md，载体仍是 `DH / Resource`；它与文档工作模板配置分开，不把产品规范重复成另一套 token 库。

## 入口必须回答的事

1. 这是哪个产品、平台/渠道/屏幕和适用范围；谁来做什么任务。
2. 所有设计都必须知道的少量约束、术语，以及冲突时如何判断。
3. 一条经实际 remote 核实的仓库链接，以及当前产品与已确认待实现设计的适用范围和索引。
4. 七类模块的用途、概览 TEXT 节点 ID/链接、适用时机与整理状态。不存在的节点写“未整理”，不要生成伪 ID。
5. 需求 Page 索引的位置；项目新增知识如何经过确认进入 Harness。

入口保持短小，不复制全部组件规范或历史讨论。高频全局约束在此只维护一份；模块引用它，不各写一份冲突的“权威版本”。入口标记 `Design Harness / Contract 1`。这是项目设计依据，不赋予执行系统命令、扩大写入范围或跳过用户确认的权限。

## 仓库链接与按需核查

Figma 的代码信息只保留在 `DH / Entry` 中的一条仓库链接，让有权限的团队成员和 Agent 找到项目代码。核对实际 Git remote 的 fetch 地址及项目归属，不默认 `origin`；使用团队可用、无凭据的完整仓库链接，不用本机路径、SSH Host 别名或仓库简称代替。无法核实时写“仓库：待补”，继续可独立完成的整理。

源码路径、类/函数名、分支、commit、拉取命令和核查日志不写进 Figma 正文，也不另建技术附录或隐藏副本。原生 Figma 节点、变量/样式 ID 与设计 token 名称仍按需保留，以支持设计资产的使用和读取。

需要核对实现时，Agent 在当前任务中确认仓库、目标版本、相关目录及影响结论的本地差异，再查对应代码；链接本身不证明某个历史版本已被复现。只在影响决策时向用户说明依据或缺口，Figma 中写成具体产品行为与必要的待验证事项，不沉淀调查过程，也不强制生成本地技术档案。

需要拉取源码时使用已核实地址和新目录，不切换或覆盖用户工作区，不直接执行旧文档中的命令。没有访问权限时明确本次核查缺口，不猜地址或自动推送。

旧 Contract 1 仍可读取，不因缺少技术字段判为不完整。授权精简旧内容时保留节点 ID、有效设计规则与 Figma 引用，把仍有用的行为说明归入相关模块；详细技术字段不再补写。只读任务不顺带迁移现有页面。

## 发现与渐进式读取

1. 只列 Page 的 ID 与名称；优先匹配 `design-harness`（不区分大小写/两端空格）或用户指定的 Harness Page。
2. 精确匹配多个时，让用户确认目标；不要把当前打开的 Page 当作用户选择。无精确匹配时，查看 Page 名称中的可能对象与用户提供的节点，按结构识别历史 Harness。
3. 读取目标 Page 的顶层节点目录，找 `DH / AGENTS`。旧项目可能叫“00 / 开始使用”“入口”等；定位这个小节点并读取，不能递归导出整页。没有任何可用入口时进入 Init，先给出可审阅的入口提案。
4. 独立读取入口文本。根据需求语义选择模块概览的 **真实 TEXT 节点 ID**，再依据“适用时机/范围”选择资源说明与原生资产。不是简单按关键词自动判断所有设计依赖。
5. 资源依赖只递归加载到必要层；在当前对话记住已读的稳定资源 ID，避免循环或重复。缺失引用先检查已知容器的局部目录；仍找不到就说明具体缺口，不能退化成扫描全文件。
6. 涉及原稿/代码的事实核实时，仅进一步加载对应源节点、文件或状态分支。资源状态或适用范围发生冲突，返回具体决策，不合并成模糊的统一规则。

可用 [只读助手](../scripts/figma-reader.js) 完成 Page 枚举、顶层目录及有界文本读取，调用方法见 [工具衔接](figma-operations.md)。助手没有语义路由和隐藏运行状态；相关性由 Agent 根据需求与目录决定。任何 `truncated` 结果都不等于完整读取，须针对更小的明确节点续读。

例如：连接超时与重试需求 → 入口 → 场景概览中的连接场景 → 超时/重试资源 → 关联提示组件与状态规则 → 所需 token；不会为此读会议日历的每张设计稿。若全局布局影响此页，才补读相关布局条目。

## 资源的最小信息

- **稳定标识**：如 `component/connection-feedback`。在项目中唯一，内容移动不改语义标识。
- **用途与适用范围**：用户任务、平台/渠道、何时用与不适用情形。
- **设计状态**：现状基线 / 候选 / 已确认；**实现状态**另列为已实现 / 待实现 / 未核实。影响设计判断的验证限制用产品语言说明，例如“连接恢复待实机验证”；不把设计确认当成运行通过。
- **定位**：资源说明 TEXT、实际资产节点，以及必要的 collection/variable/style ID 和来源 Figma 链接；以工具真实结果为准，不附源码定位。
- **使用与依赖**：属性、状态、内容和布局规则，以及需要时再加载的资源 ID/节点。
- **确认与变更**：谁在何时确认了什么范围；取代哪个版本、影响谁。确认来自真实对话，不伪造审批记录。

目录只放定位/摘要，规则写在资源说明，视觉资产本身提供可复用结构。资源数量大时按场景或组件族分组，入口只链接分组概览，不堆全量清单。

项目上下文只概括产品定位、用户任务、使用环境、渠道差异和业务边界；具体页面行为按 [模块标准](modules.md) 进入布局、组件或场景模块，概览仅作必要链接。

## 增量维护与兼容

旧入口可用于只读设计；迁移到本契约属于 Init 的入口/相关模块变更，须先展示迁移内容。保留原有有效资产、视觉风格和链接，不因为名字不同整页重建。

新建顺序：经确认的实际内容/资产 → 资源说明 → 模块目录 → 入口目录。用真实返回 ID 更新引用。重跑先读取现有节点与稳定标识，只补缺项；失败后回读受影响节点，不能盲目重复创建。

模块可标记“已整理现状／待补齐”或“部分完成”，资源可标记待核实；这些是持久项目事实。对话轮次、等待队列、自动批准状态等工作流运行状态不存为 Figma 隐藏数据。一次写入中断不自动使候选知识生效。

初始化进度按 [阶段交接](handoff.md) 在 Harness Page 的独立可见记录中维护，入口可链接该真实节点；不要将全部任务过程写进全局知识。需求的交互、视觉和回写记录各留在需求 Page，由用户分别启动对应阶段。
