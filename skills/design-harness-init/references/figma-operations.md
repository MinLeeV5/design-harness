# Figma 读写：盘点与建库

本 Skill 携带工作流与可复用读取函数，Figma 读写由当前会话可用的连接器执行。先发现工具，再核对实际连接与目标文件，最后按当前需求选择操作方式。

## 1. 发现能力并探测连接

1. 从当前工具列表或工具搜索发现 Figma 能力。先找 `figma_get_status`、`figma_list_open_files`、`figma_execute`、`use_figma` 以及本次操作的专用工具；只读取相关工具的实际说明与参数，不默认加载完整工具目录，也不依赖固定 MCP 前缀。
2. 发现 figma-console-mcp 后，按 [Console 指引](figma-console.md) 做连接探测。区分“已注册”“目标文件已连接”“该操作可用”；Bridge 断开时某些 REST 读取仍可能可用，不能把全部 Console 能力一概判为可写或不可用。
3. 使用 `use_figma` 时按 [对应指引](figma-use.md) 加载其前置 Skill，以目标 fileKey 做必要的小范围读取确认访问。只有读取工具时，根据实际能力继续定位和盘点，不为探测而创建测试节点。
4. 在对话上下文中记住本次需求、已核对的文件/Page、可读/可写/可截图能力与所选工具即可，不生成工具配置档案。首次操作、连接变化、切换目标或失败恢复后重新核对；正常连续操作复用当前探测结果。

## 2. 按需求选择工具

用户明确指定的连接器优先；否则在能访问正确目标的工具中选择。专用工具能完整表达本次操作且目标范围可控时优先使用，复杂编排再用脚本执行工具。同一操作不通过两个连接器重复执行；切换前核对文件、节点与已完成结果。

| 当前需求 | 选择依据 | 按需加载 |
| --- | --- | --- |
| 找 Harness Page、读取入口或模块 | 小范围节点读取；有执行能力时复用下方有界读取助手 | 已选执行方式的指引 |
| 盘点变量、样式或组件 | 有过滤与分页的专用读取工具，返回当前模块需要的内容 | [Console](figma-console.md) 或 [use_figma](figma-use.md) |
| 发现适用 Library 与视觉资源 | 区分已启用与可访问库，限定来源搜索，预览代表资产并记录真实引用 | [视觉资产](visual-assets.md) |
| 批量变量、组件实例和属性操作 | 已连接且能限定资产/父容器的专用工具；其他情况下使用支持对应 API 的执行工具 | 仅加载所选方式 |
| 建 Page、复制模板、组织布局与原生文本 | 按页面范围编排 `figma_execute` 或 `use_figma`；简单局部修改可选专用工具 | 仅加载所选方式 |
| 写后验证 | 回读节点属性，并用能反映本次修改的截图检查实际渲染 | 所选连接器的验证说明 |

只有部分操作不可用时，针对该操作选替代工具。Console 未连接时，若其他连接器支持正确目标则继续；全部缺少写入时明确缺口，继续只读调查与方案准备。探测不自动安装服务、修改 MCP 配置或申请额外权限。

创建文件与创建 Page 不同。本流程通常在用户项目中新建 Page；不能为了缺少入口而创建另一个 Figma 文件。不要写死某台电脑的 Skill 路径、端口、fileKey、字体或品牌色；以当前工具契约和项目资产为准。

如果只有读取能力，可以继续盘点并准备可审阅的模块内容；明确哪些写入未完成以及缺少什么能力。不要把图片、SVG 导入或本地说明文件冒充原生组件库。写入受阻时保留已授权方案，不反复索要同一授权。

## 有界读取助手

[figma-reader.js](../scripts/figma-reader.js) 定义无依赖函数 `readDesignHarness(figma, request)`。根据已选方式，把完整函数源码放入 `figma_execute` 或 `use_figma` 的 `code` 正文，再追加一次调用；调用参数与返回结果解包遵循该工具当前契约。例如：

```js
return await readDesignHarness(figma, {action: "pages"});
```

在调用中实际替换 ID，不要直接执行下列占位值：

```js
return await readDesignHarness(figma, {
  action: "page-index", pageId: "<目标 Page 的真实 ID>"
});
```

```js
return await readDesignHarness(figma, {
  action: "read", pageId: "<目标 Page ID>",
  nodeIds: ["<入口或模块概览 TEXT 的真实 ID>"]
});
```

- `pages` 只取 Page 名称与 ID，并列出精确匹配 `design-harness` 的候选；不会自动替用户选多个候选之一。
- `page-index` 只读已选 Page 的顶层元数据，返回入口候选。目录超过上限时用返回的 `nextOffset` 接续，不扩大到递归全文。
- `node-index` 对明确指定的局部容器提供同样的子节点分页；参数为 `pageId`、`nodeId`、可选 `offset`/`limit`。深度或节点预算用尽时，按返回的 `childOffset` 继续定位小节点。
- `read` 只读显式节点及小范围子节点的可见原生文本；拒绝 PAGE/DOCUMENT、跨页及重复目标，限制目标数、遍历节点、深度和字符量。隐藏子树不作为已知规范；需要时单独检查并说明。
- 返回 `truncated` 表示不完整。`continuations` 给出节点 ID、原因以及 `childOffset` 或 `textOffset`；`continuationNodeIds` 是其去重摘要。长 TEXT 可单独用 `textOffset` 分段（JavaScript UTF-16 偏移），容器则先 `node-index`。不能把截断结果作为完整约束。
- 每次调用重新选 Page 一次；不依赖上次工具的当前页面状态，不调用全文件加载或隐藏 pluginData。

函数只帮助可靠定位和限制读取，不替代项目语义判断、变量 API、资产属性检查或截图。错误会终止当前读取，不悄悄换一个同名节点。

## 写入过程

每次只写已批准的模块或需求范围。准备布局与内容后再请求尚缺的确认；已经批准的操作直接执行。

1. 核对所选工具实际指向的文件与 Page，回读相关原始节点并查看目标区域截图，确认来源与目标不同、布局空间可用且无并发变动影响本次计划。
2. 读取当前工具 API 文档，使用支持的原生创建/克隆/实例 API。先加载实际字体，再修改文本；布局用项目合适的 Frame/Auto Layout。
3. 创建真实内容和资产，保留 source→new 节点映射。只有实际 Component/ComponentSet 才声明为组件；组件描述属性不能误用到普通 Frame。
4. 如创建变量/样式，复用已确认资产或使用批准的命名空间；核对文件级 ID、模式、别名和节点绑定。编辑一个 Page 的许可不能推导为改写全部全局变量。
5. 在 Figma 原生 TEXT 填写 [上下文契约](context-contract.md) 的入口、模块与资源说明，按 [文档排版约定](work-templates.md#文档排版与可读性) 设置富文本层级。保留完整字段、真实定位和原有 TEXT ID；不以纯文本平铺或不可读取图片代替文档。
6. 返回实际创建/修改节点 ID、类型和关系。再回读关键属性并查看截图，按 [检查标准](evaluation.md) 修正。

失败/超时先回读受影响区域，确定哪些对象已创建，再继续缺项；切换连接器也不能重放整个写入。只清理可核实为本次失败产生的空容器或临时节点，保留原稿和用户资产。工具不支持需要的原生属性时报告具体缺口，不把近似结果标成完成。

整理模板时保留可编辑结构与来源；建设组件库时优先实例化或创建原生组件。与任务无关的源码、Figma 历史 Page 和已发布组件库不在默认写入范围。
