# 工程实现工作流

## 1. 确定设计与实现范围

按[来源](sources.md)识别目标仓库、目标模块、本次任务及参考设计。采用用户指定或已有明确选择的设计、候选和版本，记录足以追溯的来源。

明确涉及的页面、区域、流程和状态；局部实现按局部范围推进，完整页面同时识别适用壳层与共享区域。设计中的页面或组件划分用于理解体验，代码边界由目标工程决定。

先核实可查事实。多个候选、版本或目标的差异会影响本次落地时，只澄清当前关键歧义，不根据目录顺序或修改时间选择。已有范围、授权和决定直接承接。

## 2. 调查目标工程

读取当前作用域的 AGENTS.md 及其指向且与任务相关的规范、技术设计和流程，再检查受影响入口、直接依赖、现有实现与邻近测试。重点确定：

- 实际语言、框架、版本、构建方式和验证命令。
- 页面挂载、导航、宿主容器和模块职责。
- 共享组件、主题、样式、图标、字体及资源规范。
- 数据来源、状态管理、生命周期、异步处理和相关平台约束。

以仓库事实确定实现方式，例如 Android 项目沿用现有 Views 或 Compose 及对应导航、主题和状态模式。文档与代码存在影响方案的差异时，说明依据与影响，按项目流程处理；调查围绕当前任务展开。

## 3. 理解 UI/UX 意图

先读取需求、交接和相关交互说明，再按需查看候选 Spec、参数、组件、公共基础及资产，结合实际预览理解：

- 信息层级、区域关系、布局、内容优先级和宿主归属。
- 主路径、分支、返回、取消、恢复及相关状态。
- 滚动、浮层、输入、焦点、尺寸适配和关键视觉细节。

源码提供结构与行为线索，运行预览提供实际画面与操作事实，交互说明补充条件与规则。预置场景只提供初始状态，还需明确实际进入、退出和恢复路径。三者存在影响实现的冲突时，保留差异并澄清对应部分。

## 4. 确定落地方式并实施

存在保真策略待定、跨平台差异或业务能力缺口时，按[差异与适配](adaptation.md)处理。按目标项目流程说明实现落点、复用方式、必要改动、共享影响和验证方法，复用已确认方案。

建立本次体验要求与代码职责、验收步骤之间的对应关系，表达深度与任务规模相称，不要求设计元素和源码文件逐项映射。

先落实宿主与页面边界、布局结构、数据和状态连接及关键交互，再收敛字体、间距、颜色、边框、图标和动效。复用或扩展现有能力时保持项目职责划分；共享组件、主题或资源的变化须识别实际影响并验证相关使用方。

局部细节在已确认范围内自主决定；关键范围、行为、契约或职责变化只重新对齐受影响部分。明确改动沿用项目流程推进，不固定逐页逐状态审批。

## 5. 验证与交接

按[评价](evaluation.md)分别验证工程质量、视觉表现、实际交互和业务连接。先完成最接近改动的检查，再按影响扩大；验证环境采用目标工程适用的浏览器、模拟器或设备。

交接沿用目标项目的记录位置与流程，保留参考设计及版本、本次范围、保真策略、主要代码落点、共享影响、实际验证结果、剩余差异和未完成事项。引用设计来源，不另建重复的完整需求或设计副本；实现中发现的设计缺口按对应设计维护授权处理。

范围未完成或关键体验尚未验证时，报告阶段性结果及剩余步骤。Agent 自检与用户验收分别记录，完成本阶段后停止。
