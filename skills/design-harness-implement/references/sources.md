# 本阶段来源

按本次问题读取最小相关内容，区分三类依据：

| 来源 | 用途 |
| --- | --- |
| 用户指定设计、交互说明及相关设计资源 | 本次 UI/UX 体验要求 |
| 目标项目规范、技术设计及现有代码 | 实现方式、工程约束与当前能力 |
| 已确认业务需求、技术方案与接口契约 | 业务规则与真实能力边界 |

## 目标项目

读取当前作用域 AGENTS.md、其指向的相关规则和文档，以及实际模块、构建配置与邻近测试。仅使用环境中实际可用的工具和开发流程；公开 Skill 不依赖本插件仓库维护用的开发能力。

规范与代码存在影响方案的差异时说明依据与影响，按项目流程处理。项目资料不足以回答关键实现问题时，再按实际框架和版本查官方文档的相关部分，不预置 Android、Web 等平台的固定实现模板。

## 设计资源

用户已明确指定本轮设计时直接承接；否则结合 project.json 中的[设计组织模式](../../../shared/references/design-organization.md)定位主稿或独立设计，再读取对应 manifest.json、requirement.md、handoff.md 与相关 interactions/*.md。

按需读取当前候选的完整 Spec、参数、Catalog／Registry、组件和项目公共基础。资源关系见[资源协议](../../../shared/references/protocol.md)，行为说明与条件见[交互协议](../../../shared/references/interactions.md)，已记录的选择、依据和验证边界见[设计交接](../../../shared/references/handoff.md)。这些资料用于理解设计输入，目标工程的开发与交接规则从该项目获取。

区分草稿、候选选择、临时提案与实际确认，采用本轮明确指定或已有效确认的来源。scenarios.json 只提供体验初始状态，模拟代码只提供设计行为线索。

涉及正式业务 PRD 时按[来源与承接](../../../shared/references/product-source.md)核对相关来源及可得版本；不可访问或无法比较时说明限制，不宣称已核对最新内容。

## 预览与资产

需要操作设计预览时，按[预览与导出](../../../shared/references/preview-export.md)使用设计所在项目实际采用的工具包版本；设计资源和目标工程可以位于不同位置，不要求目标工程初始化设计工作区。

资产按目标项目资源规范使用，保留实际采用素材的来源与许可。涉及插件共享指导及素材来源时，按[来源与许可](../../../shared/references/sources.md)查阅适用部分；外部方法不替代项目事实或业务决定。
