# 本阶段验证

依据目标工程的实际代码与运行结果评价，采用开发者已选择的保真策略，区分以下证据：

| 验证方面 | 核对内容 |
| --- | --- |
| 工程质量 | 项目要求且与改动匹配的构建、静态检查和必要测试；共享改动的实际影响 |
| 视觉表现 | 在可比内容、状态与目标尺寸下，依据所选策略核对结构、层级、字体、资源及关键细节 |
| 实际交互 | 从目标应用真实入口操作主路径和必要分支，检查输入、导航、反馈、取消、返回及恢复 |
| 业务连接 | 明确测试替身、本地模拟与真实服务各自验证的能力及未完成依赖 |

完成前核对：

- 参考设计、候选及来源版本可追溯，已实现内容与本轮确定范围一致。
- 实现符合目标项目技术体系、代码约束与职责边界；未因设计技术栈引入无关运行依赖。
- 设计差异按所选策略处理；项目 UI 规范优先时，仍核对确定的操作路径、信息层级与状态要求。
- 已在适用的实际容器中检查页面、相关宿主区域、滚动、浮层及必要尺寸，跨平台适配结果与确定的体验一致。
- 关键状态从真实操作可达，预置展示与实际触发分别验证。
- 缺失业务能力按项目流程处理，剩余依赖和阶段性交付边界明确。
- 交接记录包含实现范围、策略、代码落点、验证结果、剩余差异和未验证事项。

设计工作台的效果与操作只证明设计侧表现，目标工程构建成功不等于视觉和交互通过。运行验证采用目标项目适用的浏览器、模拟器或设备；无法执行的检查标为未验证，说明限制与剩余步骤，不用任意像素相似度百分比替代判断。

范围未完成或关键体验未验证时，报告阶段性结果；Agent 自检不代替用户验收。检查结果与截图按目标项目约定处理，不为本 Skill 增设固定证据目录。
