# Design Harness · 交互设计

只处理需求与交互。先读 [当前阶段工作流](references/workflow.md) 与 [交接和恢复](references/handoff.md)，继承指定产物与已有确认。

| 当前需要 | 按需读取 |
| --- | --- |
| 获取项目依据 | [上下文读取](references/context-loading.md) |
| 进入或评审流程、当前页/状态 | [逐题共创访谈](references/interview.md)，检查关键取舍，按反馈修订后再验收与放行 |
| 制作当前页/状态或串联走查 | [原型制作](references/prototyping.md)、[工具选择](references/figma-operations.md) |
| 组织需求 Page | [需求蓝图](assets/requirement-page.txt)、[文档模板](references/work-templates.md) 对应部分 |
| 检查当前交互交付 | [交互检查](references/evaluation.md) |
| 项目依据不足以判断具体问题 | [外部来源](references/sources.md)，只读取相关段落 |

每项先回述理解，未决行为一次讨论一个问题，给推荐、理由与代价，反馈落实为当前稿变化；无新取舍沿用既有决定，不凑问题。每项先获准再生成，实际稿足以判断后再等待验收与下一项放行；取舍回答不自动放行下一页。主流程串联确认后再补分支/状态。交互交付后停止，视觉由用户另行启动。
