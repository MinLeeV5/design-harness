# 当前交互交付检查

在流程草图、当前页、单页状态和串联走查各自的门禁检查本次范围，不为一次局部修改重跑全部路径。

- **任务与顺序**：流程和关键草图确认后才制作主流程；逐页通过后还有串联确认，随后才补分支与完整状态。分支逐页、状态每轮单页一种，未做、暂缓与不适用清楚区分。
- **生成范围**：本项有明确放行，只生成获准页/状态及必要连接；必经等待只作最小表达，没有为复用组件、补连接或低保真完备性提前铺开状态。实际稿展示后停止，当前验收与下一项放行分别可核对。
- **可体验产物**：真实起点、触发条件、已生成目标和返回/退出可回读，没有假 ID、遮挡或意外死路。逐页阶段尚无目标的连接明确待补，未预建未放行画面；串联确认前补齐适用连接。可见流程箭头不能代替 reactions。
- **用户理解**：真实内容与操作尺寸足以判断交互；短标签、反馈、后果和恢复方式清楚，必要关系用可编辑图示。
- **证据边界**：连接配置、实际点击、用户确认、产品运行分别报告；原型无法完成时保留缺口，请用户决定调整范围或补足能力。
- **可恢复交付**：需求 Page 与交接记录可读，当前页/状态、版本、验收、下一项范围与放行依据和真实产物一致；待确认项恢复后仍等待。截图检查文档层级、文本与画面，而非证明产品运行。

制作错误在授权范围修正；新的行为取舍由用户决定。检查通过不等于用户批准；交互阶段完成也不批准视觉或全局知识变化。
