# 交互工作流

1. 读需求、交接、项目共享基础及必要实现事实，按[交付保真](fidelity.md)明确用户任务、交付范围、来源基线及可观察验收条件。
2. 关键分歧逐题共创；已有决定直接承接。按完整任务范围建立需求，采用[文档协议](protocol.md)，登记页面、适用的产品壳层、状态及明确排除项。
3. requirement.md 记录目标、范围和验收；interactions/*.md 按[交互协议](interactions.md)独立记录正文、页面归属、状态条件及标注模式；完整 Spec 组合页面，Catalog／Registry 注册 React 组件并实现可操作流程；scenarios.json 仅登记体验初始状态。路由与可观察状态接入工作台 SDK，实际跳页后同步顶部和说明。复杂流程可补 Mermaid，不强制另做静态线框。
4. 复用项目共享基础；沿用区域保留实际入口、控件和菜单层级，交互与视觉共用 Spec 与组件。未实现的服务行为在评审说明中明确本地模拟，不连接业务服务，也不因此省略已声明的 UI。
5. 在[预览](preview-export.md)中从真实入口体验主流程、分支、菜单／弹层、校验、键盘、固定与滚动区域以及恢复；区分可到达路径和仅预置场景。完成范围内必要页面和状态，不逐帧请求许可。
6. 展示实际产物与分项证据，处理反馈并维护[交接](handoff.md)。由用户决定视觉细化或按需导出。

关键分歧只比较对应局部；明确改动直接落实。设计确认与公共回写分别记录。
