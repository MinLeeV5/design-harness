# 交互设计：逐题共创，主流程逐页推进

按 [交接约定](handoff.md) 恢复本次需求，只读当前项依据。每个流程、页面、状态与串联评审都按 [共创访谈](interview.md#本项的讨论循环) 回述理解、检查未决取舍，逐题讨论并据反馈修订，再执行 [逐项门禁](handoff.md#交互与视觉的逐项门禁)。缺失事实先查，已有决定承接，无新取舍不凑问题；不能只展示下一步计划就声称完成访谈。

## 1. 确认流程与关键草图

从用户任务与成功标准共同确定入口、完成结果、参与端、主路径、必要分支与状态条件和不做的部分。先回述已理解的目标，对影响流程的未知意图逐题给推荐与理由，按回答修订流程设想；已有结论承接。确认本轮流程图与关键草图范围后，用流程图、简易线框和少量说明呈现讨论稿，不提前制作完整页面或各类状态稿。围绕草图检查操作顺序与后果，有未决取舍先讨论；实际稿获交互方向确认后才进入主流程，可同时放行第一张具体页面。小改动只处理受影响片段。

每次需求使用独立 Page，已有则复用；在已授权区域按 [需求蓝图](../assets/requirement-page.txt) 只建立本轮需要的内容。分支与状态先登记条件和优先级，不预建画面占位或全套空白容器。页面权限不等于文件级变量、主组件或原稿的修改权限。

## 2. 逐页制作主流程

将正常主路径按操作顺序列出，进入本页先说明用户此时知道什么、要做什么和承接依据；有未决的操作或反馈先逐题共创，足以支撑本项后提出具体制作范围。**每轮只制作一个已获准的页面**。按 [原型制作](prototyping.md) 表达本页必要操作、关键反馈和已确认的返回/退出，逐步建立可点击原型。主流程必经的等待用短提示或简易占位保留语义；完整加载、空态、失败、禁用等状态稿留到后续。复用项目组件与真实内容，不因组件有多种变体而展开所有状态，不加载插画生成或视觉精修流程。

默认一套主方案；关键交互有分歧时，局部备选也逐项获准、生成与确认，再把选定方式并回主线。每页检查并展示后解释行为及采用理由，围绕实际位置逐题处理用户反馈，说明并展示修订效果；无新取舍说明沿用依据。当前稿足以判断、下一页行为明确后，附下一页计划并停下等待合并验收与放行；取舍未决时先等待讨论回答。要求修改就只改当前页。尚未生成目标只登记待补连接，不为连通原型提前生成；逐页验收不等于整条主流程已通过。

## 3. 主流程串联确认

各页已确认后，补齐已确认行为对应的连接，按 [检查](evaluation.md) 从入口走查到完成及适用的返回/退出。分别报告连接回读、实际点击或待验证限制，围绕完整任务展示跨页顺序与反馈，逐题讨论串联暴露的理解或退出问题；修改已确认行为先取得修订范围。问题解决后停下确认整条主流程，随后才按已放行的下一项补分支或状态；不能以各页分别通过代替串联确认。

## 4. 逐项补齐分支与状态

从已登记清单提出下一项及理由，先共创本项尚未决定的触发、保留信息、恢复/退出或连接方式，再确认具体范围。分支内部仍一次制作一页，按当前页讨论循环评审；各页通过后再串联走查确认。状态一次只制作**一个页面的一种状态**，围绕用户如何理解和恢复讨论实际稿，验收放行后才继续下一种；不一次铺出同页全部状态。既有决定与常规细节委托在当前项内承接，暂缓、不适用和待验证分别记录。

分支或状态暴露主流程冲突时，给出受影响决定、原因和建议，由用户决定是否重开。只修订批准范围并复核依赖；受影响的旧确认不能沿用，不重问未受影响项。每个门禁更新当前页/状态、版本与下一项放行，恢复后继续该项。

## 5. 交付并停止

交付流程与关键草图、主流程及适用分支/状态的原型入口、确认范围和必要验证限制。记录逐项及串联确认的产物版本、仍未完成的项；不能把主流程确认当成全部分支/状态确认，也不能把静态图当成可点击原型。

用户可在知道验证限制后确认方向，或明确缩小交付范围；保留真实限制。交互就绪后建议用户在新任务调用 `$design-harness-visual` 并提供本次交接链接，**本阶段到此停止**。不细化正式视觉，不更新 Harness 全局知识。
