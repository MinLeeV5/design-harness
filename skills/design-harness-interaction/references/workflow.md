# 交互工作流

1. 读需求、交接、固定基础及必要实现事实，明确用户任务、范围、规则与可观察验收条件。
2. 关键分歧逐题共创；已有决定直接承接。按完整任务范围建立需求，采用[文档协议](protocol.md)。
3. requirement.md 记录行为、异常和规则；React 实现可操作流程；scenarios.json 登记场景及说明定位。复杂流程可补 Mermaid，不强制另做静态线框。
4. 复用固定基础；交互与视觉共用源码。未实现的外部行为清楚标识为本地模拟，不连接业务服务。
5. 在[预览](preview-export.md)中体验主流程、必要分支、校验、键盘与恢复。完成范围内必要页面和状态，不逐帧请求许可。
6. 展示实际产物与验证边界，处理反馈并维护[交接](handoff.md)。由用户决定视觉细化或固定交付。

关键分歧只比较对应局部；明确改动直接落实。设计确认与公共回写分别记录。
