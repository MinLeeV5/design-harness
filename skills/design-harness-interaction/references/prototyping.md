# 可点击低保真原型

在流程与关键草图已确认、当前页面或状态已放行时读取。使用 [原型蓝图](../assets/interaction-prototype.txt) 组织本项产物；顺序按 [工作流](workflow.md)，生成范围与停顿按 [逐项门禁](handoff.md#交互与视觉的逐项门禁)。

## 覆盖范围与保真度

- 主流程最终连通真实入口与完成结果，但本轮只做一个已获准的页面。保留本页必要操作、关键反馈与已确认的返回/退出；等待过程用短提示或简易占位表达，不制作完整状态稿。分支与完整状态待主流程串联确认后再补；状态每轮限定为单页的一种状态。
- 低保真保持真实信息层级、内容和操作尺寸，以判断交互为准。可复用项目组件、变量和现有画面，不必人为去色或重画；不提前精修阴影、装饰和情境插画。
- 需要图才能判断操作时先做可编辑示意图。占位图要说明用途，不能让占位符承载关键操作含义。
- 默认一个主方案。局部备选复用相同前提与内容，比较完后把选定方式并回；不用多套完整原型增加评审负担。

## 建立真实交互

1. 按 [工具流程](figma-operations.md) 核对文件、Page 和原型能力；发现当前连接器支持的原型写入、读取及预览方式。需要 API 细节时查 [Figma Reaction](https://developers.figma.com/docs/plugins/api/Reaction/) 与当前工具文档，不把某连接器扩展当通用 API。
2. 在本需求授权区域仅建立当前项的原生 Frame/Instance；同页变体不额外展开。确定本页操作与已确认目标的关系，再设置触发、返回/关闭和当前获准状态的切换。新增分支复用主流程已有目标。
3. 使用当前支持的专用原型操作或 Plugin API 写入 reactions 等真实连接，设置有效的流程起点；只修改本次范围，保留已有无关反应与起点。不能把可见箭头、节点名称或文本链接当作原型跳转。
4. 设备连接、网络结果、权限变化等外部事件若无法真实触发，用明确标注的演示控制或状态入口模拟。把模拟控件与产品 UI 分开，不虚构已实现的自动行为。
5. 回读本次触发条件、目标 ID、起点及状态连接，排除不存在的目标、跨错 Page、被覆盖的点击区域和意外死路。复制画面或视觉调整后复核引用。
6. 提供由真实文件与节点定位得到的原型入口。用当前可用的预览/浏览器/桌面能力从起点实际点击；只具备编辑 API 或截图能力时明确“连接已配置，点击待验证”，交给用户体验，不能宣称已走通。

目标页尚未获准生成时，只用短说明记录计划跳转和待补连接，不预建目标 Frame、不连接假 ID，也不把讨论草图冒充完成稿。目标页获准且生成后，补齐已确认行为对应的连接；逐页阶段如实报告尚未连通的范围，主流程串联检查时不再把遗漏连接当作正常待办。复制、补连接或修复不能成为预生成下一项的理由。

不预设每个连接器都支持原型。如果专用工具缺失但执行工具支持原生 API，使用执行工具。仍无法构建可点击原型时，继续完成流程与静态讨论稿，说明缺口，请用户选择补足能力或明确调整本次交付；不能悄悄把静态连线稿当成交互阶段完成。保留已有授权，不为换工具重复请求相同写入许可。

## 按路径走查与确认

当前页只检查本项已生成内容和可用连接，展示后按 [共创讨论循环](interview.md#本项的讨论循环) 围绕实际位置处理未决行为与用户反馈，说明并展示修订效果，再等待验收及下一项放行。全部主流程页面确认后，再检查入口 → 必要操作 → 反馈 → 完成及返回/退出，讨论串联暴露的问题后确认整条流程。分支逐页完成后检查触发点 → 分支操作/反馈 → 回主流程或结束；单页状态检查触发、含义及获准的恢复方式。局部修改后复核受影响连接。

展示实际稿、可体验部分与限制，说明采用理由与反馈带来的变化。未决取舍先逐题讨论，足以判断当前稿与下一项行为后，附具体下一项计划再合并验收与放行。选择行为不等于验收未展示画面或授权下一页；全部适用交互完成后交付并停止。

分别表达证据：

| 证据 | 能说明什么 |
| --- | --- |
| 原型连接回读 | 触发、目标、起点已配置，引用可解析 |
| 预览实际点击或用户体验反馈 | 对应路径在 Figma 原型中的表现；说明由谁体验、覆盖哪条路径 |
| 产品运行检查 | 实际设备、后端、焦点/读屏等行为；不能由模拟原型推断 |

用户可以在已知验证限制下确认设计方向；未执行的检查仍保留待验证状态。交付时记录原型基线与确认版本；新事实改变交互时，先由用户决定是否重开受影响的决定。
