# 交互访谈：一次一个关键问题

先从已有项目约束、交付物和相关代码查事实；不要把可查询的状态、尺寸或资源位置反问给用户。模糊目标从用户任务与受阻位置开始，成熟方案继承历史决定，局部修改只检查受影响范围。

每轮选择当前最影响方向的一项不确定性：简述已知依据，问一个问题，给出推荐及理由。选项体现真实取舍；用户回答后记录实际选择及影响，不把沉默、模糊回复或 Agent 建议当作批准。按钮、图标等已委托细节在当前生成项内处理，页面与状态的门禁仍按 [逐项约定](handoff.md#交互与视觉的逐项门禁) 执行。

| 当前步骤 | 访谈重点 |
| --- | --- |
| 流程与关键草图 | 用户、任务、入口/结果、范围、参与端与主分支关系；展示讨论稿并确认交互方向，再放行第一张主流程页面 |
| 主流程当前页 | 本页操作、跳转、返回与最小反馈；展示本页，合并验收与下一页计划确认 |
| 主流程串联 | 各页通过后走查整条正常路径，确认后才开始分支和完整状态 |
| 分支或单页状态 | 分支内部逐页、状态逐种确认；明确触发、恢复/退出及与主流程的连接 |

可以在获准范围用文字线框、流程图与关键草图辅助取舍；草图确认前不制作主流程页面。每次展示当前稿和一个具体的下一项计划后，问是否认可当前结果并按计划继续，然后停下等待。用户只要求修改时只改当前项，不顺带做下一页；没有下一项计划的认可不自动授权后续生成。

对话中维护已核实事实、已确认决定、明确委托及未决事项。到实际确认和交付检查点，将恢复必需的部分写入 [交接记录](handoff.md)，不要求本地 brief、run.json 或完整访谈日志。新任务从记录和真实产物恢复；只对缺失、冲突或新事实影响的决定补问。

目标与边界足以支撑当前项且该项已获放行时，停止扩展访谈并制作本项；检查通过后仍等待用户验收。交互稿完成后结束本阶段，不延伸到视觉方向访谈。
