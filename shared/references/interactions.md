# 页面导航与交互说明协议

本协议定义页面状态、说明与稳定目标的关联。每个需求独立维护 `interactions/*.md`，可按页面或流程拆文件；正文和关联信息都在文档中，组件只提供真实交互、路由适配和稳定定位。`requirement.md` 保存目标、范围、基线和验收；`scenarios.json` 只提供体验初始数据。

## 何时需要打点

在本次获准的交互设计范围内，关键行为、约束或结果无法仅凭画面和控件文案完整判断时，必须主动新增或更新交互说明打点，并与实现同步交付。重点检查：

- 前置条件、权限、业务校验、禁用原因及不同条件下的处理分支。
- 多步骤或跨页流程、导航去向、上下文传递、输入保留和离开保护。
- 异步处理中的反馈、重复提交限制、成功结果、失败恢复与重试。
- 危险或不可逆操作的确认、取消、撤回边界及数据保留或丢弃规则。
- 无法从画面直接看出的键盘、焦点、拖拽等操作规则。

先检查已有条目；准确覆盖时复用，行为变化时同步更新，缺失时补齐。纯视觉调整或自明的普通操作不要求增加打点，不以打点数量判断覆盖是否充分。

## 内容规范

每条说明聚焦一个明确行为或紧密关联的流程，采用“短标题＋按需选择的维度”。新说明优先显式使用 `view: dimensions`，通常组合 1～3 个维度，每个维度以一句话为主；不强制摘要，不补空维度，不要求写满全部维度。复杂内容可以增加必要维度，不设置机械的字数或数量上限。

### 五种维度模板

| 三级标题 | 内容句式与精简示例 | 统一展示 |
| --- | --- | --- |
| 操作 | 触发动作 → 行为与结果；如“点击确认后保存并关闭弹窗” | 简短说明行 |
| 条件 | 条件 → 允许或限制；如“未选择对象时禁止提交” | 条件与结果对照，可按需列出多条规则 |
| 状态 | 当前状态 → 反馈与可操作项；如“处理中禁止重复提交，成功后显示结果” | 紧凑状态列表 |
| 异常 | 问题 → 数据处理与恢复；如“失败保留输入，可重试” | 异常与恢复提示 |
| 流程 | 第一步 → 第二步 → 完成；如“选择文件 → 校验 → 确认导入” | 有序步骤 |

同一条说明可任意组合这些维度，按正文顺序展示；不要求包含“操作”或遵循固定顺序。`dimensions` 模式的三级标题必须使用表中的名称，每种最多出现一次且内容非空；同维度的多个条件或状态合并为短列表或表格。流程优先使用 Markdown 有序列表，每项一句话。已有 `card`、`steps`、`rules`、`states` 文档继续沿用原有结构与展示，不自动转换。

### 精炼与完整性

- 只补充画面和文案无法直接表达的规则，省略可从打点位置判断的页面、对象与入口，不复述控件名称或常规点击过程。
- 每句话提供新的有效信息；标题、可选导语和各维度之间不重复，同一公共规则只说明一次。简单行为用一句话，分支才用短列表或表格。
- 写作时检查触发、结果、分支、数据处理、恢复与边界是否充分，这些是检查维度，不要求逐项输出。保留影响操作、数据和风险判断的关键条件，不因精简而遗漏。
- 依据通过 `sources` 关联，详细背景留在需求文档与交接中；本地模拟、未实现或待确认事项影响行为理解时，在相关维度中简明标识，不自行编造规则或写成已实现。

内容应能转成“给定条件 → 执行操作 → 观察结果”的验收步骤，不要求将验收步骤逐项写进打点。避免只写“点击后跳转”“异常时提示”等无法判断结果的句子。

说明绑定最贴近该行为的稳定目标，正文中的适用条件与 `page`、`when` 一致；禁用、错误等必要解释不能因条件筛选而全部不可见。共享条目须适用于所有受影响候选，差异需明确处理。

## 文档格式

每个文件以 YAML 配置开始；正文用二级标题和 `{#稳定ID}` 声明交互条目，三级标题组织维度或原有展示模式的细节。配置与正文一一对应，ID 在整个需求中唯一。文件按相对路径排序，条目按 annotations 顺序排列。

以下示例演示内容粒度，实际规则以当前需求为准。

```markdown
---
schemaVersion: 1
page: catalog
annotations:
  - id: start-task
    target: catalog-list/start
    view: dimensions
    placement: auto
sources:
  - kind: prd
    ref: requirement.md
---

## 开始任务 {#start-task}

### 条件
至少选中一个可用对象后才能使用。

### 操作
点击“使用”后校验，期间禁止重复提交；通过后进入任务页，保留当前租户与选择。

### 异常
对象失效时停留原页并标出，保留选择供修正后重试。
```

| 字段 | 约定 |
| --- | --- |
| schemaVersion | 固定为 1 |
| page | manifest.pages 中的页面 ID；`"*"` 表示各页共有说明 |
| annotations[].id | 需求内唯一的小写字母开头 ID，对应正文二级标题锚点 |
| target | Spec 元素 ID，或 `元素ID/子目标`；组件用 designPart 暴露子目标 |
| view | dimensions（新说明优先）、card（省略时默认）、steps、rules、states |
| placement | auto（默认）、top、right、bottom、left；位置按真实目标边界计算，不写像素坐标 |
| when | 可选，JSON Pointer 到预览状态值的条件；多个字段同时满足，值数组表示任选一个值；缺失字段不等于 null |
| sources | 可选来源数组，kind 为 user、prd、code 或 design，ref 为可读来源；区分已确认决定、现状与设计提案 |

条件仅支持字符串、数字、布尔值、null 及其非空数组，不执行表达式或 JavaScript。YAML 拒绝重复字段、别名、未知字段。目标根元素需在各候选对应页面中存在，子目标在真实预览中检查。

## 展示模式

`dimensions` 按三级标题识别五种维度，在同一打点内使用统一标签、字号、间距和正文布局；异常有独立提示色，状态列表和有序流程按各自内容结构展示。未选维度不生成标题、占位或额外折叠层。可选导语只承载独立信息，默认省略；来源继续收在“依据与文档”中。本地工作台与新导出的离线 HTML 使用相同展示。

已有四种整条说明模式保持兼容：

- card：摘要加可展开的操作与边界，用于独立行为。
- steps：摘要加有序步骤，各三级标题是一项步骤。
- rules：三级标题与内容形成规则表；内容可使用标准 Markdown 表格。
- states：各三级标题是一种状态，内容写反馈、允许操作与恢复方式。

按内容结构选择展示组件；steps 的三级标题应对应实际步骤，rules 对应条件与规则，states 对应不同状态。说明按当前页面与状态筛选。定位目标暂时不可见时保留说明并明确提示。页面内编号跨状态稳定，隐藏条目可以留下编号空位。画面和说明通过稳定 ID 双向定位。

## 页面与状态同步

组件内自定义路由接入固定 SDK：

```tsx
import {usePreviewNavigation,usePreviewState} from "@design-harness/preview";

const requestNavigation = usePreviewNavigation({
  page,
  beforeNavigate: (target, signal) => confirmLeave(target, signal),
  navigate: target => { discardConfirmedDraft(); router.go(target); },
  state: {role, tenant}
});
usePreviewState({phase, connection, material});
// 产品内部的页面入口也使用 requestNavigation(target)。
```

`beforeNavigate` 返回 boolean 或 Promise<boolean>，只询问离开保护，不执行路由、清空草稿或提交业务。无未保存内容时返回 true；用户继续编辑时返回 false。signal 中止时关闭待决提示并保留输入。`navigate` 只在全部参与方案都通过检查后执行，才按原有语义丢弃已确认的草稿并切页。页面实际改变后 hook 上报当前页，说明与标注据此匹配。产品内部入口使用 hook 返回的 requestNavigation，避免绕过协调器；原有把确认和切页混在同一回调中的接入，应拆成这两个阶段。

多个 `usePreviewState` 发布的字段应各有归属，避免相互覆盖。状态字段只承载当前可观察行为，不包含说明正文。无离开保护时可省略 beforeNavigate；navigate 仍负责实际路由。

使用 json-render store 管理路由的简单页面也可在 manifest 声明 `navigation: {pageStatePath: "/route"}`，工作台协调该路径上的页面写入，经过导航检查后再提交；非路由字段仍保留在本方案。有自定义路由适配时优先使用适配器；存在离开保护必须接入适配器，不能绕过保护直接改路径。无路由适配或路径时，工作台仍能切换页面 Spec，但工作台不能推断组件内部跳转。

普通导航保留 iframe 和 json-render store，不重新注入场景初始数据。共享 React 会话容器保持相同 Spec key 与组件类型；跨页需要保留的数据放在该容器或 store，不放在会卸载的页面组件内。选择预置场景或重置才初始化会话。实际运行状态与初始预置场景分开记录。

## 多候选行为边界

各候选的业务输入、任务、发布状态和设计修改保持独立。导航适配需支持取消与保留草稿，只有全部参与方通过离开保护后才提交导航；beforeNavigate 不提前清理状态。共享 React 根容器与 store 的生命周期由需求组件维护。

## 验证

实际点击跨页并返回，检查导航、说明条件与稳定目标匹配；验证取消离开保留输入、确认后提交导航、跨页数据保留和显式重置。通过真实业务动作改变加载、错误、权限与弹层状态，区分实际可到达路径和仅预置的初始状态。共享变更核对所有候选，验证材料与结论遵循交付保真。
