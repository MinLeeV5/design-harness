# 完整 UI 与交付保真

## 交付目标与依据

设计工程独立、代码仅供研发参考，描述的是复用和集成边界，不代表可以简化设计质量。完整 UI 交付按最高保真要求覆盖声明范围内的画面、组件、交互与状态；局部稿和流程示例应明确范围，不作为完整 UI 交付。

已有系统先取得任务指定版本的实际运行画面、当前实现、组件与资产依据，再建立设计基线。记录环境、版本或提交、路由、身份／权限／上下文、内容、实际视口和触发步骤。代码证明所读版本的实现，运行画面证明对应环境的实际呈现；本地 Mock 不等于现网生产。取得不到对应环境时，保留未核实项，缩小一致性结论。

在 requirement.md 中按区域记录下表，handoff.md 承接实际结果，UI 结构使用原生 json-render Spec，保真证据沿用 Markdown，不另造平行的 UI 树：

| 区域／状态 | 交付责任 | 依据、版本与环境 | 设计位置 | 对照结果与证据 |
| --- | --- | --- | --- | --- |
| 按本次范围填写 | 沿用／本次变更／新增／已确认排除 | 来源与适用边界 | 页面、场景或组件 | 已核对／有差异／未验证，附实际证据 |

沿用区域保留当前正确的结构和行为；变更与新增区域按已确认目标设计，单独记录与当前产品的差异。不把代码中的偶然错误当设计要求，不用旧画稿、模板默认值或自行推演覆盖已确认依据。冲突会改变关键行为或范围时，只对冲突部分重新对齐。

## 完整性边界

先追踪页面的上层布局与共享组件，再建立页面和状态清单。整页交付包括可见的产品壳层与其适用状态；沿用的部分也要核对，不能只完成业务主体。

检查头部与品牌、上下文切换、主／辅助导航、账号菜单、分组分割线、激活态、页面容器、分页与底栏、固定输入区、滚动区域、浮层和响应式变化。以目标产品实际存在的内容为准，不为通用清单增加产品没有的功能。

保留控件真实的触发方式、菜单层级、选中／禁用／忙碌／错误、外点关闭、键盘、焦点、未保存保护与恢复。未纳入本需求的其他模块可以使用明确的本地导航占位，但保留已有入口的外观与语义，不将可点击导航降成无语义装饰。

以 Catalog／Registry 注册的自定义 React 组件和完整 Spec 独立重建需要的组件与行为，不导入业务工程的运行模块。允许使用合成内容和本地后端模拟，但不能用单段定时反馈替代声明要交付的完整界面与交互。

模拟身份、评审入口和保真缺口优先放在工作台、说明或交接中；不额外插入产品头部、底部或提示条以改变目标构图。产品本来就有的状态提示仍按依据保留。

## 对照与收敛

在相同实际视口、状态、上下文和可比内容下渲染基线及设计产物。按壳层与层级、几何与滚动、字体与换行、边框／分割／圆角／阴影、精确图标与资产、交互和状态的顺序核对。源组件尺寸和计算样式可支持判断；Token 名相同不能证明组件呈现相同。

使用项目实际图标、字体和资源并保留许可；不要用近义图标、字符箭头或自行简化的路径代替已有明确资产。尺寸变化必须用真实视口验证，不能把等比缩小桌面稿当作移动版。

默认态之外，实际操作范围内的菜单、选择器、弹层、加载、空态、禁用、失败、恢复、长内容及必要权限变体。预置一个场景只证明该场景能显示，不证明从真实入口可以到达。视觉候选保持相同内容和行为；未经确认的密度或构图变化仍属于候选，不能冒充当前产品基线。

先修结构、组件和行为缺失，再收敛分割线、像素间距等细节。截图支持审查，不能取代交互；内容或渲染环境不一致时不使用任意像素相似度百分比判定通过。

检查截图与日志临时使用后清理，不要求保留 evidence 目录；必要的对照结论、未核实项和来源版本记入 handoff。

## 完成证据

分别记录：

- 视觉保真：可比的基线与交付截图、实际视口、逐区域差异及其处理结果。
- 交互覆盖：真实触发路径、操作后的可观察结果、键盘与恢复；区分实际体验和仅预置展示。
- 行为真实性：本地设计模拟、源应用 Mock、真实服务与现网各自验证了什么，哪些仍未验证。
- 工程检查：协议、类型、构建和字节清单的实际结果。这些结果不替代以上三项。

完整 UI 声明范围内仍缺失的组件、状态或未核对的沿用区域，要修复或经用户确认缩小交付范围，不能用“设计参考”作为省略理由。未取得现网证据不声称已与现网一致。用户验收保持真实确认，不能由检查数量或 Agent 自检推断。

发现遗漏后更新当前需求和核对记录，按[导出规则](preview-export.md)重新生成单文件 HTML；历史用 Git 显式记录，验收状态记入 handoff.md，候选不自动晋升为公共基础。
