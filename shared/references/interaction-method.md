# 交互设计方法

先读取当前需求目标、已确认范围和相关交接；依据[来源与承接](product-source.md)核对指定业务来源。以用户任务组织入口、主路径、分支、反馈、失败恢复和离开保护；已有决定直接承接，实质分歧逐项对齐。

需求文档维护目标、范围、依据和验收；独立交互文档记录触发、行为、反馈、异常和状态条件。页面 Spec 维护组合与实例属性，React 维护组件内部行为，场景仅提供体验初始数据。修改对应内容前读取[资源协议](protocol.md)或[交互协议](interactions.md)相关章节。

保留范围内产品壳层、菜单层级、焦点、键盘、滚动与状态；本地模拟不构成省略界面或行为的依据。公共组件遵循项目已有基础，更新权限由当前执行入口决定，本方法不扩展权限。

从真实入口验证主路径、必要分支、校验、失败恢复及状态联动，区分可到达路径与预置场景。正文、条件和稳定 DOM 目标保持一致；共享变化核对所有受影响页面与候选。

按[交付保真](fidelity.md)分别报告视觉、交互、行为真实性与工程检查。交接保留确认状态、来源版本、未验证项和后续边界，工程成功不代替用户验收。
