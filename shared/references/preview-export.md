# 预览、编辑与离线交付

命令中的 <插件目录> 为当前 SKILL.md 所在目录向上两级；先确认该目录下有 shared/ 与 workbench/cli.mjs。所有阶段使用同一入口，不需发布或全局安装 npm 包。

需要完整插件及锁定依赖（Node.js 22+）。以下命令直接调用插件公共 CLI，项目不维护工具源码或安装路径。

```sh
node <插件目录>/workbench/cli.mjs init --project <项目目录>
node <插件目录>/workbench/cli.mjs organization --project <项目目录>
node <插件目录>/workbench/cli.mjs new <需求ID> --project <项目目录> --title <名称>
node <插件目录>/workbench/cli.mjs serve --project <项目目录> --port 4173
node <插件目录>/workbench/cli.mjs check --project <项目目录> [需求ID]
node <插件目录>/workbench/cli.mjs typecheck --project <项目目录>
```

init --example 创建局部合成示例，不代表真实产品完整稿。已有 design-harness/ 拒绝覆盖；--project 可指向资源目录。额外业务依赖用 deps 安装到项目外缓存。

初始化按[设计组织模式](design-organization.md)协助确认后，以 init --mode continuous --primary <主稿ID> 或 init --mode per-requirement 保存选择；已有工作区使用 organization 加同样参数。无参数 organization 只读配置，缺失模式不自动猜测。持续模式的 new 可省略 ID 来建立主稿，后续直接更新已有主稿；用户明确要求独立设计时用 new <ID> --separate，基础验证用 new <ID> --preview。两种参数不并用，基础预览不作为主稿。

## 预览、标注与点选

预览是主体，左右抽屉默认收起。顶部将“页面名 / 场景名”紧接在需求标题右侧，点击名称可切换，随实际页面和状态更新；正常导航保留输入，选择预设场景才重新初始化。左侧设置收纳需求、方案和视口；顶部右侧的说明、机器人图标 Agent 与工具入口分别打开对应面板，再点收起。工具面板提供标注、重置、对比和导出。窄屏时页面与场景另起一行，右侧入口只显示图标。桌面和手机均使用覆盖式抽屉，并避让完整 Header。开关不改变实际 iframe 分辨率、缩放、位置或输入，关闭保留草稿，Esc 恢复对应入口焦点。实际 iframe 尺寸决定响应式，缩放只用于摆放。

标题旁的状态图标表示本地草稿、离线预览或尚未写入的提案。悬停、键盘聚焦或触屏点击可查看名称与具体能力；Esc 先关闭说明。离线图标表示导出的独立 HTML；默认提案图标的说明明确源文件尚未更新；完全访问的提案提示源文件可能已被修改。

交互说明从需求独立的 interactions/*.md 读取，按当前页面和实际运行状态显示①②编号及对应卡片、步骤、规则表或状态对照；点击画面编号打开相应说明，点击说明定位画面。编号随当前渲染、滚动和弹层更新，不改变产品布局。普通模式直接操作 UI；点选模式先截获点击，定位具体 DOM、父层级、样式和重复实例，不执行原按钮动作；选中一个元素立即退出点选并恢复业务操作，只在 Agent 输入区保留点选入口。点选时暂隐右侧抽屉，选中或取消后返回，保留附件和层级。过长点选标签单行省略，悬停可查看全文。复杂组件可通过 designPart 暴露稳定的说明子目标。

页面同步接入 usePreviewNavigation 或 manifest.navigation，工作台切页沿用真实导航和离开保护，实际跳转后同步。选择场景和重置才重新初始化；编写格式与状态保留约定见[交互说明协议](interactions.md)。

## 设计方案探索

在输入区底部选择 1／2／3／4 个方案，默认 1，交互和视觉身份均可使用。多方案使用提案工作区权限；发送任务后先与主 Agent 讨论目标、保留内容、差异和本轮范围，点击“确认生成 N 个方案”才启动并行生成。范围按任务讨论，可跨多页，各方案可以使用不同页面数量与流程。普通单方案对话和局部修改沿用原方式。

主画布根据方案数量与可用空间自适应平铺：1 个铺满，2～3 个选择合适的横排、竖排或分区，4 个采用 2×2 四宫格。各方案保持原始设计分辨率，等比缩放显示。Agent 抽屉浮动覆盖在画布上，不占布局空间，开关不改变方案排列、缩放或输入。放大单个方案后可返回总览，页面与场景分别体验；顶部页面、场景、说明和标注跟随聚焦方案。失败方向可单独重试。选择只决定当前基线，不写正式资源。

直接说“采用 A 的 X、B 的 Y”即可要求融合，也可开启点选，在不同方案中逐个选择元素，准确版本、页面、目标及当时状态与画面会加入同一草稿。加入和移除引用不会发送消息，原文字保留。融合新增 D 并保留 A/B/C；继续细化 D 增加版本，即使底部仍选 3，也只修改一次 D。

“基于当前方案再探索”默认承接当前版本及未接受的调节，底部数量决定下一轮的输出数。讨论并确认后生成 D-A／D-B／D-C 等子方案；也可先选择其他基线或数量。未接受方案可切换设计身份继续，每轮使用一种身份。

方案历史按轮次保存结果、版本、来源和设计结论，刷新与服务重启后可以打开、比较、引用与继续。执行会话可以重建；公共基础始终引用项目当前唯一版本，恢复不兼容时报告原因并保留源。只有点击“接受修改”才写回所选结果；共享影响与文件差异需检查，源冲突拒绝覆盖。结束本轮保留历史，显式删除需再次确认且不删除已接受的正式设计或其他轮次。


## 专业设计 Agent

本页面向使用者与外部阶段说明宿主工具的操作方式，不属于业务产品的界面或设计要求；内部身份的默认资料地图不包含本手册。

会话列表可在同一候选下新建、切换独立会话，多会话可同时处理；当前只接入 Codex。切页、关闭面板和刷新不取消后台任务，取消只作用于当前会话。后台结果不抢占画布，所选会话的提案只在对应页面显示。接受仍检查完整资源版本，冲突由用户协调，不自动合并；细节及服务生命周期见[专业 Agent 协议](agent.md)。

首次默认交互设计，之后恢复本机偏好；在同一聊天中可切换交互设计或视觉设计身份，按独立内部身份及按需读取的公共专业方法展开讨论与修改；身份切换承接同一会话已确认的上下文，消息保留实际身份。具体能力与边界见[专业 Agent 协议](agent.md)。可以直接讨论页面，也可点选元素作为可移除附件。每轮由当前产品 DOM 静态快照生成截图，运行状态与点选详情保存为临时资料；入口地图提供本轮路径，Agent 按需读取，视觉判断前查看实际截图。可附加最多3张 PNG/JPEG/WebP 参考图，每张最大3MB，参考图保留至主动移除或页面重载。截图通过路径按需查看，用户参考图作为直接附图；临时文件用后清理。纯问题可以只回答，不要求每条消息都生成修改。明确提出视觉要求后才生成局部预览，并按需要给出0–4项有效控件；默认和仅点选时不展示预设参数表。控件对应已实现的设计维度，调节先作用于临时预览，可继续细化，接受后才写回。

工作台的页面、场景、方案、视口及 Agent 设置复用统一选择组件，模型入口通过四个 Tab 组织内嵌选项；模型和长列表支持搜索，禁用项附原因。方向键移动高亮，点击或 Enter 确认，Esc 先关闭下拉，现有页面联动与选择记忆保持。

Agent 标题下拉切换会话，紧邻的＋图标新建会话；Codex Provider 图标位于关闭按钮左侧，点击展开不占据聊天空间的连接气泡，已有会话时 sessionId 单行保留头尾，悬停查看全文并复制完整值。输入框底部用单行工具栏点选元素、添加参考图、打开依次显示当前身份图标与模型名的模型设置并发送／停止。交互设计用流程节点、视觉设计用调色盘，身份选项与入口同步，窄屏只省略模型名。模型入口合并模型、推理强度、权限和设计身份四个 Tab，选择立即生效并保持面板打开；切换 Tab 只切换页面。模型按钮按名称自然宽度伸缩，空间不足时省略，悬停查看完整配置；模型图片能力以小图标提供悬停详情。完全访问在入口保留醒目标记，详细风险说明仅在权限 Tab 展示。模型默认跟随本机配置；列表由本机运行器发现，明确不支持图片输入的选项不可选。切换模型只影响下一轮并保留会话，生成期间锁定设置；思考深度仅展示当前模型支持的档位，默认自动；每轮消息记录实际模型及深度。身份、模型及各模型深度选完即保存本机偏好，刷新／服务重启后恢复，新会话继承最近偏好，已有会话保留自身设置。失效深度自动回退并提示，保存失败可重试；不保存聊天或凭据。连接气泡默认显示认证、当前模型和最近请求，四格用量只保留最近输入／输出、本轮文本及会话累计。缓存、窗口、压缩及资料目录收进“更多信息”；长名称省略，ID／路径保留头尾并可复制完整值，计数缩写可悬停看精确值。默认正常面板约300px，展开后最高440px并在内容区滚动；缺失值保持未知，累计总量不作为上下文占用率。支持刷新，读取状态不发起推理、不读取或修改凭据。只有点击发送时调用本机已登录 Codex，使用本轮选定模型。当前所选会话展示完整用户消息、Agent 回复及每轮实际处理活动：请求、可公开的 Agent 进展、工具状态、构建、浏览器校验和接受结果。等待显示 loading、实际耗时和取消入口；完成、失败和取消均留在本轮记录中。只展示真实事件，不编造进度或思考内容，展示 Provider 提供的公开推理摘要、命令、目录、退出码与可折叠输出，不展示原始内部推理或最终包含源码的结构化结果。完整源码仍通过明确的修改文件查看入口评审。

权限有只读分析、提案工作区（默认）和完全访问三档，按会话选择、每轮记录，不保存为全局偏好。完全访问可能在接受提案前修改源文件，取消或放弃不会撤销这些修改。命令、文件与权限扩展的原生审批显示在对应轮次，批准本次、拒绝或取消不会影响其他会话；浏览器刷新可恢复待审批状态。详细边界见[专业 Agent 协议](agent.md)。

消息区独立滚动；停留底部时跟随新输出，上翻阅读后暂停跟随，右下角显示“回到最新”。点击或键盘激活该按钮会置底、将焦点交回消息区并恢复跟随。切换会话从其最新消息开始，空会话不保留上一会话的置底按钮。

当前候选内任一会话待审批时，顶部 Agent 入口展示待审批标记，替代生成中的旋转图标，收起面板仍可发现。面板在输入区上方固定显示“等待你审批”和当前请求数；若请求位于其他会话，则显示待确认的会话数。点击“查看审批”会定位并聚焦当前会话第一项未决卡片，或切换到待审批会话后定位；会话列表同时保留“等待你审批”状态。处理或撤销请求后按剩余数量更新，全部结束后清除提示，实际审批仍在卡片中明确选择。

会话按需求和候选隔离，仅保存在服务内存，服务重启清空，不向项目写聊天或模型日志。工作台展示完整当前会话，模型使用当前会话的原生 thread 历史与本轮权威设计资源。切换面板或关闭抽屉保留聊天草稿、预览和调节值；切换页面／场景／候选不取消任务或丢弃预览。接受后局部刷新资源并保留其他会话，浏览器刷新可从同一服务恢复消息与任务。

有实际进展会刷新10分钟的无进展超时计时；等待审批期间一直保留任务，最后一项审批结束后重新计时。等待时仍可显式取消；切页、刷新或关闭面板不代替审批，也不会因等待时长自动批准或取消。

继续修改承接当前暂存代码和调节值。生成结果在系统临时资源中检查协议、类型、构建和隔离浏览器场景，再提供预览。调整项绑定当前页面 Spec 字面量属性或候选 params 中已实际引用的数值样式变量。视觉身份维护当前候选及交接；交互身份还可修改当前需求的说明、场景和页面登记，提案展示受影响候选，并验证所有受影响方案。新增页面只向其他候选补齐新页面 Spec，已有实现保持独立。完整提案预览可查看所有页面、说明和场景，文件评审显示修改前后。点击“接受修改”统一写入本次提案；源文件变化拒绝覆盖并保留预览。细化失败或取消本轮时恢复上一版预览和调节值；普通单提案显式放弃或关闭服务清理临时修改，未处理预览30分钟后过期；多方案的设计结果随历史长期保存。共享基础及其他候选的既有实现由外部 Agent 按授权单独维护。普通单提案须先接受或放弃再切换专业身份；已保存的多方案支持直接跨身份继续。

点选复用固定提交的 Impeccable DOM 辅助模块，视觉调整参考其按需生成方式；插件按 json-render 协议适配会话和写回，并非整体复制上游 Live 服务。离线 HTML 提供体验、说明和点选，不运行 Agent 生成或本地写回。

## 候选与公共基础

```sh
node <插件目录>/workbench/cli.mjs clone <需求ID> <原候选> <新候选> --project <项目目录> --title <名称>
```

clone 复制完整 Spec、参数与专属实现，两候选的运行状态独立。所有需求引用项目唯一 foundation；公共更新保持向下兼容并检查既有页面，不复制需求基础或建立升级草稿。

## 按需导出单文件 HTML

工作台“导出离线 HTML”直接触发下载，无需版本号。需要先接受、放弃或取消当前 Agent 提案；导出不影响产品体验输入，也不写项目文件。

命令行明确指定资源目录之外的 .html 文件：

```sh
node <插件目录>/workbench/cli.mjs export <需求ID> --project <项目目录> --out <资源目录之外的文件.html>
```

export 使用当前 requirements、公共 foundation 与当前插件生成一个 HTML，内嵌工作台、候选、样式、资源、说明与许可，可从 file:// 离线体验。CLI 重新导出可以替换选定文件，构建失败保留原输出；目标不能位于 design-harness 资源目录内，不能是目录或软链接。

持续模式可省略 export 的 ID，读取配置中的主稿，后续通过相同 --out 更新同一 HTML；浏览器默认下载名由设计 ID 稳定生成。按需求模式指定各自 ID，显式打开独立例外时导出当前独立设计，不自动合入主稿。

requirements 是唯一维护来源；项目不创建 releases、sources 副本、运行器或 release.json。重新生成统一使用 export，无独立 verify/rebuild 或版本归档流程。历史用 Git 显式记录，验收状态记在需求 handoff.md，下载和导出不自动登记已验收。

验证实际下载的 HTML 在断网环境下的交互与资源。截图和日志临时使用后清理，不保留 evidence/；必要结论与未决项记入 handoff.md。工程成功、离线可用、完整 UI 保真与用户验收分别报告；见[保真要求](fidelity.md)。
