# 业务 PRD 与设计承接

用户指定的正式业务 PRD 是业务结论的维护位置；例如用户选择飞书时，以该飞书文档维护业务 PRD。没有外部正式文档时，既有本地需求仍可独立使用。区分文档当前内容与实际已确认的决定，草稿或较新的修订不自动等于评审通过。

产品讨论或非界面需求不需要创建设计工作区。用户另行开展设计时，按现有工作区协议建立或使用完整需求，在 requirement.md 中保留设计所需的已确认摘要、正式 PRD 链接、已读取的版本／修订信息或核对时间，以及尚待决定且影响设计的问题；不要复制维护另一份完整业务 PRD。离线 HTML 继续读取本地设计资源，不依赖联网；外链内容不自动嵌入或同步。

后续设计或交接时，若环境具备访问能力，重新核对指定来源及其可得版本，与本地摘要比较；发现变化或冲突时保留已有内容，说明差异及对设计的影响，关键业务变化由用户决定后再更新。来源不可访问、没有版本或无法比较时，记录核对限制，不宣称本地内容为最新或已通过评审。只在取得实际资料或用户确认后记录对应状态。

requirements/ 仍是本地设计产物的唯一维护来源；这一约定不改变用户指定的业务 PRD 所在位置，也不要求迁移原有无外链的需求。正式文档的编辑遵守其工具能力和用户已有授权，优先局部修改并检查读回结果。
