# 验证范围

2026-09-17 重构验证：8 项分发测试、13 项读取助手测试通过，Codex 官方插件及两个 Skill 的格式检查通过。另通过真实 Figma 连接器完成 Page 枚举、目标 Page 顶层目录与一个历史入口的有界读取（7 个节点、375 个文本字符）；仅做只读检查，没有迁移项目内容。

这次真实连接器检查覆盖读取 API，不代表完整 Init、原生资产生成、Design 多方案或用户选择后的回写已在真实项目执行。

## 可重复运行的自动检查

```sh
python3 scripts/validate.py
python3 -m unittest discover -s tests -v
node --test tests/figma-reader.test.js
```

Python 3.10+ 和 Node.js 18+ 即可运行，无第三方包、凭据或联网需求。它们是开发与分发检查；使用 Skill 本身不要求运行本地 CLI。

- 结构检查：两个 Skill、相对引用、工作流资源、分发目录与第三方许可哈希。
- 分发测试：源目录/版本缓存布局、解压到含空格的新路径、marketplace 相对路径、校验和、重复构建、拒绝覆盖、排除临时数据、拒绝外部软链接。
- Figma 读取测试：只枚举 Page、不扫描无关页面/组件库、歧义候选、精确节点定位、跨页与陈旧引用拒绝、分页、共享读取预算、深度上限、长文本续读、隐藏内容和非执行性文本处理。

Figma 测试使用最小 Plugin API 模型，不连接真实文件。测试不会模拟用户批准，也不以文案命中率、打勾记录或置信度证明工作流有效。

## 工作流审阅情境

维护者应沿实际入口和引用检查以下情境。此表是审阅/试运行用例，不宣称已在真实项目完整执行：

| 情境 | 应观察的行为 |
| --- | --- |
| 新项目中代码比 Figma 新 | 先整理现状和差异，每模块展示具体提案；确认后才写入；阶段二补真实资产 |
| 已有 Harness 且某新设计尚未实现 | 保留当前实现与已确认待实现，按目标范围选依据，不用旧代码倒退覆盖 |
| 成熟需求带历史决策 | 先读相关入口/资源，继承决策，只问关键缺口；整体确认后才正式出稿 |
| 模糊目标 | 先探索用户任务，一轮一个问题，可临时草图，不写 brief 文件 |
| 用户选 B | 展示受影响模块的具体知识增量，确认后回写；已有同范围明确批准则继续 |
| 只读连接器/缺写入能力 | 继续调查与访谈，明确未生成资产，不能冒充已完成 |
| 中断后恢复或写入超时 | 回读真实结果，依据稳定 ID 补缺，避免重复建库 |
| 同名 Harness 多个、索引丢失、读取截断 | 澄清目标或定向续读，不盲选、不整文件扫描、不把部分内容当完整 |

## 真实 Figma 验证仍需什么

在具体项目已授权范围内运行一次 Init 和一次 Design；按模块落实用户确认、原生变量/组件与状态补齐、实际截图检查、多个方案及选定后的确认回写。逐项观察 [评价标准](../evaluation/checks.md)。

仅安装或重构本通用插件不包含修改某个项目 Figma 的授权。打包验证也不能代替团队真实试用；发现具体失败再修相应规则或助手，避免预设无限门禁。
