# 验证范围

自动检查验证插件结构、本地资源独立性和读取助手行为。真实项目的 Init、原生资产生成、Design 多方案及用户选择后的回写，需要在具体项目中验证；文件检查和模拟 API 测试不能代替设计验收。

## 可重复运行的自动检查

```sh
npm ci
npm run check
```

统一使用 Node.js 22+、ESM 与 npm。`npm run check` 依次执行 `npm run validate` 和 `npm test`，测试全部由内置 `node:test` 运行。`npm ci` 安装锁文件记录的 ZIP 开发依赖 `fflate`；安装完成后校验、测试和打包均无需凭据或联网。使用 Skill 本身不要求运行本地 CLI 或安装开发依赖。实际任务需要获取外部最新指导时使用联网读取工具，离线测试不验证上游可达性。

- 结构检查：两个 Skill 各自的运行资源、内部相对引用、分发目录、marketplace 目标与策略、发布版本一致性、随附的第三方许可与声明，以及两份读取助手/资源蓝图/原创许可证的一致性。不固定上游版本或许可文件哈希。
- Skill 独立性：仅复制一个 Skill 到新目录后验证全部本地引用；阻止引用插件根目录或另一个 Skill 的文件，并检查孤立的参考文档。
- 分发测试：源目录/版本缓存布局、解压到含空格的新路径后运行 Node 校验命令、marketplace 相对路径、校验和、跨时区重复构建、拒绝覆盖、中文路径与二进制资源、排除依赖和临时数据、拒绝外部软链接。
- Figma 读取测试：只枚举 Page、不扫描无关页面/组件库、歧义候选、精确节点定位、跨页与陈旧引用拒绝、分页、共享读取预算、深度上限、长文本续读、隐藏内容和非执行性文本处理。

Figma 测试使用最小 Plugin API 模型，不连接真实文件。测试不会模拟用户批准，也不以文案命中率、打勾记录或置信度证明工作流有效。

维护外部来源时另行联网确认默认分支中的目标文档可读，并核对最新许可和声明。单次读取成功只证明当时可达；每次使用仍按 Skill 的来源说明按需读取。

## 工作流审阅情境

维护者应沿实际入口和引用检查以下情境。此表是审阅/试运行用例，不宣称已在真实项目完整执行：

| 情境 | 应观察的行为 |
| --- | --- |
| 新项目中代码比 Figma 新 | 先整理现状和差异，每模块展示具体提案；确认后才写入；阶段二补真实资产 |
| 已有 Harness 且某新设计尚未实现 | 保留当前实现与已确认待实现，按目标范围选依据，不用旧代码倒退覆盖 |
| 成熟需求带历史决策 | 先读相关入口/资源，继承决策，只问关键缺口；整体确认后才正式出稿 |
| 模糊目标 | 先探索用户任务，一轮一个问题，可临时草图，不写 brief 文件 |
| 用户选 B | 展示受影响模块的具体知识增量，确认后回写；已有同范围明确批准则继续 |
| 只读连接器/缺写入能力 | 继续调查与访谈，明确未生成资产，不能冒充已完成 |
| Console 工具已注册但 Bridge 未连接 | 报告连接状态，检查其他可用连接器；不执行 Console 写入，也不以此阻断代码调查 |
| Console 与 use_figma 都可用 | 按具体操作及目标范围选择；变量批量操作用适用专用工具，原生 Page 编排用执行工具，不重复写入 |
| Console 连接了多个文件 | 核对用户 URL 与连接列表；使用活动文件的工具先定位目标，不把 figma_execute 的 fileKey 当成全局切换 |
| 组件生成成功但截图来自旧缓存 | 回读本次节点并取得同文件的运行时截图；缺少新鲜证据时标明未核验 |
| 当前工具缺少目标能力或支持的平台不同 | 只对当前操作选择可用替代方案；原生代码盘点不套用仅支持 Web 的提取器 |
| 中断后恢复或写入超时 | 回读真实结果，依据稳定 ID 补缺，避免重复建库 |
| 同名 Harness 多个、索引丢失、读取截断 | 澄清目标或定向续读，不盲选、不整文件扫描、不把部分内容当完整 |

## 真实 Figma 验证仍需什么

在具体项目已授权范围内运行一次 Init 和一次 Design；按模块落实用户确认、原生变量/组件与状态补齐、实际截图检查、多个方案及选定后的确认回写。分别依据 [Init 检查](../skills/design-harness-init/references/evaluation.md) 和 [Design 检查](../skills/design-harness-design/references/evaluation.md)。

仅安装或重构本通用插件不包含修改某个项目 Figma 的授权。打包验证也不能代替团队真实试用；发现具体失败再修相应规则或助手，避免预设无限门禁。

连接器适配还需区分三层证据：工具及参数已经发现、目标文件的只读调用成功、经授权的写入与截图验证成功。连接探测失败不影响本地资源校验，但不能据此宣称已验证 Console 的实际读写兼容性。
