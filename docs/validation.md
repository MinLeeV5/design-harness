# 验证范围

自动检查验证插件结构、本地资源独立性和读取助手行为。真实项目的 Library 复用、主流程/分支原型、视觉资产生成与最终确认后的回写，需要在具体项目中验证；文件检查和模拟 API 测试不能代替设计验收。

## 可重复运行的自动检查

```sh
npm ci
npm run check
```

统一使用 Node.js 22+、ESM 与 npm。`npm run check` 依次执行 `npm run validate` 和 `npm test`，测试全部由内置 `node:test` 运行。`npm ci` 安装锁文件记录的 ZIP 开发依赖 `fflate`；安装完成后校验、测试和打包均无需凭据或联网。使用 Skill 本身不要求运行本地 CLI 或安装开发依赖。实际任务需要获取外部最新指导时使用联网读取工具，离线测试不验证上游可达性。

- 结构检查：两个 Skill 的运行资源、内部相对引用、分发目录、marketplace、版本、品牌资源及第三方许可完整；两份读取助手、资源说明、视觉资产选择/图标/插画方法及来源声明与许可、Library 来源蓝图、工作模板、设计描述及其许可/原创许可证一致。不固定上游版本或许可哈希。
- Skill 独立性：仅复制一个 Skill 到新目录后验证全部本地引用；阻止引用插件根目录或另一个 Skill 的文件，并检查孤立的参考文档。
- 文档蓝图：检查文本角色引用的字号配置存在、阅读布局参数有效，以及两份蓝图一致；只验证构建数据的完整性，不判定默认字号、行距或配色的审美质量。
- 新流程资源：原型指引与蓝图、视觉资产选择与图标/插画方法、Library 引用、视觉指导来源与 Lucide 许可、UI/UX Pro Max 路由与许可必须可达、非空并随 ZIP 保持字节一致；只检查资源完整性，不通过匹配文案模拟阶段批准或质量验收。
- 分发测试：源目录/版本缓存布局、解压到含空格的新路径后运行 Node 校验命令、marketplace 相对路径、校验和、跨时区重复构建、拒绝覆盖、中文路径与二进制资源、图标/浅深 Logo 的资源字节一致、缺失或不可移植品牌资源拒绝、排除依赖和临时数据、拒绝外部软链接。
- Figma 读取测试：只枚举 Page、不扫描无关页面/组件库、歧义候选、精确节点定位、跨页与陈旧引用拒绝、分页、共享读取预算、深度上限、长文本续读、只有一条仓库链接的富文本入口与旧入口的完整读取、隐藏内容和非执行性文本处理。

Figma 测试使用最小 Plugin API 模型，不连接真实文件。测试不会模拟用户批准，也不以文案命中率、打勾记录或置信度证明工作流有效。

品牌资源的文件检查只验证引用和基本 PNG 头，不代替完整解码或视觉检查。修改图标后打开[品牌预览](brand-preview.html)，确认浅色、深色背景以及 16/24/32/64/128px 显示。主题色是插件展示元数据，页面中的背景配色仅用于预览，不会改写 Codex 应用主题。

维护外部来源时另行联网确认默认分支中的目标文档可读，并核对最新许可和声明。单次读取成功只证明当时可达；每次使用仍按 Skill 的来源说明按需读取。

## 工作流审阅情境

维护者应沿实际入口和引用检查以下情境。此表是审阅/试运行用例，不宣称已在真实项目完整执行：

| 情境 | 应观察的行为 |
| --- | --- |
| 按 Google DESIGN.md 整理项目风格 | 先读默认分支最新规范与理念，适用章节有视觉意图、用途、边界与真实 token/组件依据；Figma 中保留可读资源及状态，既有项目规则优先，不照搬示例风格 |
| 已有 DESIGN.md 与 Figma 或代码冲突 | 按版本、范围和确认状态展示冲突；不因文件名或上游格式变化覆盖已确认设计，不另造重复 token 库 |
| 新成员只有 Harness 链接，需要找到代码 | 入口只提供一条经实际 remote 核实的仓库链接；完整、无凭据，不把本机路径或 SSH 别名当作团队地址；不要求补分支、commit 或拉取命令 |
| 需要核查实现，存在多 remote、相关仓库或本地差异 | Agent 在任务中确认实际来源、相关版本与范围；不在 Figma 建技术附录，不把仓库链接当作已复现历史版本的证明 |
| 旧 Contract 1 只有本地路径，或含大量技术字段 | 仍可只读使用，从工作区/已有上下文核实必要来源；获准精简时保留原节点和设计知识，不补回旧技术字段或擅自迁移 |
| 项目上下文塞满具体页面行为 | 概括产品定位、任务、环境、渠道与业务边界；将区域分配归布局、控件状态归组件、任务分支归场景，上下文仅保留必要索引 |
| 资源卡反复记录路径、类名、commit 和核查日志 | 改为产品行为、设计规则、适用范围和状态；保留设计资产引用，源码调查留在任务中 |
| 实现行为仅从源码核实 | 不声称运行通过；用具体的待实机验证事项说明限制，不逐卡重复技术核查过程 |
| 入口/模块/资源文档同字号平铺 | 在原语义 TEXT 内补标题、段落/列表和链接层级；整体与正文局部截图可读，仓库链接与真实 Figma 定位仍完整可读取 |
| 旧项目有流程模板和原稿风格模板 | 插件承载通用流程，项目配置与原生资产登记到设计风格模块；已填写内容、来源和实际引用在清理前迁移 |
| 用内置蓝图生成跨端场景 | 真实 Auto Layout 与组件可编辑，参与端/步骤不固定；长文、分支、画面比例与原稿来源可核验，文档样式不进入产品 UI 规范 |
| 新项目中代码比 Figma 新 | 先整理现状和差异，每模块展示具体提案；确认后才写入；阶段二补真实资产 |
| 已有 Harness 且某新设计尚未实现 | 保留当前实现与已确认待实现，按目标范围选依据，不用旧代码倒退覆盖 |
| 成熟需求带历史决策 | 先读相关入口/资源，继承决策，只问关键缺口；整体确认后才正式出稿 |
| 模糊目标 | 先探索用户任务，一轮一个问题，可临时草图，不写 brief 文件 |
| 新功能有主流程与多条分支 | 整体需求/骨架确认后先做可点击主流程，确认后逐条展开分支，交互确认后再细化视觉；持续逐题访谈 |
| 纯文案/配色微调 | 说明不影响交互的依据，裁剪无关流程，保留必要可读性与项目一致性检查 |
| 主流程已获确认，又发现分支改变入口前提 | 展示具体冲突，只重开受影响决定与连接，不重做全部访谈 |
| 一个关键交互有分歧 | 只比较对应片段，同一前提与内容，选定后并回；不默认铺 2–3 套完整方案 |
| 用户提供历史确认或明确委托常规细节 | 直接承接，不为每个节点重复审批；主流程确认不自动批准未呈现分支 |
| 只画了静态箭头或只有连接读取结果 | 静态图不能充当可点击原型，连接已配置不能声称已实际点击；提供真实起点并分开报告验证 |
| 原型能力缺失 | 继续流程与讨论稿，说明未完成项；用户选择补足能力或调整交付，不能自动跳过原型阶段 |
| 外部事件只能模拟 | 演示入口明确标识且与产品 UI 分开；原型体验不证明设备、后端、读屏或键盘行为 |
| 视觉细化修改了操作区域或复制了画面 | 回读连接、目标与起点，再走查受影响路径；交互变化重新确认对应决定 |
| 有项目/团队 Library | 先查认可来源和已启用库，按语义/平台/主题筛选，复用实际实例和绑定；不因同名判为适用 |
| Library 无权限、分页未完成或没有目录能力 | 明确未查范围和限制，不宣称团队无资产，不把 libraryKey 当 fileKey，不为探测导入或启用库 |
| 库中缺少合适图形 | 通用图标用一致的成熟矢量，功能关系用可编辑示意图，情境插画按上下文生成并导入；色彩沿用项目 token |
| 只需复用一组现有图标 | 从资产入口按需读图标方法，不加载插画生成步骤；保留真实实例与绑定，不重建整套图标系统 |
| 项目图标参数与社区体系不同 | 采用适用项目家族的实际规格，借鉴视觉重量/光学调整等方法，不把 Lucide 参数强制覆盖项目 |
| 图形能被认出，但操作含义不清 | 检查语境与后果，保留短标签或访谈该分歧；Agent 判断不冒充真实用户理解测试 |
| 需要准确连接或步骤示意 | 使用可编辑图形、连接与原生文字；不把生成位图当作准确可编辑结构，不引入无依据的功能 |
| 需要多张同系列情境插画 | 先明确表达目的、槽位和参考，再制作代表样图、修正并扩展必要系列；既有风格确认不逐图重复审批 |
| 插画显示棋盘格或缩小后细节难辨 | 检查真实 alpha、目标背景、实际槽位裁切与清晰度，修正后再交付；生成成功不等于版面可用 |
| Init 需要登记图标或插画规则 | 只从已有代表资产与实现核实家族/系列和使用边界；不主动生成新方向，不把社区示例写成项目事实 |
| 参考官方设计系统或社区规范 | 按问题读取现行来源，保留适用许可；区分可分发适配、外部阅读和素材复用，不复制未获许可的手册/图形 |
| 图像生成成功但未导入 Figma | 只报告素材生成，不宣称版面交付；继续导入、裁切和真实截图检查，位图类型如实表达 |
| 要求图形表达与少量文案 | 流程/状态/局部对照为主，保留必要标签、后果、规则、仓库链接与可读取定位，不设置删字指标 |
| 新素材来源或风格拟进入 Harness | 展示用途与范围增量，确认后登记；素材使用不自动授权改源库、文件订阅或发布 |
| 使用 UI/UX Pro Max 或 Impeccable | 读取默认分支最新相关指导并核对平台，项目规则优先；不强制重建设计系统、安装或继承上游审计/快照/多 Agent 流程 |
| 最终确认一套主方案或选定局部备选 | 展示具体知识增量后回写；不额外要求多方案选择，不把阶段交互确认当作全局变更授权 |
| 只读连接器/缺写入能力 | 继续调查与访谈，明确未生成资产，不能冒充已完成 |
| Console 工具已注册但 Bridge 未连接 | 报告连接状态，检查其他可用连接器；不执行 Console 写入，也不以此阻断代码调查 |
| Console 与 use_figma 都可用 | 按具体操作及目标范围选择；变量批量操作用适用专用工具，原生 Page 编排用执行工具，不重复写入 |
| Console 连接了多个文件 | 核对用户 URL 与连接列表；使用活动文件的工具先定位目标，不把 figma_execute 的 fileKey 当成全局切换 |
| 组件生成成功但截图来自旧缓存 | 回读本次节点并取得同文件的运行时截图；缺少新鲜证据时标明未核验 |
| 当前工具缺少目标能力或支持的平台不同 | 只对当前操作选择可用替代方案；原生代码盘点不套用仅支持 Web 的提取器 |
| 中断后恢复或写入超时 | 回读真实结果，依据稳定 ID 补缺，避免重复建库 |
| 同名 Harness 多个、索引丢失、读取截断 | 澄清目标或定向续读，不盲选、不整文件扫描、不把部分内容当完整 |

## 真实 Figma 验证仍需什么

在具体项目已授权范围内运行一次 Init 和一次 Design：验证 Library 发现/复用与模块确认，主流程及至少一条适用分支的原型制作、实际点击和逐步确认，必要资产的生成/导入、视觉截图与最终知识增量回写。分别依据 [Init 检查](../skills/design-harness-init/references/evaluation.md) 和 [Design 检查](../skills/design-harness-design/references/evaluation.md)。无相关分支或无需生成插画时如实说明，不为覆盖测试虚构需求。

当前读取助手的模拟 API 测试不执行 reactions 写入、原型预览、图像生成/导入或团队库真实访问。上述能力需要逐项报告真实工具与体验证据；流程文档、蓝图字段、连接回读、截图与用户确认之间不能互相替代。

需要核查实现时，在任务中分别报告实际查到的源码与执行过的运行检查，不把入口链接或静态阅读当作版本复现、运行通过的证明。Figma 只保留影响设计判断的状态与必要限制。文档检查需真实整体/局部截图、正文回读和链接核对；模拟 API 不证明富文本渲染、可读性或真实仓库可达。

仅安装或重构本通用插件不包含修改某个项目 Figma 的授权。打包验证也不能代替团队真实试用；发现具体失败再修相应规则或助手，避免预设无限门禁。

连接器适配还需区分三层证据：工具及参数已经发现、目标文件的只读调用成功、经授权的写入与截图验证成功。连接探测失败不影响本地资源校验，但不能据此宣称已验证 Console 的实际读写兼容性。
