# 验证范围

自动检查验证插件结构、本地资源独立性和读取助手行为。真实项目的逐项生成与人工门禁、Library 复用、主流程/分支/状态原型、视觉方案比较与整合及确认后的回写，需要在具体项目中验证；文件检查和模拟 API 测试不能代替设计验收或证明 Agent 会按时停止。

## 可重复运行的自动检查

```sh
npm ci
npm run check
```

统一使用 Node.js 22+、ESM 与 npm。`npm run check` 依次执行 `npm run validate` 和 `npm test`，测试全部由内置 `node:test` 运行。`npm ci` 安装锁文件记录的 ZIP 开发依赖 `fflate`；安装完成后校验、测试和打包均无需凭据或联网。使用 Skill 本身不要求运行本地 CLI 或安装开发依赖。实际任务需要获取外部最新指导时使用联网读取工具，离线测试不验证上游可达性。

- 结构检查：四个手动入口的运行资源、内部相对引用、分发目录、marketplace、版本、品牌资源及第三方许可完整；读取助手、交接协议/蓝图、连接器、工作模板及各阶段实际共享的方法和许可按使用方分组一致；入口元数据要求显式调用。不固定上游版本或许可哈希。
- Skill 独立性：仅复制一个 Skill 到新目录后验证全部本地引用；阻止引用插件根目录或另一个 Skill 的文件，并检查孤立的参考文档。
- 文档蓝图：检查文本角色引用的字号配置存在、阅读布局参数有效，以及使用方携带的蓝图一致；方案比较的选择理由、融合范围及整合代表稿采用可选槽位，不迫使交互阶段新增流程。只验证构建数据的完整性，不判定默认字号、行距或配色的审美质量。
- 阶段资源：交接协议与蓝图、交互原型、视觉交付、视觉方法与 Library 引用、知识增量，以及各阶段实际使用的第三方路由/许可必须可达、非空并随 ZIP 保持字节一致；只检查资源完整性，不通过匹配文案模拟阶段批准或质量验收。
- 分发测试：源目录/版本缓存布局、解压到含空格的新路径后运行 Node 校验命令、marketplace 相对路径、校验和、跨时区重复构建、拒绝覆盖、中文路径与二进制资源、图标/浅深 Logo 的资源字节一致、缺失或不可移植品牌资源拒绝、排除依赖和临时数据、拒绝外部软链接。
- Figma 读取测试：只枚举 Page、不扫描无关页面/组件库、歧义候选、精确节点定位、跨页与陈旧引用拒绝、分页、共享读取预算、深度上限、长文本续读、只有一条仓库链接的富文本入口与旧入口的完整读取、隐藏内容和非执行性文本处理；仅凭交接容器读取当前阶段记录，不读取其他阶段画面。

Figma 测试使用最小 Plugin API 模型，不连接真实文件。测试不会模拟用户批准，也不以文案命中率、打勾记录或置信度证明工作流有效，也不证明新任务/上下文压缩后的 Agent 行为。

品牌资源的文件检查只验证引用和基本 PNG 头，不代替完整解码或视觉检查。修改图标后打开[品牌预览](brand-preview.html)，确认浅色、深色背景以及 16/24/32/64/128px 显示。主题色是插件展示元数据，页面中的背景配色仅用于预览，不会改写 Codex 应用主题。

维护外部来源时另行联网确认默认分支中的目标文档可读，并核对最新许可和声明。单次读取成功只证明当时可达；每次使用仍按 Skill 的来源说明按需读取。

## 工作流审阅情境

维护者应沿实际入口和引用检查以下情境。此表是审阅/试运行用例，不宣称已在真实项目完整执行：

| 情境 | 应观察的行为 |
| --- | --- |
| 在新任务只提供交接链接 | 显式启动对应 Skill；仅读当前交接、相关上游产物和必要项目约束，承接真实确认，说明恢复位置 |
| 主流程已确认，分支 2 中途发生上下文压缩 | 核对当前页/状态、真实版本、验收与下一项放行；待确认则等待，当前项已放行则只补缺，不重访主流程或进入视觉 |
| 交接标记完成但节点不存在或版本已变 | 按真实产物判断缺口，说明冲突并仅核实受影响决定；不以完成文字推定成功 |
| 流程图与关键草图已生成但用户未确认 | 展示讨论稿与首张主流程页计划后停下；不以流程合理或草图已生成代替用户确认 |
| 用户已批准整项需求，只放行第一张主流程页 | 仅生成该页；必要等待用最小表达，不批量铺主流程、完整状态或组件变体 |
| 当前页跳转目标尚未获准生成 | 标明待补连接，不预建目标 Frame、不用假 ID 或讨论草图充当完成稿；目标页获准生成后补齐 |
| 当前页已展示，同时给出下一页具体计划，用户明确同意 | 一次回复承接当前稿验收并只放行所述下一项，生成并展示该项后再次停下 |
| 用户认可当前稿，但尚未提供下一项计划 | 保留本稿验收，先提出一个下一项具体范围并等待，不推定整个后续流程获准 |
| 用户只要求修改当前稿 | 只修当前项，重新展示并合并询问验收与下一项放行，不同时制作下一页 |
| 主流程各页分别通过，尚未串联确认 | 补齐适用连接并走查整条流程，展示并取得整体验收后才补分支和完整状态 |
| 下一项为当前页失败态 | 只做此页的这一状态，验收后才进入下一项；不能连带制作加载、空态、禁用等其他状态 |
| 本项需要多次 API 调用、截图或制作错误修复 | 在本项授权内完成，不将工具调用另设审批；修复不新增页面/状态或改变已确认交互 |
| 新任务恢复时记录已有下一项明确放行 | 核对真实版本与实际范围后直接完成该项，不因换任务重复索要相同放行；若已生成则展示待验收结果 |
| 新需求进入视觉阶段 | 先逐题确认视觉目标与探索边界，每题有推荐和理由，再制作代表方案，不先铺开全部页面 |
| 本次探索有两个可行方向，第三个只会重复 | 计划两套有差异的候选，逐套逐页放行和制作；齐备后停在比较选择，不为填写下一项计划增加第三套 |
| 候选 A 的代表页已生成，候选 B 未放行 | 展示 A 与 B 的单页计划并停下；A 的制作验收不等于最终选择，也不能为补齐 2–3 套而批量生成 |
| 多页视觉需求 | 只复制当前获准页面，用相同内容、状态、尺寸及交互约束逐项补齐共同代表范围；不先复制全套交互稿 |
| 用户选择 A 的主方向与 B 的局部表达 | 记录主方向、选择理由及融合范围，生成一份一致的整合代表稿并确认该版本，不能把零散偏好当作整合批准 |
| 用户只说“都不错”或所有方案均不满意 | 逐题澄清影响选择的取舍，必要时修订代表方案，不自动选定、混合或完整展开 |
| 约束只允许唯一视觉表达 | 说明具体限制，由用户决定可开放的视觉维度；不突破项目规则或用无关装饰凑方案 |
| 整合稿尚未确认时压缩或换任务恢复 | 从可见交接读当前步骤、方案链接、主方向、理由和融合范围，核对实际稿件后继续确认，不重做已完成探索或直接展开 |
| 整合代表稿已确认，完整页面尚未展示 | 先放行下一张页面，随后仍逐页、逐状态生成和确认；风格通过不放行全套，也不为每个实例重开多方案探索 |
| 视觉阶段认为原型需要新增操作 | 在自己的记录给出问题、影响与建议；由用户决定是否返回交互，其他独立画面另行放行后可继续，不修改上游确认稿 |
| 用户批准返回交互并修订一个分支 | 对应阶段只修批准范围，保留版本关系；下游核对受影响交付，不偷偷采用旧版本继续 |
| 视觉稿已确认，但候选知识增量未批准 | 视觉交付后停止；用户启动回写后展示增量，只写已批准部分 |
| 纯交互规范增量无需视觉修改 | 用户可直接从确认交互启动回写，不要求空跑视觉阶段 |
| 交接记录写入失败或缺权限 | 对话给出必要交接内容和未持久化限制，不伪称已经可以跨任务恢复 |
| 同一任务连续调用多个 Skill | 遵守当前职责但不宣称已清空上下文；建议跨阶段新开任务，不代用户创建 |
| 按 Google DESIGN.md 整理项目风格 | 先读默认分支最新规范与理念，适用章节有视觉意图、用途、边界与真实 token/组件依据；Figma 中保留可读资源及状态，既有项目规则优先，不照搬示例风格 |
| 已有 DESIGN.md 与 Figma 或代码冲突 | 按版本、范围和确认状态展示冲突；不因文件名或上游格式变化覆盖已确认设计，不另造重复 token 库 |
| 新成员只有 Harness 链接，需要找到代码 | 入口只提供一条经实际 remote 核实的仓库链接；完整、无凭据，不把本机路径或 SSH 别名当作团队地址；不要求补分支、commit 或拉取命令 |
| 需要核查实现，存在多 remote、相关仓库或本地差异 | Agent 在任务中确认实际来源、相关版本与范围；不在 Figma 建技术附录，不把仓库链接当作已复现历史版本的证明 |
| 旧 Contract 1 只有本地路径，或含大量技术字段 | 仍可只读使用，从工作区/已有上下文核实必要来源；获准精简时保留原节点和设计知识，不补回旧技术字段或擅自迁移 |
| 项目上下文塞满具体页面行为 | 概括产品定位、任务、环境、渠道与业务边界；将区域分配归布局、控件状态归组件、任务分支归场景，上下文仅保留必要索引 |
| 资源卡反复记录路径、类名、commit 和核查日志 | 改为产品行为、设计规则、适用范围和状态；保留设计资产引用，源码调查留在任务中 |
| 实现行为仅从源码核实 | 不声称运行通过；用具体的待实机验证事项说明限制，不逐卡重复技术核查过程 |
| 入口/模块/资源文档同字号平铺 | 在原语义 TEXT 内补标题、段落/列表和链接层级；整体与正文局部截图可读，仓库链接与真实 Figma 定位仍完整可读取 |
| 旧项目有流程模板和原稿风格模板 | 插件承载通用流程，项目配置与原生资产登记到设计风格模块；已填写内容、来源和实际引用在清理前迁移 |
| 用内置蓝图生成跨端场景 | 真实 Auto Layout 与组件可编辑，参与端/步骤不固定；长文、分支、画面比例与原稿来源可核验，文档样式不进入产品 UI 规范 |
| 新项目中代码比 Figma 新 | 先整理现状和差异，每模块展示具体提案；确认后才写入；阶段二补真实资产 |
| 已有 Harness 且某新设计尚未实现 | 保留当前实现与已确认待实现，按目标范围选依据，不用旧代码倒退覆盖 |
| 成熟需求带历史决策 | 继承有效的流程/页面确认，只问关键缺口；核对本项具体放行后才生成，不将历史决策当作后续全量授权 |
| 模糊目标 | 先探索用户任务，一轮一个问题，可临时草图，不写 brief 文件 |
| 新功能有主流程与多条分支 | 流程与关键草图确认后逐页做主流程，串联确认后分支内部仍逐页、状态逐种推进；交互交付即停止，视觉由用户另行启动 |
| 纯文案/配色微调 | 行为明确时直接进入视觉；精简确认目标，在受影响区域比较 2–3 套代表方案，由用户选择，不因改动小跳过探索 |
| 主流程已获确认，又发现分支改变入口前提 | 展示具体冲突与建议，由用户决定是否重开受影响决定与连接，不重做全部访谈 |
| 一个关键交互有分歧 | 只比较对应片段，同一前提与内容，选定后并回；不默认铺 2–3 套完整方案 |
| 用户提供历史确认或明确委托常规细节 | 承接当前项内的实际范围与有效版本；细节委托不跳过逐页/状态门禁，主流程确认不批准未呈现分支；新视觉需求仍做候选比较 |
| 只画了静态箭头或只有连接读取结果 | 静态图不能充当可点击原型，连接已配置不能声称已实际点击；提供真实起点并分开报告验证 |
| 原型能力缺失 | 继续流程与讨论稿，说明未完成项；用户选择补足能力或调整交付，不能自动跳过原型阶段 |
| 外部事件只能模拟 | 演示入口明确标识且与产品 UI 分开；原型体验不证明设备、后端、读屏或键盘行为 |
| 视觉细化修改了操作区域或复制了画面 | 回读连接、目标与起点，修正保持已确认行为的副本映射并走查；需要改变交互则先报告，由用户决定返回交互阶段 |
| 有项目/团队 Library | 先查认可来源和已启用库，按语义/平台/主题筛选，复用实际实例和绑定；不因同名判为适用 |
| Library 无权限、分页未完成或没有目录能力 | 明确未查范围和限制，不宣称团队无资产，不把 libraryKey 当 fileKey，不为探测导入或启用库 |
| 库中缺少合适图形 | 通用图标用一致的成熟矢量，功能关系用可编辑示意图，情境插画按上下文生成并导入；色彩沿用项目 token |
| 只需复用一组现有图标 | 从资产入口按需读图标方法，不加载插画生成步骤；保留真实实例与绑定，不重建整套图标系统 |
| 项目图标参数与社区体系不同 | 采用适用项目家族的实际规格，借鉴视觉重量/光学调整等方法，不把 Lucide 参数强制覆盖项目 |
| 图形能被认出，但操作含义不清 | 检查语境与后果，保留短标签或访谈该分歧；Agent 判断不冒充真实用户理解测试 |
| 需要准确连接或步骤示意 | 使用可编辑图形、连接与原生文字；不把生成位图当作准确可编辑结构，不引入无依据的功能 |
| 需要多张同系列情境插画 | 承接已确认风格，仅制作当前获准页面/状态所需图形；不为系列扩展提前生成后续页素材，本项内不逐次工具调用重复审批 |
| 插画显示棋盘格或缩小后细节难辨 | 检查真实 alpha、目标背景、实际槽位裁切与清晰度，修正后再交付；生成成功不等于版面可用 |
| Init 需要登记图标或插画规则 | 只从已有代表资产与实现核实家族/系列和使用边界；不主动生成新方向，不把社区示例写成项目事实 |
| 参考官方设计系统或社区规范 | 按问题读取现行来源，保留适用许可；区分可分发适配、外部阅读和素材复用，不复制未获许可的手册/图形 |
| 图像生成成功但未导入 Figma | 只报告素材生成，不宣称版面交付；继续导入、裁切和真实截图检查，位图类型如实表达 |
| 要求图形表达与少量文案 | 流程/状态/局部对照为主，保留必要标签、后果、规则、仓库链接与可读取定位，不设置删字指标 |
| 新素材来源或风格拟进入 Harness | 展示用途与范围增量，确认后登记；素材使用不自动授权改源库、文件订阅或发布 |
| 使用 UI/UX Pro Max 或 Impeccable | 先定位当前问题对应章节，只读默认分支最新的相关段落并核对平台，项目规则优先；不强制重建设计系统、安装或继承上游审计/快照/多 Agent 流程 |
| 完整视觉交付获准 | 本阶段停止，由用户启动回写并批准具体增量；回写阶段不重新要求多方案选择，不把设计确认当作全局变更授权 |
| 只读连接器/缺写入能力 | 继续调查与访谈，明确未生成资产，不能冒充已完成 |
| Console 工具已注册但 Bridge 未连接 | 报告连接状态，检查其他可用连接器；不执行 Console 写入，也不以此阻断代码调查 |
| Console 与 use_figma 都可用 | 按具体操作及目标范围选择；变量批量操作用适用专用工具，原生 Page 编排用执行工具，不重复写入 |
| Console 连接了多个文件 | 核对用户 URL 与连接列表；使用活动文件的工具先定位目标，不把 figma_execute 的 fileKey 当成全局切换 |
| 组件生成成功但截图来自旧缓存 | 回读本次节点并取得同文件的运行时截图；缺少新鲜证据时标明未核验 |
| 当前工具缺少目标能力或支持的平台不同 | 只对当前操作选择可用替代方案；原生代码盘点不套用仅支持 Web 的提取器 |
| 中断后恢复或写入超时 | 回读真实结果，依据稳定 ID 补缺，避免重复建库 |
| 同名 Harness 多个、索引丢失、读取截断 | 澄清目标或定向续读，不盲选、不整文件扫描、不把部分内容当完整 |

## 真实 Figma 验证仍需什么

在具体项目已授权范围内分别运行 Init、交互、视觉和知识回写，阶段间由用户新建任务并仅提供交接链接。验证 Library 发现/复用、流程与关键草图确认、主流程逐页制作和串联验收、分支逐页/状态逐种补齐、视觉候选逐项制作与选择、整合及完整展开逐项放行、必要资产导入和批准增量回写。每次展示后观察 Agent 是否停止，有效放行后是否只做所述单项；中途恢复、失效交接和上游问题另查边界。使用各阶段的 [Init 检查](../skills/design-harness-init/references/evaluation.md)、[交互检查](../skills/design-harness-interaction/references/evaluation.md)、[视觉检查](../skills/design-harness-visual/references/evaluation.md) 和 [回写检查](../skills/design-harness-writeback/references/evaluation.md)。不为覆盖测试虚构分支、插画或设计变化。

这些试运行需要用户提供对应项目范围；另用一个小修改和一个多页面需求观察候选比较及逐项放行。门禁是 Skill 指令与可见记录，不是 Figma API 拦截器。自动测试未验证模型会等待逐项确认、产出有效视觉差异或正确承接偏好，也未执行四个真实任务或模拟上下文压缩，不能称为已证明不会漂移。

当前读取助手的模拟 API 测试不执行 reactions 写入、原型预览、图像生成/导入或团队库真实访问。上述能力需要逐项报告真实工具与体验证据；流程文档、蓝图字段、连接回读、截图与用户确认之间不能互相替代。

需要核查实现时，在任务中分别报告实际查到的源码与执行过的运行检查，不把入口链接或静态阅读当作版本复现、运行通过的证明。Figma 只保留影响设计判断的状态与必要限制。文档检查需真实整体/局部截图、正文回读和链接核对；模拟 API 不证明富文本渲染、可读性或真实仓库可达。

仅安装或重构本通用插件不包含修改某个项目 Figma 的授权。打包验证也不能代替团队真实试用；门禁限定于已约定产物单位，不给 API 调用或当前项制作修复另设审批。发现具体失败再修相应规则或助手。

连接器适配还需区分三层证据：工具及参数已经发现、目标文件的只读调用成功、经授权的写入与截图验证成功。连接探测失败不影响本地资源校验，但不能据此宣称已验证 Console 的实际读写兼容性。
