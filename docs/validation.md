# 验证范围

## 自动检查

    npm ci
    npm run check

Node.js 22+、ESM、内置 node:test。依赖由锁文件管理，首次安装后自动检查不访问业务服务。
结构校验检查四个显式入口、自包含引用、全部模板副本、版本、品牌、marketplace 和许可完整性。
分发测试覆盖独立 Skill 初始化、全新路径解压、中文/空格路径、可重复 ZIP、SHA-256、拒绝覆盖与私有数据排除。
工作区测试验证协议引用、候选参数范围、需求基础快照、显式升级、源文件导入边界、HTML/资源内嵌、并发/重复导出拒绝覆盖、实际字节清单，以及本地写回冲突。

## 真实浏览器

    npm run test:browser

需要本机 Chrome；测试使用 Playwright 驱动独立浏览器、临时设计工作区和本地服务，不访问 Figma、业务代码或服务。
检查新建表单必填、实际输入、运行反馈、结果与材料、失败恢复、场景重置、说明定位、两候选、即时调参及源文件保存。
检查预览默认满幅、辅助面板默认收起，悬浮入口可展开或收起抽屉。检查三种预览尺寸在开关面板时实际分辨率、缩放和位置不变，操作状态保留，关闭保留未保存参数和反馈，Esc 与焦点恢复正常。
检查实际 iframe 的桌面、窄窗口与手机宽度，工作台窄屏无横向溢出，手机底部浮层处于视口内。
导出后从 file:// 在离线浏览器环境打开，检查交互、材料与资源，并确认未依赖 HTTP/CDN。
截图与结果写到 dist/evidence，属于检查证据，不进入分发包。

## 边界

协议或类型通过不能证明元素真实存在、候选审美质量、读屏体验、用户验收或生产后端能力。
DOM 定位由预览实际报告；有说明目标未出现时需在相应状态核对。数据、权限、Agent、外部文件和设备行为按真实产品另行验证。
测试使用合成数据，不创建真实项目任务，不模拟用户批准，也不以提示词匹配证明 Agent 会正确共创或恢复。
固定快照不自动登记已验收；版本字节检查证明交付一致，不能证明设计正确。

## 维护时选择检查

- 修改协议/运行器：工作区测试、模板类型检查、相关浏览器路径。
- 修改评审工作台/产品预览：浏览器交互和必要尺寸截图。
- 修改 Skill 指令：引用与自包含检查、实际工作流审阅；不把文案测试当作行为验证。
- 修改分发：完整自动检查、新路径打包/解压与单 Skill 初始化。
- 修改品牌：沿用[品牌说明](../assets/README.md)，单独检查浅深背景与小尺寸；普通 HTML 重构不改品牌图形。

真实项目试点应通过分发的能力创建自己的工作区，记录反馈再修通用能力，不把项目专用实现写回通用模板。
