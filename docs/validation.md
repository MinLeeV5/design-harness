# 验证范围

## 自动检查

    npm ci
    npm run check

Node.js 22+、ESM、内置 node:test。依赖由锁文件管理，首次安装后自动检查不访问业务服务。

架构校验随 validate 和打包执行：使用锁定的 @babel/parser 开发依赖分析 JS、TS 与 TSX 导入，检查 frontend、preview、backend/http、backend/services、backend/adapters、contracts 与 CLI 的相对导入边界、移动后缺失引用、前端请求集中和共享协议的运行时独立性。校验器回归覆盖允许依赖、反向依赖、混合及跨行导入、动态导入、重导出与缺失模块，并排除注释和字符串；它不替代类型、构建和行为验证。
结构校验检查四个显式入口、阶段与共享引用边界、唯一固定工具和公共业务模板、版本、品牌、marketplace 和许可完整性；退役回写入口即使只残留引用文件也拒绝分发。
分发测试覆盖完整插件初始化、四入口直连同一 CLI、三个设计阶段的工作区运行，以及单独 Skill 缺共享资源时的明确错误、全新路径解压、中文/空格路径、可重复 ZIP、SHA-256、拒绝覆盖与私有数据排除；产品讨论无需初始化工作区。
工作区测试验证协议引用、Spec 结构、Catalog／Registry 编译、实例属性范围、单一共享基础、当前插件按需导出、源文件导入边界、HTML/资源内嵌、无项目落盘下载、当前源更新、CLI 输出边界与原子替换，以及本地写回冲突；扩展依赖维护检查可能访问 npm 注册表，不访问业务服务。

## CLI 安装分发

    npm run test:install

npm 包名为 @minleev5/design-harness，命令和可选插件名为 design-harness；锁文件的根包名与 package.json 一致。项目本地版本发现按工具包自身名称解析，tests/cli.test.js 验证项目中另有无关的 design-harness 包时不会误转交。

实际 npm pack 后在中文／空格临时路径安装 tarball，覆盖宿主项目 devDependency、隔离 prefix 全局安装和本机可用的 pnpm 安装。此检查需要 npm 注册表或缓存中的依赖，以及本机 Chrome；不修改其他项目或用户已安装的全局工具。npm 包不包含本包 devDependencies 和源码 package-lock.json，验证运行、类型、浏览器与资源 revision 均不依赖这些开发文件。检查项目脚本能够发现命令、全局／插件入口优先使用项目本地版本，以及实际安装后的初始化、构建、类型检查、离线导出和包内专业指导路径。

移除服务进程 PATH 中的 Codex 后，仍验证工作台可启动并加载；doctor 报告缺少 Codex 的单元回归与工作区运行分别检查。安装包 Agent 验证从包内实际加载身份和公共方法，通过确定性执行夹具生成提案，并运行真实类型／构建／Chrome 校验，接受前源文件保持不变，接受后写回。此结果证明分发和提案链路，不代表真实 Codex 推理。tests/cli.test.js 另覆盖空工作目录的帮助与版本、四阶段定位、错误命令、中文参数与非零退出状态透传、软链接安装避免循环及缺少 Codex 的只读诊断。

需要真实验证安装包连接本机 Codex 时，显式运行 npm run test:install -- --live。在 npm 开发依赖安装后的临时项目中，以只读身份发送一次无工具、无文件修改的连接请求，并核对真实模型回复；该选项不进入默认自动检查。

安装回归同时覆盖 pnpm hoist=false，确保引擎依赖和传递依赖的许可不依赖提升。npm 布局下尝试导入宿主 node_modules 中的无关模块，必须被构建边界拒绝；未安装自身运行依赖的可选插件入口仍能转交项目本地 CLI。

通用模板浏览器检查证明运行能力，项目完整 UI 另按[交付保真](../shared/references/fidelity.md)核对指定版本和环境。
按可比视口、上下文、内容与状态下的基线及设计画面，逐区核对壳层、菜单、组件细节、分割、固定／滚动区域与响应式；实际操作入口、弹层、键盘和恢复路径。
视觉保真、交互覆盖、行为真实性及工程检查分别记录。源代码、本地 Mock、设计模拟和现网各有证据边界；预置场景不代替真实触发，未核实不计为通过。
检查数量不构成完成门槛，未取得现网证据不使用“已与生产一致”的结论；修正当前需求后重新导出，不将导出当作用户验收。

## Init 的工作流验证

Init 按[本阶段验证](../skills/design-harness-init/references/evaluation.md)核对覆盖清单、实际基础预览和声明范围。检查代表布局的行高、条目与分组间距、标题、内边距、分割线、固定／滚动区域及组件状态；已有产品先校准样式转换与运行基线，再扩展。用户验收与初始化实现完成分别记录。

维护指引时审阅以下场景；实际试跑还需检查 Agent 的操作与产物，文案匹配和分发测试不证明工作流行为通过：

| 场景 | 应观察到的结果 |
| --- | --- |
| 已有产品首次建立设计工作区 | 先界定覆盖，取得可用运行基线，核对代表布局后提取；公共组件及实际页面模式有可定位预览，按范围完成布局与交互验证 |
| 有源码但无法取得运行基线 | 保留已尝试方式、原因和未核实项，完成可做的提取，交付阶段性结果，不将工程检查算作视觉通过 |
| 尚无界面的新项目 | 按已确认意图和约束建立设计草稿与基础预览；没有历史画面不作为失败，也不虚构既有规范 |
| 已有设计工作区或只初始化了目录 | 承接现有公共基础，更新后复验受影响需求；0 个需求的 check 仅证明入口有效，仍需建立实际基础预览 |

修改 Init 指令和说明模板运行 npm run validate 与 node --test tests/distribution.test.js，核对引用、完整插件分发、模板复制及异地运行。工具仍只负责资源初始化，不自动提取产品或生成基础预览；实际 Agent 改善需另行试跑确认。

组织模式由 tests/design-organization.test.js 覆盖：实际 CLI 保存与读取选择、无模式及旧配置保持可读、持续主稿默认入口、普通新建拒绝隐式拆分、显式独立例外及基础预览、预览不能作为主稿、切换配置不迁移资源、同一输出 HTML 的持续更新、工作台两种身份每轮获取实际配置，以及提案不能改写项目模式。共享指导加载使用模型夹具核对真实上下文，不据此声称 Agent 已正确协助用户决策；后者需实际 Skill 试跑。工作区与 Agent 邻近测试、完整检查、类型、分发及相关浏览器路径一并验证。

## 边界

协议或类型通过不能证明元素真实存在、候选审美质量、读屏体验、用户验收或生产后端能力。
DOM 定位由预览实际报告；有说明目标未出现时需在相应状态核对。数据、权限、Agent、外部文件和设备行为按真实产品另行验证。
测试使用合成数据，不创建真实项目任务，不模拟用户批准，也不以提示词匹配证明 Agent 会正确共创或恢复。
离线导出不自动登记已验收；文件可打开不能证明设计正确。


统一下拉使用真实 Chrome 点击和键盘验收，不通过隐藏原生 select 代替操作。覆盖预览、身份与模型设置中的选择入口、需求跳转、搜索与无结果、禁用原因、方向键仅高亮、Enter 确认、Esc 嵌套关闭与焦点恢复、外部点击／Tab、长列表滚动、320/360 窗口、触屏和离线 HTML。原有页面联动、保护与偏好检查使用同一公共浏览器选择助手，继续验证实际业务结果。

输入工具栏验收检查图标可访问名称、模型单一入口、四Tab切换不提交设置、即时保存且面板与Tab保持、模型图片能力图标和详细提示、完全访问标记、权限 Tab 风险说明及输入区无重复提示、控件位于正文下方、附件移除、身份迁入模型设置且与模型选择独立、两种身份图标区分及入口随身份切换同步、模型名与身份图标组合展示且窄屏图标保持可见、生成期间锁定及停止、模型切换与历史恢复、图片能力限制、认证缺失保留草稿，以及320/360宽度无溢出。连接测试覆盖元数据脱敏、只读RPC分页与UTF-8、缓存和刷新、超时退出、令牌保护，以及认证／推理成功／失败／取消分离；真实本机调用验证所选模型与接受写回。

本机偏好另验证首次交互默认、未发送即保存、跨进程与端口恢复、新旧会话继承边界、按模型恢复深度、失效回退、保存失败重试、原子替换与权限、并发局部合并、损坏／软链接保护，以及请求与历史的实际深度。测试注入临时或内存偏好存储，不污染真实用户偏好；真实调用在临时存储中验证显式深度与接受写回。

交互说明内容按[统一规范](../shared/references/interactions.md#内容规范)审阅，避免只验证 YAML 和目标存在：

| 场景 | 应观察到的结果 |
| --- | --- |
| 新增异步提交或失败重试 | 必要时主动补点，按需选择条件、状态或异常等维度，用短句说明关键反馈、重复提交限制、结果与恢复，无重复摘要或空章节 |
| 修改跨页流程或离开保护 | 同步更新已有说明，写清去向、上下文和输入保留或丢弃规则，正文、条件和真实目标一致 |
| 增加权限、校验或禁用分支 | 写明条件、原因与可继续的动作，必要解释不会因状态筛选而全部不可见 |
| 已有准确说明或仅调整视觉 | 复用已有条目；无需增加的打点不机械新增，不以数量计完成 |
| 同一打点含多种规则或只需一句说明 | 按需组合维度，简单情况允许仅一个维度；每句话提供新信息，复杂分支才使用短列表或表格，不为写满模板而增加内容 |
| 业务规则未确认或仅本地模拟 | 明确依据与待确认、模拟边界，不编造具体值或将未实现行为写成已实现 |

真实项目试点应通过分发的能力创建自己的工作区，记录反馈再修通用能力，不把项目专用实现写回通用模板。

Live Agent 自动测试使用结构化结果夹具验证预览、候选边界、取消、放弃、接受和外部编辑冲突；夹具不证明真实模型可用。改动运行适配器时，另使用已登录本机 Codex 在临时合成项目中生成并接受一次实际修改，仅报告结果，不保存模型输出。

统一Agent验收：初始和仅点选均无预铺控件；点选一次自动结束、不触发原动作且附加元素返回Agent；纯回答无文件修改；会话按候选隔离且保留完整消息和每轮活动；生成后调整实际改变Spec/CSS预览，继续对话基于已调节的临时源，接受后检查真实文件。验证请求、生成与校验活动、loading/耗时、取消、放弃、失败重试、外部编辑冲突及移动端。JSONL夹具覆盖UTF-8分块、过大/非法行、原始内部推理及最终源码结果过滤、公开摘要与命令输出展示。真实API和Chrome配合确定性模型结果只证明机制；另使用本机Codex实际完成一次生成、调节和接受后再报告模型链路通过。

多会话专项覆盖原生 thread/turn 的事件交错、提前通知、UTF-8、单轮取消及连接退出；同候选并发、单会话互斥、消息／设置／最近请求隔离、跨会话操作拒绝、源版本冲突与保留预览。sessions-smoke 使用真实 Chrome 与本地 API 验证切换、后台完成不抢画布、刷新恢复任务、接受后局部刷新、草稿隔离及窄屏。真实 Codex 验证临时 thread 并发、多轮上下文隔离和仅接受后写源；确定性夹具不替代真实模型验证。

权限专项覆盖三档原生策略及完全访问降回受限策略、审批按 thread/turn 分发、原生请求撤销和取消后的迟到答复、权限扩展仅限当前轮次、跨会话拒绝与重复审批失效。实际副本文件变化纳入范围检查，拒绝隐式 foundation／依赖修改、删除、软链接和非设计资源。完全访问对合成源文件的直接修改在取消后保留并记录源版本变化。permissions-smoke 使用真实 HTTP 与 Chrome 验证三档选择、完全访问风险提示、每轮权限记忆、会话隔离、刷新待审批恢复、批准／拒绝／取消、公开摘要与折叠命令输出、工具修改副本的接受写回及320/360px无溢出。权限不写全局偏好，新会话回到默认提案工作区。真实本机 Codex 在临时合成目录验证只读命令、提案副本写入和完全访问的目录外写入；这些不访问实际业务资源。

后台命令回归验证结束前清理原生终端、清理期间拒绝迟到审批、旧执行目录的延迟写入不能改变冻结预览或最终接受内容。MCP确认覆盖无turnId的thread归属、基本表单的必填与类型校验，以及未支持请求的明确响应。副本扫描先检查体积上限，再以64KB分块哈希，避免新工具文件被无界读入内存。

## Agent 按需上下文与 Provider 用量

agent-context 回归验证大文件正文不进入提示且副本内容完整、入口存在、状态与点选详情按需读取、正式来源与当前副本分离、每轮路径刷新、中文空格路径与 Git worktree 宿主解析。角色回归验证内部身份不再注入外部 Skill，公共方法引用真实唯一资源，已有暂存修改和控件值仍由当前副本承接。原生协议回归覆盖无 turnId 的 usage、过期 turnId、线程隔离、缺失／非法计数、压缩完成事件与去重。字符数不等同 Token。

context-smoke 在真实 Chrome 与本地 API 中检查四格核心用量、生成中更新、缺失与零值、百万级计数的精确 title、会话切换和刷新恢复。桌面／360／320px 的默认正常面板不超过340px；详情上限440px，标题与会话固定、内容内滚动；长来源、模型名、ID 与目录单行省略，title 和复制保留原值，验证目录复制及折叠状态重置。模拟原生输出仅证明 UI 与路由，真实 Codex 试跑另核对按地图读取、图片工具查看当前截图、相关宿主文件读取、修改与接受，以及实际原生用量返回。保留用户确认与质量验证的独立性。
