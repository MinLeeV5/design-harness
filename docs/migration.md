# 从旧 v0.1 迁移

重构更换了公开 Skill。安装新包并开新任务后使用：

| 旧入口/行为 | 现在的入口/行为 |
| --- | --- |
| design-harness / dh-context 的初始盘点 | design-harness-init |
| dh-brief / dh-design 的新需求设计 | design-harness-design |
| dh-review | 评价嵌入 Init/Design；可在同一设计任务中请求重点检查 |
| dh-handoff | 选定稿与交互、状态、源码来源随需求 Page 交付；知识增量确认后沉淀 |
| 本地项目配置、运行目录、brief、JSON 门禁 | Figma 项目入口 + 按需读取；对话中确认需求 |

旧的本地记录不会被自动删除或迁移。必要时将其作为历史事实来源，核实后按对应 Init 模块整理到 Figma。不要让旧文件覆盖新的用户决定。

## 已有 Harness Page

可以继续使用已有页面，包括旧名为“开始使用”的入口与原项目风格分组。先读取 Page 顶层目录、入口及本次需要的小节点。

用户要求迁移或新契约确有需要时，先提出入口/模块的具体迁移内容，再按 Init 门禁更新。保留有效资产、来源链接和稳定标识；不要求重做已完成部分。旧参考 Frame 或原稿副本要如实标明类型，需要建设组件库时另补原生 Component/ComponentSet。

原来的知识维护暂缓条款，按本次用户决策更新为“选定方案后，具体增量确认再回写”。这不启动自动学习或跨项目规则推广。

## 仓库与代码映射

项目入口定位代码仓库；资源说明关联文件、符号、资源名、版本和必要的渠道范围。插件不自动向消费项目写 AGENTS、Skill 或改源码。用户另行要求研发集成时，在研发仓库约束下完成；Figma 原生 Code Connect 可在有对应需求和能力时使用，并非本插件启动前提。
