# Skill 维护指南

## 设计流程与知识

四个入口显式启动；产品共创独立处理业务 PRD，交互和视觉共同编辑同一 json-render Spec 与 React 组件产物。维护流程时读取实际影响阶段的 references/workflow.md、evaluation.md。
不恢复固定逐页逐状态审批，不强制小修改探索多套候选。范围内直接落实明确改动；关键业务行为或交付边界变化才重新对齐。
交互与视觉在当前任务中完成过程维护、获准的公共基础更新、验证与交接，按请求导出并验证离线 HTML；共同规则只维护在[设计维护与交接](../shared/references/handoff.md)，不另设回写入口。各阶段仍保留自身的交互或视觉评价。
验证输出临时清理，不在项目和分发中维护 evidence；必要结论和未决项记入 handoff.md。真实决定、反馈与实际变化记入需求 handoff.md，工具成功和导出版本不等于验收。

使用方设计知识与本地设计产物保存在仓库 design-harness/；用户指定正式业务 PRD 时按[来源与承接](../shared/references/product-source.md)处理。HTML 按需下载或导出到资源目录之外，历史用 Git 记录。项目规范和真实代码用于建立当前事实；已确认未来设计单独表达。
协议、稳定定位和恢复方式见 [协议](../shared/references/protocol.md)、[交接](../shared/references/handoff.md)。
模板默认值保持草稿身份，通用分发包不包含真实项目标识、路径或任务记录。

维护完整 UI 标准时遵循[交付保真](../shared/references/fidelity.md)：先明确范围与实际基线，检查产品壳层及沿用组件，分别提供视觉、交互、行为与工程证据。各阶段评价按职责维护，不使用同一份笼统评价代替阶段证据。
该指导由三个设计入口共同引用；模板只演示局部流程，不隐含真实品牌、完整产品壳层或现网一致结论。新增规则保持来源通用，不写入试点的真实标识或路径。

## Skill 结构与运行

每个 Skill 保留入口、agents 与阶段工作流、评价、来源路由。公共指导、模板和来源声明只在 shared/ 保存一份，原创许可使用插件根 LICENSE；各入口链接同一个 workbench/cli.mjs，产品讨论无需运行它。Markdown 可引用本阶段、插件 shared/ 及明确公开的 CLI／许可文件，不依赖兄弟 Skill 或任意插件内部文件。
公共基础仅在项目根目录保留一份，所有需求与导出共享，兼容更新需验证已有需求。requirements 为本地设计产物的唯一维护来源；正式业务 PRD 的位置由用户决定。不创建 releases 或业务源码副本；重新生成统一使用 export。
完整插件统一携带公共工作台、业务资源模板及资源／协议／预览／交接指导；单独复制 Skill 不作为安装方式。
workbench/ 是唯一工具开发源，shared/workspace/ 是唯一公共业务模板，shared/references/ 维护公共指导，shared/third-party/ 保留适用来源声明。维护原文件后直接验证，无复制或同步步骤；分发检查拒绝旧副本、缺失共享文件和软链接。

工作台内部按 [源码架构与依赖](html-design.md#源码架构与依赖) 维护。跨功能选择器集中在 frontend/ui，字段和工具栏共享交互与选项协议；新增功能归入 frontend/features，跨端数据与纯规则归入 contracts，本地能力归入 backend/adapters，完整操作由 backend/services 编排；HTTP 和 CLI 复用服务。新增或移动模块时同步 scripts/validate.js 的分发资源清单，并通过架构边界校验，不在旧目录保留运行源码副本。
各阶段独立维护工作流和评价；Init/视觉在需要资产时读取公共资产方法，其余阶段不引入生图流程。

固定工具使用 Node.js 22+、json-render、React、TypeScript 与 esbuild，工具依赖和锁文件位于插件。项目只维护 Spec、Catalog／Registry、业务组件和可选扩展依赖声明；扩展缓存位于项目之外。
交互正文与关联配置由各需求 interactions/*.md 统一维护，场景仅保存初始数据；[交互协议](../shared/references/interactions.md)约定文档、展示模式与导航 SDK。对比共享页面/场景/视口/标注上下文，编辑焦点不影响两侧会话；离开保护先分别确认再统一切页，输入及业务/Agent 修改保持方案独立。
图标输入工具栏复用本机 Codex 配置与登录；身份首次默认交互，用户级偏好在项目与插件外保存；新会话继承最近选择，已有会话独立。身份、模型与按模型记住的思考深度互相独立，切换只影响下一轮，认证和推理结果分别展示，不管理新的 Provider 或密钥。专业身份从本阶段 Skill、工作流、评价及 shared 公共协议读取方法；身份元数据独立于模型输出，切换身份保留同一候选已确认上下文。交互提案可包含需求级说明、场景和页面登记，需展示共享影响、验证全部候选并统一接受；公共基础与已有其他候选实现继续隔离。
工作台内设计 Agent 预加载业务 PRD 与设计承接指导；它不能访问网络或自行读取飞书，来源核对由具备访问能力的外部 Agent 或用户完成，未核对不得称为最新。
预览工具维护本地 HTTP 服务、隔离 iframe、页面状态双向同步、四种说明组件、编号说明、单次精确点选、统一Agent讨论与视觉预览、动态控件、完整当前会话和公开活动记录，不注册 MCP、hooks 或遥测。
[技术结构](html-design.md) 解释协议、编译边界和按需导出；[验证范围](validation.md) 说明检查证据。

## 外部来源与许可

优先项目已确认规范。按当前问题读取官方现行页面或默认分支最小部分，不复制完整上游手册或实际素材。
保留已有许可证和来源声明；维护适配时核对上游当前许可，失败时如实说明，不称已验证最新。
参考方法、设计素材和代码依赖分别核对许可。
生图按当前环境的 imagegen 工具/Skill 使用，检查实际导入与版面；不能只记录提示词就称素材交付。
Live 复用 workbench/vendor/impeccable 的 DOM 辅助模块，保留固定提交、Apache-2.0 LICENSE 和 NOTICE；插件实现适合 json-render 资源的 Agent 生命周期适配，不宣称整体内嵌上游 Live 服务。更新时核对上游来源与授权，并同步离线 HTML 内的许可。

## 版本与分发

插件清单、package.json、锁文件版本同步。使用 SemVer，本地正式源版本不带缓存后缀；远端发布与推送需明确授权。
日常迭代不自动递增版本；有明确版本或发布需求时再同步调整。
市场稳定名为 design-harness，根 source.path 为 ./，ZIP 中转换为 ./plugins/design-harness。
npm ci 安装依赖，npm run check 验证，npm run package -- --out <新目录> 打包；拒绝覆盖并输出 SHA-256。
保留品牌和许可证；.harness、openspec、node_modules、dist、私有设计工作区不进入包。
验证入口指导完整性、脱离完整插件时的明确错误、完整插件在全新路径安装解压及离线交付；构建成功、真实浏览器运行、设计验收与用户批准分别报告。
