# 实施任务

本清单只投影 `brainstorm.md` 中 D-01 至 D-08、现有仓库约束及可验证的机械拆分。目录和接口示例仍为提案，本清单不把具体文件名、接口字段或尚未确认的功能变成已确认契约；实施中若出现影响结构、可观察行为或维护方式的关键选择，返回共同设计处理。

当前 change 的可写边界为本仓库。真实项目的运行画面和试点记录可作为依据，不在本任务清单中授权修改其他项目、发布插件或推送代码。下列 checkbox 按实际实施和验证结果更新。

## 交付结果

- [x] **1. 工作台作为插件固定工具运行，项目初始化只生成业务设计资源**
  - **来源：** [D-01](brainstorm.md#d-01)、[D-05](brainstorm.md#d-05)；[当前初始化助手](../../../../skills/design-harness-init/scripts/harness.mjs)及[运行结构](../../../../docs/html-design.md)。
  - **结果：** 工作台及运行引擎由插件维护和启动，不再把可编辑工作台源码复制到项目 `design-harness/`。项目组件、页面、场景、素材、说明和证据保存在项目侧。当前统一到新模式，不新增旧工作区兼容层或多版本引擎管理。
  - **范围：** 插件工具与初始化助手、资源模板、根依赖和命令、对应工作区／分发测试及运行说明；保留本仓库既有未提交改动。
  - **验证：** 在全新临时项目初始化并从独立插件位置启动；检查生成内容不含可编辑工作台源码；修改项目业务资源后插件工作台源码保持不变，工具可继续加载该项目。运行相关工作区和分发检查。

- [x] **2. 固定引擎通过资源协议加载项目 Catalog、Registry 与完整页面 Spec**
  - **来源：** [D-01](brainstorm.md#d-01)、[D-02](brainstorm.md#d-02)、[D-05](brainstorm.md#d-05)、[D-07](brainstorm.md#d-07)；[当前协议](../../../../skills/design-harness-init/references/protocol.md)与[构建器](../../../../workbench/lib/build.mjs)。
  - **结果：** 项目以资源协议向工作台提供业务设计内容；json-render 使用项目 Catalog／Registry 渲染自定义 React 组件和页面 Spec。页面组合与组件实现保持各自的维护来源；运行器不写入项目专用业务实现，为以后更换资源加载来源保留边界。
  - **范围：** 固定引擎的资源加载、构建与校验，项目组件／页面资源模板及协议说明，所需依赖和相邻验证。
  - **验证：** 使用通用组件包与独立页面 Spec，在不同临时项目资源目录完成加载、渲染和类型检查；验证组件注册与属性约束实际生效，资源错误可定位。检查运行代码与通用分发内容没有真实项目标识或业务源码依赖。

- [x] **3. 需求固定组件基础，候选完整资源和专属实现彼此隔离**
  - **来源：** [D-06](brainstorm.md#d-06)；[当前需求创建及基础快照](../../../../workbench/lib/workspace.mjs)和[工作区测试](../../../../tests/workspace.test.js)。
  - **结果：** 同一需求的候选共享固定组件基础；每套候选持有独立完整页面 Spec、参数和专属实现，不依赖基础 Spec 加差异补丁生成自身内容。修改一个候选不会隐式改变另一个候选或公共基础。
  - **范围：** 需求与候选资源管理、固定基础、候选构建选择、通用候选示例及工作区／浏览器验证。
  - **验证：** 建立两套候选，分别修改页面组合、参数和专属组件后比较并重新加载，确认另一套内容和交互状态不串扰；改变公共基础后，已有需求的固定基础不变。分别构建两套完整候选资源。

- [x] **4. 产品预览与工作台隔离，实例属性修改保存到正确候选的 Spec**
  - **来源：** [D-01](brainstorm.md#d-01)、[D-03](brainstorm.md#d-03)、[D-04](brainstorm.md#d-04)；[当前预览容器](../../../../workbench/app.tsx)、[本地写回保护](../../../../workbench/lib/server.mjs)及[浏览器验收](../../../../scripts/browser-smoke.js)。
  - **结果：** 项目代码在隔离预览中运行，通过协议与工作台交换预览、定位和编辑信息，不修改工作台自身。Live 对页面实例属性的修改保存到对应候选 Spec；组件内部变化仍由 Agent 修改项目组件或 Token。保留现有外部编辑冲突保护、未保存修改保护和辅助面板不改变预览尺寸的行为。
  - **范围：** 工作台与预览通信、定位桥接、实例属性编辑和持久化、隔离及路径边界检查，相关说明与回归验证。
  - **验证：** 实际点选并修改一个实例属性，保存、重新加载后核对相应 Spec 和画面；确认未改变另一候选、组件内部源码或工作台。制造外部编辑和延迟保存／重载，验证冲突或在途响应不覆盖未保存修改。核对桌面、窄窗口、手机在面板开关前后的实际视口、缩放、位置和操作状态；验证编译后的预览仍能定位目标。

- [x] **5. 固定工具可以导出可独立运行、可核验且拒绝覆盖的离线交付**
  - **来源：** [D-01](brainstorm.md#d-01)、[D-05](brainstorm.md#d-05)、[D-06](brainstorm.md#d-06)；[现有固定交付及字节核验](../../../../workbench/lib/workspace.mjs)、[HTML 内嵌构建](../../../../workbench/lib/build.mjs)和[验证边界](../../../../docs/validation.md)。
  - **结果：** 工具与业务资源分离后仍可生成自包含 HTML，交付包含实际业务资源、固定基础和运行时对应信息；不依赖本机插件缓存。沿用构建与快照同源、实际字节清单和已有交付拒绝覆盖的约束，不把交付生成或核验成功登记为用户验收。
  - **范围：** 构建与快照收集、离线导出及核验、对应许可与依赖信息、相邻工作区测试和离线浏览器检查。
  - **验证：** 导出后在离线浏览器以 `file://` 打开实际 HTML，操作组件、切换候选并检查交互和资源不依赖 HTTP／CDN 或插件安装目录；核验实际文件，确认篡改、缺失、未登记文件和重复版本均被拒绝；已有交付字节保持不变。

- [x] **6. 四个入口、分发校验与完整 UI 交付标准统一到新运行方式**
  - **来源：** [D-01](brainstorm.md#d-01)、[D-02](brainstorm.md#d-02)、[D-07](brainstorm.md#d-07)、[D-08](brainstorm.md#d-08)；[仓库约束](../../../../AGENTS.md)、[Skill 维护指南](../../../../docs/skill-maintenance.md)、[分发检查](../../../../tests/distribution.test.js)及[交付保真](../../../../skills/design-harness-init/references/fidelity.md)。
  - **结果：** 四个 Skill 围绕同一插件工具读写项目资源，工作流、引用、蓝图、同步／分发检查及维护文档不再要求向项目复制整套工作台。同步调整当前自包含运行模板约定与新边界的冲突，保持各入口说明完整。完整 UI 的壳层、组件、状态、真实基线与 Mock／现网证据边界继续明确，不以通用示例或工程检查代替真实项目保真验收。
  - **范围：** 四个公开入口及其资源、同步与打包校验、分发测试、README、AGENTS.md 和相关维护／验证说明；项目业务资产不进入通用分发包。
  - **验证：** 运行 `npm run check` 与 `npm run test:browser`；在新目录打包、解压并从分发插件创建和加载临时业务资源。逐项核对四入口的工具调用、注册与 Spec 约定及质量要求；保留现有运行器相关类型检查和必要浏览器证据。通用能力结果与智工作等真实项目的后续完整 UI 复核分别报告，不冒称已修复或验收真实项目稿件。
